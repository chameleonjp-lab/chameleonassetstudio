# R02: 保存・取り消し・復旧の統合

対象は完成計画のR02。開始mainは `1122595`（R01、PR #282）。
R03〜R06と正式公開・iPhone実機確認は未完了。

## 実装

- 保存予約を対象別に保持する。名前変更と複数素材の編集を相互に置き換えず、保存中に届いた変更も処理する。名前は保存時の最新Projectへ適用し、古い素材一覧で上書きしない。
- 名前変更、新規・複製・反転コピー・通常削除、Familyの作成・割当・独立化・削除を履歴へ統合する。素材一覧、選択、画像と復旧点を同じtransactionで戻す。他タブで正本が変わった場合は履歴適用を拒否する。
- 保存失敗時の履歴補償は端末内データへも適用する。無関係な保存を失敗と一緒に捨てず、失敗対象だけを安全な補償内容で再試行する。Undo / Redoの保存失敗でも履歴位置と正本を維持する。
- 既存の `exportPresets` を検査後に捨てず、Project所有の設定として原子的に取り込む。再読込API、バックアップへの同梱、ごみ箱復元と完全削除に接続した。実際の配布設定画面はR05の対象。
- 復旧点は全編集画像を保持し、復旧とUndoで画像・Asset・Project概要を一緒に変更する。画像の競合または途中失敗では一部の画像だけ戻さない。構造履歴は新しい復旧点を保持し、枝刈り済み復旧点を復活させない。
- 保存状態は未保存・保存中・保存済み・失敗を表示する。名前はEnterまたはフォーカス移動で確定する。書き出しは保留保存を完了させ、バックアップは同一読み取りtransactionから全データを取得する。

履歴は開いている編集セッションの既存100件上限を共有する。画像を保持する履歴のメモリ量はR06の容量・性能確認に含める。

## 互換性

`asset.json`、`.casproj`、ZIP内容契約、JSON Schemaとversionは変更していない。
IndexedDBのversionも変更せず、既存Blob storeの別名前空間に設定を保持する。
端末内復旧点だけに任意の追加画像フィールドを加え、従来の単一画像復旧点も読み込む。
設定を含まない旧バックアップは従来どおり取り込める。

## 検証する境界

- 名前と2素材を両順序で連続保存、保存中の追加予約、別対象の失敗と再試行。
- 初回編集・Undo・Redoの保存失敗と補償、保存済み正本と履歴位置の一致。
- 作成→画像編集→編集Undo→作成Undo→Redo、削除復元の全画像と復旧点、他タブ競合。
- 設定を含むバックアップの再取込と再読込、旧バックアップ、設定不正時の全体rollback、ごみ箱・完全削除。
- 複数画像の復旧成功と2枚目の競合時の全体拒否。
- 実画面の名前・複製・削除・白紙作成のUndo / Redoと再開後の画像bytes（Chromium / WebKit）。

独立したread-onlyレビューで保存・履歴の重大な残り問題がないことを確認し、関連5ファイル43テストが成功した。
統合検査の最終結果はPRに記録する。

## 既存E2Eの修正理由

名前入力の確定、保存状態の完全一致検索、コピー作成後の履歴を新しい操作仕様へ合わせた。
失敗した一括保存は追加履歴を作らず、その前にある白紙作成履歴を残すことを検査する。
キャンバス操作は現在の表示変換から座標を求め、対象をスクロールして実際に操作する。
前後コマの画素不一致は開始mainでも再現した。表示変換利用後は同じ厳密な画素条件で成功した。
トリミングは上端のズームバーを避け右下1/4を囲み、同じ画像サイズ・画素・Undo条件を検査する。
ズームバーと小さいキャンバスの重なりはR03の画面整理へ引き継ぐ。
プロパティのガイドは通常配置にして、スクロールした入力やボタンへの操作を妨げないようにした。

Game CheckのZIP比較は日時による偽陽性を修正した。central/local headerの日時4bytesだけを正規化する。
圧縮bytes・順序・その他のメタデータのhashと全entryのhashを比較し、生ZIP hashも証跡として保持する。
本体のZIP生成は変更していない。

この管理環境ではブラウザからCDNへ直接接続できず、明示proxy使用でも `ERR_CERT_AUTHORITY_INVALID` となった。
TLS検証を行うcurlで既存の固定版CDNファイルを取得し、任意の `PLAYWRIGHT_ENGINE_CACHE_DIR` でSHA-256検査後に同じbytesを渡す。
エンジンを偽装せず、既存の描画画素・animation・version条件を維持する。通常CIは従来どおりCDNを使う。
WebKitの不足共有libraryはworkspace内に展開し、実ブラウザを実行する。実機Safariの代替ではない。
