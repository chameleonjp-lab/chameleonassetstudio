## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **T-DONE-4**: 原点・足元・向き・スケールを整え、**3D アンカー**と 3D 当たり判定を付けられる。
- **T-DONE-7**: metadata と inspection report を付けられる。

逆算の理由: 2D の `F-2D-09`（原点 / アンカー）に対応する **3D 版**。**モデルを「見た目」から「ゲームで動かせる素材」へ変える情報**であり、`F-3D-05` が決めた基準の上に載る。

3D で特に効くのは、上流が挙げた用途——**武器、手、足元、弾発射位置、カメラ注視点**（系譜: 上流 §4.1）。これらは**モデルの形からは判らない**。**制作者が意味を与えて初めて存在する情報**である。

## 1. ユーザーストーリー

- 制作者として、**武器を持たせる位置**を決めたい。
- 制作者として、**弾が出る位置**を決めたい。
- 制作者として、**カメラが見る位置**を決めたい。
- 制作者として、**アンカーの名前でエンジン側から参照**したい。
- 制作者として、**勝手にアンカーを作られたくない**。
- 制作者として、**置いた位置が、書き出し先でもずれない**と確信したい。

## 2. 用語

- **アンカー**: モデル上の意味のある位置（と、必要なら向き）。
- **役割（role）**: そのアンカーが何のためのものか（足元・頭・手・武器・発射位置・注視点など）。

## 3. 機能要件（FR）

### 3.1 付与と役割

- **FR-1** アンカーを**追加・移動・削除**できる。
- **FR-2** アンカーは **位置**を持ち、**必要なら向き**も持てる（系譜: 上流 §4.1 の `position` と optional な `rotation`。**向きは必須にしない**——多くの用途では位置だけで足りる）。
- **FR-3** アンカーは **役割**を持てる（足元・頭・左右の手・武器・弾発射位置・カメラ注視点・任意。系譜: 上流 §4.1 の `role`）。
- **FR-4** **役割の一覧を閉じない**。`custom` 相当の逃げ道を残す（系譜: 同上。**制作者の用途を想定で塞がない**）。

### 3.2 名前と参照（継承）

- **FR-5** アンカーは **名前を持ち、名前は一意**である（**外部から参照されるため**。系譜: ADR-0002 / `F-2D-09` と同じ規律）。
- **FR-6** **重複・未設定を検出**する（`F-CORE-06` の意味検証に委ねる）。
- **FR-7** **識別子と表示名を混同しない**（系譜: ADR-0002）。表示名を変えても参照が壊れない。

### 3.3 推測で作らない（継承）

- **FR-8** **アンカーを自動生成しない**（系譜: `F-2D-10` FR / ADR-0018 の「当たり判定を自動生成しない」と同じ思想。**モデルの形から意味は決まらない**）。
- **FR-9** **候補の提示は可**とする（bounds や原点から「ここが足元では」と示す）。ただし **確定は制作者が行う**（`F-2D-15` FR-9 の「修正案を自動確定しない」と同じ）。
- **FR-10** 骨格に基づく対応付けは **`F-3D-08` の担当**とし、本機能では**骨格の有無に依存しない**（骨が無いモデルでもアンカーを置ける）。

### 3.4 基準との関係

- **FR-11** アンカーの座標は **`F-3D-05` が決めた基準**（原点モード・向き・スケール）に従う。**基準を変えたら、アンカーの意味がどう変わるかを示す**。
- **FR-12** **対象エンジンごとの軸・単位変換で、アンカーの保存値を変えない**（`F-3D-05` FR-15 と同じ境界。**変換は書き出し側**）。
- **FR-12a** 保存はモデル自身の空間で行い、**画面に見えている空間の値で保存しない**（`F-3D-05` FR-17。系譜: 上流 `3d/3D_DECISION_LOG_AND_OPEN_ITEMS.md` `3D-RISK-09`）。

### 3.4a モデル内部の要素に結び付ける場合（継承 — 上流リスク台帳）

- **FR-12b** アンカーをモデル内部の要素（節点など）へ結び付ける場合、**結び付けの宣言点を 1 か所に限る**（系譜: 同上 `3D-RISK-02`「node index の基準バイト列のずれ」。**同じ番号が、元モデルと派生モデルで別の要素を指す**事故を防ぐ）。
- **FR-12c** 結び付け先は **どのバイト列を基準にした番号か**が判る形で保持し、**照合できなければ「未解決」と表示**する。**黙って別の要素へ結び付けない**（系譜: 同上。`F-2D-08` の「未解決参照を理由つきで拒否」と同じ思想）。
- **FR-12d** **派生モデル（軽量化後など）で結び付けを張り直す場合、それは専用の検証を要する操作**として扱う（系譜: 同上。`F-3D-10` FR-13/FR-14 と対）。

### 3.5 非破壊と編集の土台

- **FR-13** アンカーは **元モデルを変更しない**追加情報である（`G5` / `F-CORE-03`）。
- **FR-14** 付与・移動・削除は **Core の履歴に乗る**（`F-CORE-04`）。
- **FR-15** 配置は **`F-3D-03` の面の上で、モデルに重ねて**行える（**数値入力だけにしない**）。

## 4. 非機能要件（NFR）

- **NFR-1（意味の明示）**: 何のためのアンカーかが判る（FR-3）。
- **NFR-2（参照の安定）**: 名前が一意で、表示名変更で壊れない（FR-5/FR-7）。
- **NFR-3（推測しない）**: 自動生成しない（FR-8）。
- **NFR-4（非破壊）**: 元モデルが不変（FR-13。`G5`）。
- **NFR-5（可視性）**: 絵に重ねて置ける（FR-15）。
- **NFR-6（境界の明確さ）**: 対象ごとの変換は書き出し側（FR-12）。

## 5. データ・保存への影響

- アンカーは **additive な追加情報**として保存する（`D3` / `D4`。**未対応環境でも正本が成立する**）。
- **元モデルはバイト不変**（FR-13）。
- **書き出し時の変換は保存値を変えない**（FR-12）。
- 名前空間は `F-CORE-05` の境界規則に従う。

## 6. 依存機能

- **F-3D-05**（基準整備）: 座標の土台（FR-11）。
- **F-3D-03**（ビューポート）: 重ね表示と配置操作（FR-15）。
- **F-CORE-06**（検品）: 一意性・妥当性・未設定の検証（FR-6）。
- **F-CORE-03 / 04**: 非破壊・履歴（FR-13/FR-14）。
- **F-3D-08**（骨格検査）: 骨との対応付け（FR-10。別機能）。
- **F-3D-13 / 14 / 15**（metadata / report / 書き出し）: 出力先。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: アンカーを**追加・移動・削除**できる（FR-1）。
- **AC-2**: **位置は必須、向きは任意**として扱える（FR-2）。
- **AC-3**: **役割を付けられ**、一覧が**閉じていない**（FR-3/FR-4/NFR-1）。
- **AC-4**: 名前が**一意**で、**重複・未設定が検出**される（FR-5/FR-6/NFR-2）。
- **AC-5**: **表示名を変えても参照が壊れない**（FR-7）。
- **AC-6**: **アンカーが自動生成されない**（FR-8/NFR-3）。
- **AC-7**: 候補が提示されても、**確定は制作者が行う**（FR-9）。
- **AC-8**: **骨格が無いモデルでもアンカーを置ける**（FR-10）。
- **AC-9**: **基準を変えたとき、アンカーの意味の変化が示される**（FR-11）。
- **AC-10**: **書き出し時の軸・単位変換で保存値が変わらない**（FR-12/NFR-6）。
- **AC-11**: 付与後も**元モデルがバイト不変**（FR-13/NFR-4）。
- **AC-12**: 操作が**履歴に乗り、取り消せる**（FR-14）。
- **AC-13**: **モデルに重ねて配置**できる（FR-15/NFR-5）。

## 8. 非目標

- role の網羅（FR-4 のとおり**閉じない**。初期セットは実装時に判断）。
- 骨格との対応付け（**F-3D-08**）。
- 当たり判定（**F-3D-07**）。
- アンカーの自動推定（FR-8）。
- アニメーション中のアンカー追従（骨格・動きの担当。必要なら別判断）。
- 対象エンジンごとの変換（**F-3D-15**）。
