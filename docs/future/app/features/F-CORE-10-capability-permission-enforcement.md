## 0. 完成系での位置づけ（逆算リンク）

由来する完成系（`features/README.md` 2 章）:

- **S-DONE-2**: 必要な機能だけをインストールして広げられる（＝**安心して足せる**ことが前提）。
- **S-DONE-4**: 失敗・制限が文章で分かり、手動で必ず回復できる。

逆算の理由: 本コンセプトは**ブラウザのサンドボックスを前提にしない**（`APP_PRODUCT_VISION.md` 2 章：OS のファイル・メモリ・並列処理・GPU を正面から使う）。つまり**ブラウザが代わりに守ってくれていた境界が無くなる**。そこへ「後から機能を足せる」機構を組み合わせる以上、**モジュールに与える力を絞る仕組みが無ければ、拡張性がそのまま危険性になる**。

これは `APP-RISK-07`（ネイティブ化を理由に安全境界を緩める）を塞ぐ機構であり、外部事例の教訓（`APP_COMPETITIVE_LANDSCAPE.md` 3 章：**拡張機構の設計品質が製品の運命を左右する**）への回答でもある。本機能は **`A8 capability 権限` の正本**である。

関係マップのノード: `A8 capability 権限`（本機能が実現）、`A9 Extension Host`（強制の実行主体）、`A6 Manifest 契約`（宣言の出所）、`G5 非破壊`（Source への書き込み禁止）。

## 1. ユーザーストーリー

- 制作者として、足した機能が**自分のファイルを勝手に読み書きしない**と信じたい。
- 制作者として、**勝手に外部へ通信しない**と信じたい。必要なら**理由を説明して聞いてほしい**。
- 制作者として、機能が**何をできるのか**を入れる前に知りたい。
- 制作者として、**元の素材が壊されることは絶対に無い**と確信したい。

## 2. 用語

- **capability**: モジュールが宣言する「必要な能力」（`A6` manifest の `capabilities`）。
- **最小権限**: 宣言し、承認された能力だけを持つ状態。
- **deny by default**: 宣言が無い・不明なものは**拒否**する既定。
- **権限昇格**: 与えられていない能力を、迂回して得ようとすること。

## 3. 機能要件（FR）

### 3.1 宣言と最小権限

- **FR-1** モジュールは必要な capability を **manifest で宣言**する（`A6`）。**宣言していない能力は使えない**。
- **FR-2** **Core が強制する**。宣言を「自己申告として信用する」だけにしない。実行時の判定主体は **Extension Host（`A9`）**（`A8` 強制 `A9`）。
- **FR-3** **deny by default**: 未宣言・不明・解釈不能は、すべて**拒否**側に倒す。

### 3.2 権限の区分

- **FR-4** capability を**意味のある単位に区分**する（概念例。実際の粒度は実装時に確定）:
  - **project 読み取り** / **派生への書き込み**（`G5` の派生領域のみ）
  - **利用者が選んだファイルへのアクセス**（任意のファイルシステム走査ではない）
  - **ネットワーク**（既定不可。FR-6）
  - **GPU / 重い計算資源**
  - **サブプロセス・ネイティブ実行**（最も強い区分として明確に隔離）
- **FR-5** **Source（元データ）への書き込みは、いかなる capability でも許可しない**（`G5`、F-CORE-03 NFR-1 の絶対性を権限側からも保証）。
- **FR-6** **ネットワークは既定で不可**。必要な場合のみ**明示宣言 + 理由表示 + 利用者承認**を要する（オフライン既定。`APP_PRODUCT_VISION.md` 7 章）。

### 3.3 開示と実行時

- **FR-7** **導入前に要求権限を開示**する（F-MOD-02 FR-1／F-MOD-03 FR-8 の材料）。**依存が要求する権限も隠さない**。
- **FR-8** **実行時の権限違反を拒否し、記録し、理由を利用者へ示す**（無言で失敗させない。`S-DONE-4`）。
- **FR-9** **権限昇格の経路を作らない**。モジュール同士で権限を貸し借りさせない。他モジュールの拡張点を踏み台にさせない。
- **FR-10** **無効化・撤去で権限も失効**する（F-MOD-02 / F-CORE-09 のライフサイクルに追随）。

## 4. 非機能要件（NFR）

- **NFR-1（deny by default）**: 判断できないものは拒否する（FR-3）。
- **NFR-2（最小権限）**: 与える力は宣言・承認された範囲に限る。
- **NFR-3（可観測性）**: 何が許可され、何が拒否されたかを後から確認できる（FR-8）。
- **NFR-4（非破壊の保証）**: 権限機構が `G5` を破る経路を持たない（FR-5）。
- **NFR-5（性能）**: 強制のオーバーヘッドが体感に出ない（`PF1` の予算内）。
- **NFR-6（明快さ）**: 権限の意味が利用者に伝わる言葉で示される（専門用語の羅列にしない）。

## 5. データ・保存への影響

- 権限の宣言・承認状態は**アプリ環境レベル**。**プロジェクト保存の器（F-CORE-05）に含めない**。
- **`G5` の保証点**: 権限機構は Source への書き込み経路を持たない。派生（Derivation）への書き込みのみを許す（F-CORE-03 と対）。
- 権限が無い／失効しても、**プロジェクトデータは保持**される（`D3`）。権限の喪失はデータの喪失ではない。

## 6. 依存機能

- **F-CORE-09**（Extension Host）: 強制の実行主体（`A8` 強制 `A9`）。
- **A6 / Manifest 契約**: capability 宣言の出所。
- **F-CORE-03**（非破壊）: Source 不可侵の対象定義（FR-5）。
- **F-MOD-02 / F-MOD-03**: 導入前の権限開示（依存込み集約）。
- **F-PLT-01**（ネイティブ外殻）: OS 権限との対応付け（外殻方式決定後）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 宣言していない能力をモジュールが使おうとすると**拒否され、理由が記録・提示**される（FR-1/FR-2/FR-8）。
- **AC-2**: 未宣言・不明な要求が**既定で拒否**される（FR-3/NFR-1）。
- **AC-3**: **いかなる capability でも Source を書き換えられない**（FR-5、F-CORE-03 AC-1/AC-6 と整合）。
- **AC-4**: ネットワークを宣言していないモジュールが**通信できない**。宣言時は理由表示と承認を経る（FR-6）。
- **AC-5**: 導入前に、**依存込みの要求権限**が開示される（FR-7）。
- **AC-6**: モジュールが他モジュールを踏み台に**権限を拡大できない**（FR-9）。
- **AC-7**: 無効化・撤去で**権限が失効**し、以後その能力を行使できない（FR-10）。
- **AC-8**: 権限が無い状態でも**プロジェクトデータが保持**される（`D3`）。

## 8. 非目標

- 拡張点の設計・ライフサイクルそのもの（**F-CORE-09**）。
- 第三者拡張向けの強いサンドボックス（別プロセス隔離等）の採否（Stage 4、`G4`。本機能は公式モジュール前提の最小権限を定義）。
- OS ごとの権限 API の具体（`PF5` / F-PLT-01 の決定後）。
- ライセンス・法的な可否（F-MOD-04）。権限は**技術的にできること**の制御であり、**してよいこと**の判断とは別。
