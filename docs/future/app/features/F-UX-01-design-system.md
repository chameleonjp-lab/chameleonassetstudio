## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **S-DONE-3**: 2D と 3D が、**別最適化されつつ同じ操作感**で行き来できる。
- **S-DONE-1**: Home から 2D・3D いずれのプロジェクトへも入れる。

逆算の理由: 本コンセプトは **目的別に分ける**（`P5`）と決めた。分けた以上、**「別々の道具を 2 つ持たされた」と感じさせない**仕掛けが要る。それが本機能である。

そして `F-2D-01`〜`16` と `F-3D-01`〜`15` が出揃った**今だからこそ**、横断的な一貫性を**後から**定義できる。**先に決めた見た目に機能を合わせるのではなく、揃った機能から共通の作法を抽出する**——順序として、こちらが正しい。

## 1. ユーザーストーリー

- 制作者として、**2D で覚えた操作が 3D でも通じる**と嬉しい。
- 制作者として、**同じ意味のものが同じ言葉で呼ばれている**と迷わない。
- 制作者として、**今どういう状態か**が、どの画面でも同じ形で分かってほしい。
- 制作者として、**モジュールを足しても、見た目や作法がちぐはぐにならない**でほしい。
- 制作者として、**2D と 3D で違って当然の部分**は、無理に揃えないでほしい。

## 2. 用語

- **作法**: 同じ意味の操作を、同じ形で提供する取り決め。
- **語彙**: 同じものを指す言葉。
- **状態表示**: 空・処理中・成功・警告・失敗・保存状況の見せ方。

## 3. 機能要件（FR）

### 3.1 揃えるもの（継承）

- **FR-1** **同じ見た目・同じ言葉遣い・同じ配置の規則**を 2D / 3D で共有する（系譜: 上流 §1-2）。
- **FR-2** **状態表示の形を共通化**する（系譜: 上流 §7）。少なくとも次を同じ形で扱う:
  - **空**: 目的と次の操作を短い文で示し、主要な入口を出す（**空の画面を放置しない**）。
  - **処理中**: 進み具合と**中断**。**長くかかる場合は目安**を示す。
  - **成功**: 控えめに示す（**達成を大げさに祝わない**）。
  - **警告**: 件数と一覧への導線。**作業は続行できる**。
  - **失敗**: **理由と復旧手段**（`F-UX-03`）。
  - **保存状況**: **常に見える位置**に置く。
- **FR-3** **待たせる処理は、進み具合・中断・失敗理由を必ず持つ**（系譜: 上流 §1-4。**例外を作らない**——`F-PLT-03` / 各機能の offload 要件と対）。
- **FR-4** **破壊的に見える操作には、前後の数値を示し、取り消せる**ようにする（系譜: 上流 §1-3。`F-3D-12` の前後比較 / `F-2D-14` の実行前分類が、この原則の具体例にあたる）。
- **FR-5** **同じ意味には同じ語彙**を使う（`F-3D-08` FR-8 の「独自語彙を作らない」を、UI 全体へ広げる）。

### 3.2 揃えないもの（分離の尊重）

- **FR-6** **編集面は分ける**（`F-CORE-08` FR-12 / `P5`）。2D の描画面と 3D の表示面を**無理に同じ形にしない**。
- **FR-7** **中身が違うものを、同じ名前で呼ばない**（`F-CORE-06` FR-13 の「段・重大度・提示の作法は共通、中身は別」と同じ）。
- **FR-8** **語彙が同じでも、実装・型・検証を共有しない**（系譜: 上流 `3D-RISK-06`「2D と 3D のモーションテンプレート混同」。**同じ言葉に見えて完全に別物のものがある**。共有してよいのは**呼び名まで**）。

### 3.3 拡張との関係

- **FR-9** **モジュールが提供する UI も、同じ作法・同じ語彙・同じ状態表示に従う**（`A4` / `F-CORE-09`。`F-2D-13` FR-20 / `F-3D-15` FR-29 と同じ規律）。
- **FR-10** モジュールが**独自の見た目を持ち込めない**境界を定める（**足せるのは機能であって、作法ではない**）。

### 3.4 履歴と一時状態（継承）

- **FR-11** **編集操作は、すべて共通の履歴経路に載せる**（系譜: 上流 §8。`F-CORE-04`。**画面ごとに別の取り消し方を作らない**）。
- **FR-12** **一時状態（視点・選択・開いている場所）を保存しない**（系譜: 同上。`F-CORE-01` 6 章 / `F-2D-03` / `F-3D-04` FR-7 と同じ規律を、**横断の取り決めとして固定**する）。

### 3.5 軽さとの関係

- **FR-13** **共通の作法は、未導入のモジュールのコストを持ち込まない**（`P4`。**見た目を揃えるために全部読む、をしない**）。
- **FR-14** 画面の初期表示で、**重い実体を起動しない**（`F-CORE-08` FR-9b と同じ）。

## 4. 非機能要件（NFR）

- **NFR-1（学習の移転）**: 2D で覚えたことが 3D で通じる（FR-1/FR-5）。
- **NFR-2（分離の尊重）**: 違って当然のものを無理に揃えない（FR-6/FR-7）。
- **NFR-3（言葉の正確さ）**: 同じ名前で別物を指さない（FR-8）。
- **NFR-4（拡張の一貫性）**: モジュールが作法を崩さない（FR-9/FR-10）。
- **NFR-5（予測可能性）**: 状態の見え方がどこでも同じ（FR-2）。
- **NFR-6（ゼロコスト）**: 一貫性のために重くしない（FR-13/FR-14）。

## 5. データ・保存への影響

- **保存データに影響しない**。本機能は**見え方と作法**の取り決めである。
- **一時状態を保存しない**境界を横断で固定する（FR-12）。
- 利用者の見た目の設定を持つ場合、**編集データと分ける**（`adr/0007` の層分離）。

## 6. 依存機能

- **F-CORE-08**（Dashboard）: 共通の入口（`S-DONE-1`）。
- **F-CORE-04**（履歴）: 共通の取り消し経路（FR-11）。
- **F-CORE-06 / 07**（検品 / 書き出し）: 状態表示の中身（FR-2）。
- **F-CORE-09**（Extension Host）: モジュール UI の境界（FR-9/FR-10）。
- **F-2D-03 / F-3D-03**（各編集面）: 揃えない部分の担い手（FR-6）。
- **F-UX-02**（アクセシビリティ）: 到達性の要件。
- **F-UX-03**（メッセージ）: 文章の要件。
- **F-PLT-04**（計測）: 一貫性の追加が重さを招いていないかの確認（FR-13）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 2D / 3D で**同じ見た目・言葉遣い・配置の規則**が使われる（FR-1/NFR-1）。
- **AC-2**: **空・処理中・成功・警告・失敗・保存状況**が同じ形で示される（FR-2/NFR-5）。
- **AC-3**: 待たせる処理が**例外なく**進み具合・中断・失敗理由を持つ（FR-3）。
- **AC-4**: 破壊的に見える操作が**前後の数値を示し、取り消せる**（FR-4）。
- **AC-5**: **編集面は分かれている**（FR-6/NFR-2）。
- **AC-6**: **同じ名前で別物が指されていない**（FR-7/FR-8/NFR-3）。
- **AC-7**: **モジュール提供の UI も同じ作法**に従う（FR-9/NFR-4）。
- **AC-8**: モジュールが**独自の見た目を持ち込めない**（FR-10）。
- **AC-9**: 編集操作が**共通の履歴経路**に載る（FR-11）。
- **AC-10**: **一時状態が保存されない**（FR-12）。
- **AC-11**: 一貫性のために**未導入のコストが持ち込まれない**（FR-13/NFR-6）。
- **AC-12**: 画面の初期表示で**重い実体が起動しない**（FR-14）。

## 8. 非目標

- 視覚仕様（色・字形・寸法）の確定（実装時に判断。**作法の枠だけ**を固定）。
- コンポーネント一覧の網羅。
- 2D と 3D の編集面の統一（FR-6。**分けることが目的**）。
- 利用者による見た目の自由変更（必要なら別判断）。
- アクセシビリティの要件（**F-UX-02**）とメッセージの書き方（**F-UX-03**）。
