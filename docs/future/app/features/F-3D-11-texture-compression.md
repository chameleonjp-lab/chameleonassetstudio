## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **T-DONE-6**: **元を壊さず**軽量化した別モデルを作り、前後を比較して選べる。
- **T-DONE-3**: テクスチャ枚数と最大サイズを検品できる（**その結果を受けて直す側**）。

逆算の理由: 3D モデルの重さは、**面の数だけで決まらない**。多くの場合、**テクスチャがメモリと読み込み時間の大半を占める**。`F-3D-10`（mesh 簡略化）が「形」を軽くするのに対し、本機能は **「絵」を軽くする**——**軽量化の二本目の軸**である。

上流の検品必須項目に「テクスチャ枚数」と「テクスチャ最大サイズ」が入っており、警告例に「4096px を超えるテクスチャがあります」があるのは、**そこが実際に効くから**である（系譜: §5 / §5.1）。

## 1. ユーザーストーリー

- 制作者として、**テクスチャが重い原因**を知りたい。
- 制作者として、**画質を落としすぎずに軽くしたい**。
- 制作者として、**圧縮後の見た目を、適用前に見たい**。
- 制作者として、**対象環境で読めない形式を選びたくない**。
- 制作者として、**元のテクスチャを失いたくない**。

## 2. 用語

- **解像度削減**: テクスチャの縦横サイズを小さくすること。
- **圧縮**: データ量を減らす符号化。**見た目が変わり得る**ものと、変わらないものがある。
- **色空間**: 色の解釈規則。**用途によって扱いが違う**（見た目の色と、法線などのデータ）。

## 3. 機能要件（FR）

### 3.1 原因を示す

- **FR-1** **どのテクスチャが重いのか**を示す（枚数・個々のサイズ・最大サイズ・合計。`F-3D-03` の検品項目と**同じ指標**で示す）。
- **FR-2** **重さの意味を示す**（読み込み時間 / メモリ）。**数値だけにしない**（`F-3D-03` FR-6 と同じ）。
- **FR-3** **用途ごとに扱いが違うことを示す**（見た目の色を持つテクスチャと、データを持つテクスチャでは、**許される劣化が違う**）。

### 3.2 軽くする手段

- **FR-4** **解像度の削減**ができる（系譜: 上流 §6「テクスチャサイズ確認」）。
- **FR-5** **圧縮方式の候補を提示**できる（系譜: 上流 §6「テクスチャ圧縮の候補提示」——**提示であって自動適用ではない**）。
- **FR-6** **見た目が変わる処理は、必ずプレビューしてから適用する**（系譜: 上流 §6。`F-3D-10` FR-7 と同じ）。
- **FR-7** **見た目が変わらない処理と、変わる処理を区別**して示す（`F-3D-10` FR-8 と同じ思想）。
- **FR-8** **色空間と透明度の扱いを明示**する。**用途に合わない変換を黙って行わない**（FR-3 と対）。

### 3.3 対応状況を曖昧にしない（継承）

- **FR-9** 圧縮形式ごとに **対象環境での対応状況を示す**。**記録の無いものを「対応」と表示しない**（系譜: `2D_EXPORT_COMPATIBILITY_MATRIX.md` 1 章の原則を 3D へ展開。`F-2D-16` FR-1/FR-2 と同じラベル規律）。
- **FR-10** **対象環境で読めない可能性がある形式を選んだ場合、警告する**（**「軽いが動かない」を作らせない**）。
- **FR-11** 対応状況は **対象とそのバージョンに紐づく**（`F-2D-16` FR-3 と同じ。**永続的な保証として表示しない**）。

### 3.4 非破壊

- **FR-12** **元テクスチャを保持**し、圧縮結果は**派生**として持つ（`G5` / `F-CORE-03`。系譜: 上流 §6「元ファイルを保持する」）。
- **FR-13** **やり直せる**。設定を変えて**複数の候補を持てる**（`F-3D-10` FR-3 と同じ）。
- **FR-14** **採用は必須ではない**。元のまま書き出せる（`F-3D-10` FR-4 と同じ）。

### 3.5 実行と再現性

- **FR-15** 圧縮は **決定的**である（同じ入力・同じ設定で同じ結果。`F-3D-10` FR-15 と同じ）。
- **FR-16** 重い処理は **UI から逃がす**（`PF3` / `F-PLT-03`）。進行を表示し、取消できる。
- **FR-17** **失敗・取消で、プロジェクトを変更しない**（原子性）。
- **FR-18** 外部ライブラリの採用は **ライセンス検証ゲート**を通る（`G1` / `F-MOD-04`）。

## 4. 非機能要件（NFR）

- **NFR-1（原因の可視化）**: どれが重いか・なぜ重いかが判る（FR-1/FR-2）。
- **NFR-2（見てから決める）**: 見た目が変わる処理はプレビューが先（FR-6）。
- **NFR-3（正直さ）**: 対応状況を曖昧にしない（FR-9/FR-10/FR-11）。
- **NFR-4（非破壊）**: 元テクスチャが不変（FR-12。`G5`）。
- **NFR-5（決定性）**: 同じ設定に同じ結果（FR-15）。
- **NFR-6（原子性）**: 失敗が何も壊さない（FR-17）。
- **NFR-7（用途の尊重）**: データ用テクスチャを見た目用と同じに扱わない（FR-3/FR-8）。

## 5. データ・保存への影響

- **元テクスチャは Source として不変**（FR-12）。圧縮結果は**派生**（`F-CORE-03`）。
- 圧縮の**設定を保存し得る**（再現のため。FR-15）。additive / 名前空間分離（`D4`）。
- **書き出しに含めるかは `F-3D-15` の判断**（FR-14）。
- 対応状況の記録は **対象とバージョンに紐づけて**保存する（FR-11。`F-2D-16` の verification record と同じ考え方）。

## 6. 依存機能

- **F-3D-01**（安全読み込み）: 元テクスチャの供給と verbatim 保持。
- **F-3D-03**（検品表示）: 重さの指標（FR-1）。
- **F-3D-10**（mesh 簡略化）: 軽量化のもう一つの軸。
- **F-3D-12**（前後比較）: 採用可否の判断面。
- **F-3D-15**（書き出し）: 圧縮結果の同梱と対応状況の表示（FR-9/FR-14）。
- **F-PLT-03**（offload）: 重い処理（FR-16）。
- **F-MOD-04**（ライセンス検証）: 外部ライブラリの門（FR-18）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: **どのテクスチャが重いか**が、`F-3D-03` と同じ指標で示される（FR-1/NFR-1）。
- **AC-2**: 重さの**意味（読み込み / メモリ）**が伴う（FR-2）。
- **AC-3**: **用途ごとに許される劣化が違う**ことが示される（FR-3/NFR-7）。
- **AC-4**: **解像度削減**ができる（FR-4）。
- **AC-5**: 圧縮方式が**候補として提示**され、**自動適用されない**（FR-5）。
- **AC-6**: **見た目が変わる処理が、プレビューなしに適用されない**（FR-6/NFR-2）。
- **AC-7**: **見た目が変わる処理と変わらない処理が区別**される（FR-7）。
- **AC-8**: **色空間・透明度の扱いが明示**され、用途に合わない変換が黙って行われない（FR-8）。
- **AC-9**: **記録の無い形式が「対応」と表示されない**（FR-9/NFR-3、`F-2D-16` AC-2 と同じ規律）。
- **AC-10**: **対象環境で読めない可能性がある形式で警告**される（FR-10）。
- **AC-11**: 対応状況が**対象バージョンに紐づく**（FR-11）。
- **AC-12**: 圧縮後も**元テクスチャがバイト不変**（FR-12/NFR-4）。
- **AC-13**: 設定を変えて**複数の候補を持て**、**採用せず元のまま書き出せる**（FR-13/FR-14）。
- **AC-14**: 同じ設定で**同じ結果**になる（FR-15/NFR-5）。
- **AC-15**: 失敗・取消で**プロジェクトが変わらない**（FR-17/NFR-6）。
- **AC-16**: 外部ライブラリが**ライセンス検証を通らずに入らない**（FR-18）。

## 8. 非目標

- 圧縮形式の確定（`G1` の評価と対応状況の記録が先。**候補名を採用として書かない**）。
- 自動での「最適な圧縮」選択（FR-5 のとおり**提示に留める**）。
- テクスチャの内容編集（描き直し・修復）。**軽くするのであって作り直すのではない**。
- mesh の簡略化（**F-3D-10**）。
- 前後比較の面（**F-3D-12**）。
- 対象環境ごとの書き出し構成（**F-3D-15**）。
