## 0. 完成系での位置づけ（逆算リンク）

由来する完成系（`features/README.md` 2 章）:

- **S-DONE-2**: 最小構成で軽く起動し、**必要な機能だけをインストール**して広げられる。**使わない機能の重さを負わない。**

逆算の理由: F-MOD-02 は「合計コストを見せて入れる／外せば戻る」を要件にした。しかしその**合計が正しくなければ、利用者の判断は成り立たない**。1 つのモジュールが別のモジュールを連れてくれば重さは増え、共有依存を二重計上すれば過大に、撤去で共有依存を巻き添えにすれば他機能が壊れる。本機能は、**依存を正しくたどり、増分としての重さを誠実に開示し、撤去時に壊さない**ことを定義する。

関係マップのノード: `A7 依存解決`（本機能が実現）、`A6 Manifest 契約`（dependsOn / footprint / coreContract の出所）、`P4 未使用ゼロコスト`（増分計上と orphan 回収）、`PF2 計測・退行検知`（宣言値と実測の突き合わせ）。

## 1. ユーザーストーリー

- 制作者として、1 つ入れるつもりが**実際は何が一緒に入るのか**を知りたい。
- 制作者として、**「なぜこれも入るのか」**の理由を辿れると納得できる。
- 制作者として、**すでに入っている共有部分は二重に数えない**、正直な増分を見たい。
- 制作者として、**外したときに他の機能が壊れない**と信じたい。
- 制作者として、外して**不要になった連れ物も、確認のうえ片付けたい**（残ったままにされたくない）。

## 2. 用語

- **推移的依存**: `dependsOn` をたどって必要になるモジュールの全体。
- **共有依存**: 複数モジュールから必要とされる依存。
- **逆依存（dependents）**: あるモジュールを必要としている側の集合。
- **orphan**: 撤去の結果、どこからも必要とされなくなった依存。
- **宣言 footprint**: manifest が申告する重さ（`installMB` / `residentMB` / `startupMs`）。
- **実測 footprint**: 実際に計測した重さ（`PF2` / F-PLT-04）。
- **増分コスト**: 現在の構成に対して**新たに増える分**（すでに導入済みの共有依存を含まない）。

## 3. 機能要件（FR）

### 3.1 解決

- **FR-1** `dependsOn` を**推移的に解決**し、導入に必要なモジュール集合を確定する。
- **FR-2** 解決は**決定的**である（同じ構成・同じ入力なら、同じ集合・同じ順序）。
- **FR-3** **循環依存**を検出し、導入を**拒否**する（理由を提示）。黙って一部だけ入れない。
- **FR-4** **導入不可条件**を導入前に検出し、理由つきで拒否する: `coreContract` 範囲外、`edition` 不一致、依存の version 要求の衝突。
- **FR-5** 衝突を**勝手な強制解決で潰さない**（片方を黙って落とす・降格させる等をしない）。解決できない場合は「できない理由」を示して止まる。

### 3.2 開示

- **FR-6** 導入前に、**増分コスト**を提示する（追加サイズ / 常駐見込み / 起動影響）。**すでに導入済みの共有依存を二重計上しない**（`P4`）。
- **FR-7** **依存理由の可視化**: 連れてくる各モジュールについて「どれが要求しているか」を辿れる（FR-6 の内訳）。
- **FR-8** 依存が要求する **capabilities（権限）も合算して開示**する。依存側の権限を隠さない（F-MOD-02 FR-1 の承認材料に含める）。
- **FR-9** 依存込みで **ライセンス・verified 状態を集約**して示す。**verified でない依存を含む導入は成立しない**（enforcement は F-MOD-04）。

### 3.3 撤去と回収

- **FR-10** 撤去時は**逆依存を尊重**する。**まだ他から必要とされている共有依存を巻き添えで消さない**。
- **FR-11** 撤去で **orphan** になった依存を検出し、**回収候補として提示**する。回収は利用者の確認のうえ行い、黙って残さない・黙って消さない（`P4` のコスト戻りと、他機能を壊さないことの両立）。
- **FR-12** 解決・回収の途中失敗で、アプリを**不整合状態にしない**（F-MOD-02 FR-7 の原子性に乗る）。

### 3.4 宣言値と実測の突き合わせ

- **FR-13** **宣言 footprint と実測 footprint を突き合わせ**、乖離を検出できるようにする（`PF2` / F-PLT-04）。乖離は「宣言が信用できない」兆候として扱う（`APP-RISK-02` の早期検知）。

## 4. 非機能要件（NFR）

- **NFR-1（誠実さ）**: 提示する増分コストが実態と一致する。過小申告を検出できる（FR-13）。
- **NFR-2（決定性）**: 解決結果が再現する（FR-2）。
- **NFR-3（透明性）**: 何がなぜ入る/出るかを、利用者が理由まで辿れる（FR-7）。
- **NFR-4（非破壊）**: 撤去・回収が他機能とプロジェクトを壊さない（FR-10、F-MOD-02 NFR-3）。
- **NFR-5（性能）**: 依存数が増えても解決・提示が待たされない。UI を固めない（F-PLT-03）。
- **NFR-6（オフライン）**: ローカル構成の解決はオフラインで完結。

## 5. データ・保存への影響

- 解決結果・依存グラフ・導入集合は**アプリ環境レベル**の情報であり、**プロジェクト保存の器（F-CORE-05）に含めない**（F-MOD-01 / 02 と同じ分離）。
- 依存の有無はプロジェクトデータの解釈可否に影響するが、**データそのものは常に保持される**（`D3`、F-CORE-05 の未知データ往復）。依存が無い＝データ削除ではない。

## 6. 依存機能

- **A6 / Manifest 契約**: `dependsOn` / `footprint` / `coreContract` / `capabilities` / `license` の出所。
- **F-MOD-02**（導入/撤去）: 本機能の解決結果を使って導入・撤去する（合計コスト承認・逆依存尊重）。
- **F-MOD-01**（カタログ）: 依存・footprint の単体表示。合計は本機能。
- **F-MOD-04**（ライセンス検証）: 依存込み verified の enforcement（FR-9）。
- **F-PLT-04**（計測 & 退行検知）: 実測 footprint の供給（FR-13）。
- **F-MOD-05**（プロファイル）: 束ねた一括導入も本機能の解決に乗る。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: A が B を必要とするとき、A の導入提示に **B が理由つきで含まれ**、合計が A+B で示される（FR-1/FR-7）。
- **AC-2**: B が導入済みの状態で A を入れるとき、提示される増分に **B が二重計上されない**（FR-6）。
- **AC-3**: A と C が B を共有する状態で A を外しても、**B は残り C は動く**（FR-10）。
- **AC-4**: 最後の依存元を外すと **B が orphan として提示**され、確認のうえ回収できる（FR-11）。
- **AC-5**: `coreContract` 範囲外・edition 不一致・version 衝突・循環依存は、**理由つきで導入前に拒否**される（FR-3/FR-4/FR-5）。
- **AC-6**: 依存が要求する権限と、依存込みのライセンス/verified 状態が、承認前に開示される（FR-8/FR-9）。
- **AC-7**: 同じ構成・同じ入力に対する解決結果が毎回一致する（NFR-2）。
- **AC-8**: 宣言 footprint と実測の乖離が検出・提示できる（FR-13）。

## 8. 非目標

- オンライン配布・署名（未決 `APP-O-02`）。
