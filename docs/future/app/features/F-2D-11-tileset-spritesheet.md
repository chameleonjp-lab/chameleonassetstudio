## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **D-DONE-5**: **tileset / sprite sheet を再整理**し、atlas に詰められる。
- **D-DONE-1**: 画像取り込みから作れる（**既存のシートを持ち込む**入口）。

逆算の理由: ゲーム制作では、**すでにシート状になった素材を受け取る／作り直す**場面が多い。ここは **「1 枚の画像を、意味のある単位へ切り分ける」** 工程であり、`F-2D-02`（取り込み）と `F-2D-12`（atlas 化）の**間**に位置する。

`APP_COMPETITIVE_LANDSCAPE.md` で見たとおり、この領域は Tiled（12.7k★）/ LDtk（4.1k★）が確立した期待値を持つ。**データ形式の素直さ**が価値になる領域である。

## 1. ユーザーストーリー

- 制作者として、**1 枚のシートを格子で切り分けて**使いたい。
- 制作者として、**切り出した各コマに名前を付けて**管理したい。
- 制作者として、**タイルとして扱う**場合に、サイズや並びを整えたい。
- 制作者として、**自分が書き出したシートを、あとから読み直せる**と嬉しい。
- 制作者として、**読み直しで失われるものがあるなら、事前に知りたい**。

## 2. 機能要件（FR）

### 2.1 切り分け

- **FR-1** 1 枚の画像を **格子（セル）で切り分け**られる（セルサイズ・余白・間隔の指定）。
- **FR-2** 切り分けた各コマを**フレーム／レイヤーとして扱える**（`F-2D-04` / `F-2D-07` の構造に載せる）。
- **FR-3** 各コマに **名前を付けられ、名前は一意**である（外部で参照されるため。`F-CORE-06` の意味検証に載る）。
- **FR-4** 切り分けは **非破壊**であり、**元画像（Source）を書き換えない**（`G5` / F-2D-02 FR-6）。やり直せる。

### 2.2 tileset としての扱い

- **FR-5** **tile として扱うモード**を持つ（`F-2D-01` FR-2 のアセット種別と接続）。
- **FR-6** **タイルサイズとキャンバスの関係を検証**する（割り切れない場合は**警告**する。系譜: ADR-0018 の tileSize ≦ cellSize・非除算は warning）。
- **FR-7** タイル用の設定（当たり方・見た目の分類など）を持てる。**当たり判定を勝手に自動生成しない**（系譜: ADR-0018。推測で作らない）。

### 2.3 自形式シートの読み直し（継承 — 重要）

- **FR-8** **自分が書き出したシートを読み直せる**。ただしこれは **「配布物を元のプロジェクトへ戻す操作ではない」**（系譜: ADR-0018）。**新しい ID 体系の、平坦化されたアセットを作る**操作である。
- **FR-9** 読み直しで **復元できないものを明示**する（系譜: ADR-0018）: 元のレイヤー構造・変形・パーツ・タグ・ゲーム属性・リグ・元の出所情報・識別子・可変時間など。
- **FR-10** **loss / 警告の確認を必須**とする（系譜: ADR-0018。黙って進めない。`F-2D-02` FR-17 と同じ規律）。
- **FR-11** **元画像は verbatim 保持**し、付随データは**そのまま保存しない場合、その旨を loss として示す**（系譜: ADR-0018 の「raw JSON 非保持を常時 loss 表示」）。
- **FR-12** 読み直しの**受け入れ条件を厳格に定める**（想定した構成・サイズ・件数・参照の解決）。**外部ツールの形式を「対応」と表現しない**（系譜: ADR-0018/0016。`F-2D-02` FR-2 と同じ）。
- **FR-13** **現行の書き出し結果すべてが読み直せるとは表現しない**（系譜: ADR-0018 の明示）。

### 2.4 安全と原子性

- **FR-14** 取り消し・検証失敗・保存失敗では、**プロジェクトを変更しない**（系譜: ADR-0018。`F-2D-02` FR-9 と同じ）。
- **FR-15** **隔離（quarantine）の対象を限定**する（画像として壊れているものに限り、**構成の不一致は隔離せず理由つきで拒否**）（系譜: ADR-0018。`F-2D-02` FR-8 と同じ思想）。

## 3. 非機能要件（NFR）

- **NFR-1（非破壊）**: 元画像が不変（FR-4/FR-11）。
- **NFR-2（正直さ）**: 復元できないものを事前に示す（FR-9/FR-10/FR-13）。
- **NFR-3（原子性）**: 失敗時に何も変えない（FR-14）。
- **NFR-4（明快さ）**: 「読み直し」が**元に戻す操作ではない**と分かる（FR-8）。
- **NFR-5（応答性）**: 大きなシートでも UI を固めない（`PF3`）。

## 4. データ・保存への影響

- 切り分け結果は **`F-2D-04` / `F-2D-07` の構造**として保存する（独自形式を作らない）。
- **元画像は Source として verbatim 保持**（F-2D-02 / F-CORE-03）。
- 読み直しで生成するものは **新しい ID 体系**とし、**元のプロジェクトの ID を再利用しない**（FR-8。系譜: ADR-0018）。

## 5. 依存機能

- **F-2D-02**（取り込み）: シート画像の入口・安全な読み込み。
- **F-2D-04 / F-2D-07**: 切り出し結果の載り先。
- **F-2D-12**（Atlas パッキング）: 詰め直しの相手。
- **F-CORE-06**（検品）: 名前の一意性・構成の検証・loss 提示。
- **F-CORE-03 / 04**: 非破壊・履歴。

## 6. 受け入れ条件（Acceptance）

- **AC-1**: 格子で切り分けられ、各コマが**フレーム／レイヤーとして扱える**（FR-1/FR-2）。
- **AC-2**: 各コマに**一意な名前**が付き、重複が検出される（FR-3）。
- **AC-3**: 切り分け後も**元画像がバイト不変**（FR-4/NFR-1）。
- **AC-4**: タイルサイズが割り切れない場合に**警告**される（FR-6）。
- **AC-5**: **当たり判定が勝手に自動生成されない**（FR-7）。
- **AC-6**: 自形式シートの読み直しが、**「元に戻す操作ではない」と示され**、**新しい ID 体系**で作られる（FR-8/NFR-4）。
- **AC-7**: **復元できないものが列挙され、確認なしに進まない**（FR-9/FR-10）。
- **AC-8**: **すべての書き出しが読み直せるとは表現されない**（FR-13）。
- **AC-9**: 失敗・取り消しで**プロジェクトが変わらない**（FR-14/NFR-3）。

## 7. 非目標

- **外部ツール形式（Tiled / Aseprite JSON 等）の読み込み**（系譜と同じく対象外。必要なら別判断 + ライセンス評価）。
- 配布物からプロジェクトを**完全復元**すること（FR-8 で明確に否定）。
- タイルマップ（配置）の編集。本機能は**素材としての tileset 整理**であり、レベルエディタではない。
- 自動での当たり判定生成（FR-7）。
- atlas への詰め方（**F-2D-12**）。
