## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **S-DONE-2**: 最小構成で軽く起動し、**必要な機能だけをインストールして広げられる**。使わない機能の重さを負わない。

逆算の理由: `F-MOD-01`〜`04` は **install-on-demand を機構として**完成させた——一覧でき、入れられ、依存が解け、ライセンスが検証される。しかし機構が正しくても、**利用者が「自分に何が必要か」を判断できなければ、選択は負担にしかならない**。

**選択肢の多さは、それ自体が使われない理由になり得る**（`P1`）。50 個のモジュールから正しい 8 個を選べと言われた利用者は、**多機能ゆえに重いアプリを避けた先で、今度は選択の重さに直面する**。本機能はその橋を架ける。

ただし——**束ねた提示は、install-on-demand の原則を裏切りやすい**。「おすすめ」を既定で入れてしまえば、それは**ただの全部入り**である。**提示と決定を分けること**が本機能の生命線になる。

## 1. ユーザーストーリー

- 制作者として、**自分の用途を言えば、必要そうなものを教えてほしい**。
- 制作者として、**一つずつ吟味しなくても始められる**と助かる。
- 制作者として、**まとめて入れる前に、合計の重さを知りたい**。
- 制作者として、**まとめて入れたものを、あとから individually 外せる**ようにしたい。
- 制作者として、**勧められたものを断っても、不便にならない**でほしい。
- 制作者として、**「おすすめ」が実は全部入りだった**、を避けたい。

## 2. 用語

- **プロファイル**: 用途に応じた、モジュールのまとまりの提案。
- **提示**: こういう組み合わせがある、と示すこと。
- **適用**: 提示された組み合わせを実際に導入すること。

## 3. 機能要件（FR）

### 3.1 提示と決定を分ける（本機能の生命線）

- **FR-1** プロファイルは **提案であり、既定ではない**（`F-UX-05` FR-10。**選ばなくても始められる**）。
- **FR-2** **適用は明示的な操作**を要する（`F-MOD-02` の導入経路に乗る。**選んだ瞬間に入らない**）。
- **FR-3** **適用前に、含まれるモジュールと合計の重さを提示**する（`F-MOD-03` FR の footprint 開示。**中身を見せずに束ねない**）。
- **FR-4** **一部だけを選べる**（**束は分解できる**。**全部か無かにしない**）。
- **FR-5** **断ることに不利益がない**（**断った利用者に、繰り返し勧めない**）。

### 3.2 束ね方の規律

- **FR-6** プロファイルは **用途で束ねる**（何を作るか）。**「上級者向け」のような曖昧な括りにしない**。
- **FR-7** **なぜその組み合わせなのかを示す**（**根拠のない「おすすめ」を出さない**。`F-UX-03` FR-3 と同じ思想）。
- **FR-8** **最小構成も一つの選択肢**として並べる（**何も足さないことが、正当な選択である**と示す。`F-UX-05` FR-1/FR-2 と対）。
- **FR-9** **プロファイルが肥大しない**ようにする（**「とりあえず入れておく」を束の中に作らない**。**未使用ゼロコストは、束ねた瞬間に失われやすい**）。

### 3.3 適用後

- **FR-10** 適用後も、**個々のモジュールを独立に撤去できる**（`F-MOD-02`。**束で入れたものが、束でしか外せない状態にしない**）。
- **FR-11** **プロファイルとの一致を強制しない**（適用後に外しても、**「構成が壊れている」と扱わない**）。
- **FR-12** **適用の結果として何が入ったかを、後から確認できる**（**入れた覚えのないものが増えない**）。

### 3.4 提供と拡張

- **FR-13** プロファイルは **カタログの一部として提示**する（`F-MOD-01`。**別系統の勧誘経路を作らない**）。
- **FR-14** **未検証のモジュールをプロファイルに含めない**（`G1` / `F-MOD-04`。**束ねることで検証を迂回させない**）。
- **FR-15** **モジュールがプロファイルを提供できる**場合も、**同じ規律に従う**（`A4`。**提示であって既定ではない**、**根拠を示す**、**分解できる**）。

### 3.5 対象との関係

- **FR-16** **書き出し先や制作対象に応じたプロファイル**を持てる（系譜: 上流の対象別優先順位。**「この対象向けに作るなら、これが要る」**）。
- **FR-17** ただし **対象への対応区分（確認済み / 未確認）を、プロファイルが上書きしない**（`F-2D-16` FR-2 / `F-3D-15` FR-16。**束に入っていることは、確認済みであることを意味しない**）。

## 4. 非機能要件（NFR）

- **NFR-1（提示と決定の分離）**: 選んだ瞬間に入らない（FR-1/FR-2）。
- **NFR-2（透明さ）**: 中身と重さと根拠が見える（FR-3/FR-7）。
- **NFR-3（分解できる）**: 束が檻にならない（FR-4/FR-10）。
- **NFR-4（断れる）**: 断っても不便にならず、繰り返し勧められない（FR-5）。
- **NFR-5（肥大しない）**: 束の中に「とりあえず」を作らない（FR-9）。
- **NFR-6（検証を迂回しない）**: 未検証を束で通さない（FR-14）。

## 5. データ・保存への影響

- **プロジェクトデータに影響しない**。プロファイルは**導入の提案**であり、制作データではない。
- 適用の履歴を持つ場合、**利用者設定として編集データと分ける**（`adr/0007`）。
- **どのモジュールが入っているかの正本は `F-MOD-02` 側**にある（**プロファイルを構成の正本にしない**。FR-11）。

## 6. 依存機能

- **F-MOD-01**（カタログ）: 提示の場（FR-13）。
- **F-MOD-02**（導入 / 撤去）: 適用と個別撤去（FR-2/FR-10）。
- **F-MOD-03**（依存解決 / footprint）: 合計の重さ（FR-3）。
- **F-MOD-04**（ライセンス検証）: 未検証の排除（FR-14）。
- **F-UX-05**（初回起動）: 最初の提示の場（FR-1/FR-8）。
- **F-MOD-06**（文脈連動）: 必要になった時の提示（**本機能は「先に束ねる」、あちらは「その時に示す」**）。
- **F-2D-16 / F-3D-15**（書き出し preset）: 対象との対応（FR-16/FR-17）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: プロファイルが**既定ではなく、選ばなくても始められる**（FR-1/NFR-1）。
- **AC-2**: **適用に明示的な操作**を要し、選んだ瞬間に入らない（FR-2/NFR-1）。
- **AC-3**: 適用前に**含まれるモジュールと合計の重さ**が示される（FR-3/NFR-2）。
- **AC-4**: **一部だけを選べる**（FR-4/NFR-3）。
- **AC-5**: **断っても不便にならず、繰り返し勧められない**（FR-5/NFR-4）。
- **AC-6**: プロファイルが**用途で束ねられ**、曖昧な括りでない（FR-6）。
- **AC-7**: **なぜその組み合わせかが示される**（FR-7/NFR-2）。
- **AC-8**: **最小構成も選択肢として並ぶ**（FR-8）。
- **AC-9**: **束の中に「とりあえず」が入っていない**（FR-9/NFR-5）。
- **AC-10**: 適用後も**個々に撤去できる**（FR-10/NFR-3）。
- **AC-11**: 適用後に外しても**「構成が壊れている」と扱われない**（FR-11）。
- **AC-12**: **何が入ったかを後から確認できる**（FR-12）。
- **AC-13**: プロファイルが**カタログの一部**として提示される（FR-13）。
- **AC-14**: **未検証のモジュールが束に含まれない**（FR-14/NFR-6）。
- **AC-15**: モジュール提供のプロファイルも**同じ規律**に従う（FR-15）。
- **AC-16**: **束に入っていることが、対象での確認済みを意味しない**（FR-17）。

## 8. 非目標

- **プロファイルの中身の確定**（実装時／運用で判断。**束ね方の規律だけ**を固定）。
- **既定のプロファイル**（FR-1。**既定は最小構成**）。
- 利用状況に基づく自動推薦（**外部送信しない**前提。必要なら別判断）。
- 構成の強制・固定（FR-11。**プロファイルは檻ではない**）。
- 文脈に応じた提示（**F-MOD-06**）。
- 導入・撤去の機構（**F-MOD-02**）。
