## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **T-DONE-3**: ファイルサイズ・ポリゴン数・マテリアル・テクスチャ・bounds・妥当性を**検品できる**。
- **T-DONE-4**: 原点・足元・向き・スケールを整えられる（**その前提となる「見る」面**）。

逆算の理由: 上流が明言したとおり、**3D 対応の最初の価値は「生成」ではなく「検品と軽量化」**である（系譜: 上流 §15）。生成された 3D モデルは、**そのままではゲームに入らない**——重すぎる、原点が足元にない、テクスチャが 4096px、マテリアルが分かれすぎている。**その事実を最初に見せる場所**が本機能である。

`F-2D-03`（2D Canvas）が「全 2D 編集が載る面」であるのと同じく、本機能は **全 3D 作業が載る面**であり、同時に **`F-CORE-06`（検品フレーム）の 3D 具体化**でもある。

## 1. ユーザーストーリー

- 制作者として、**読み込んだモデルを見たい**（回して、寄って、確かめたい）。
- 制作者として、**このモデルが重いのか軽いのか**を知りたい。
- 制作者として、**何が重さの原因か**を知りたい（数字だけでは直せない）。
- 制作者として、**原点や足元がずれていないか**を見たい。
- 制作者として、**対象（スマホ / Web / PC）ごとに基準が違う**ことを反映してほしい。
- 制作者として、**見ているだけでモデルが変わらない**と確信したい。

## 2. 用語

- **bounds**: モデルが占める直方体の範囲。サイズと中心のずれを見る。
- **しきい値プリセット**: 対象環境ごとの「重さ」の基準（例: モバイル / Web / デスクトップ）。
- **read-only**: 表示・計測がデータを変更しないこと。

## 3. 機能要件（FR）

### 3.1 見る（ビューポート）

- **FR-1** 読み込んだモデルを **3D で表示**し、**視点操作**（回転・寄り引き・平行移動）ができる。
- **FR-2** **bounds・原点・足元基準・向き**を**モデルに重ねて表示**できる（`F-2D-15` FR-1 と同じ思想——**数値ではなく、絵に重ねて確認させる**）。
- **FR-3** **表示・視点操作がモデルデータを変更しない**（`G5` / `F-2D-03` FR と同じ規律。**見ただけで保存内容が変わらない**）。
- **FR-4** 表示の補助（グリッド・寸法・スケール参照）は **UI 一時状態**であり、保存データに混ぜない（`F-CORE-01` 6 章）。

### 3.2 検品表示（重さと状態を知る — 継承）

- **FR-5** 次を**必ず表示**する（系譜: 上流 §5 の必須項目）: **ファイルサイズ・頂点数・三角形数・マテリアル数・テクスチャ枚数・テクスチャ最大サイズ・アニメーション数・bounds・原点 / 足元基準**。
- **FR-6** 各項目に **なぜそれを見るのか**（読み込み負荷 / 描画負荷 / メモリ / 管理のしやすさ）が伴う（**数値の意味が判らなければ、直せない**）。
- **FR-7** 問題は **理由つきの警告**として示す（例: サイズが大きすぎる、三角形数が多すぎる、テクスチャが大きすぎる、原点が足元にない、bounds の中心が大きくずれている、アニメーションが無い、マテリアルが多すぎる。系譜: 上流 §5.1）。
- **FR-8** **警告と拒否を区別**する。**警告は作業を止めない**（`F-CORE-06` / `F-2D-15` FR-8 と同じ）。

### 3.3 しきい値（固定しすぎない — 継承）

- **FR-9** しきい値は **対象環境ごとのプリセット**として持つ（少なくとも **モバイル / Web / デスクトップ**相当の 3 つ。系譜: 上流 §5.1「しきい値は最初から固定しすぎない」）。
- **FR-10** **どのプリセットで評価しているかを明示**する。**同じモデルが対象によって評価を変える**ことを隠さない。
- **FR-11** しきい値は **調整でき、調整したことが判る**（**厳しすぎて無視される基準は、基準として機能しない**）。
- **FR-11a** **同じしきい値・上限値を複数箇所に持たない**（系譜: 上流 `3d/3D_DECISION_LOG_AND_OPEN_ITEMS.md` `3D-RISK-03`「しきい値・上限値の多重定義」。**検品・書き出し前検査・持ち込み手順書が別々の値を見ていると、通ったのに動かないが起きる**。`F-2D-12` FR-4 の「同じ意味の設定を二重に持たない」と同じ規律）。
- **FR-11b** 文書に書かれた数値は **例・暫定**として扱い、**確定値の所在を一つに定める**（系譜: 同上）。

### 3.4 検品フレームとの関係

- **FR-12** 本機能の検品は **`F-CORE-06` の三段（構造 / 意味 / 出力 preflight）に対応づける**。**別系統の検証を作らない**（`F-2D-15` FR-6 と同じ）。
- **FR-13** 検品は **read-only** であり、**表示・計測がデータを変更しない**（系譜: ADR-0014。FR-3 と同じ規律）。
- **FR-14** 検品結果は **`F-3D-14`（inspection report）と `F-3D-15`（書き出し）の入力**になる。**同じ結果が、画面でも成果物でも一致**する。
- **FR-15** 計測は **決定的**である（同じモデルに同じ数値・同じ警告。`F-2D-15` FR-18 と同じ）。

### 3.5 実行とエディション境界

- **FR-16** 大きなモデルの表示・計測で **UI を固めない**（系譜: 上流 §12。`PF3` / `F-PLT-03`）。**進行を表示**する。
- **FR-17** **3D 描画基盤は 3D エディション / モジュールにのみ載る**（`P4` / `F-PLT-05`。系譜: 上流 §12 の「3D 関連は 2D の bundle size を不必要に増やさない・可能なら lazy load」——**本コンセプトでは工夫ではなく構造で満たす**）。
- **FR-18** 特定の GPU API を**必須にしない**（系譜: 上流 §14。`F-3D-01` FR-9 と同じ）。**描画できない環境では、理由を示して段階的に劣化させる**（表示できなくても検品数値は出せる）。

## 4. 非機能要件（NFR）

- **NFR-1（read-only）**: 見ても測ってもデータが変わらない（FR-3/FR-13。`G5`）。
- **NFR-2（説明可能性）**: 数値の意味と警告の理由が判る（FR-6/FR-7）。
- **NFR-3（文脈依存の正直さ）**: 対象によって基準が違うことを隠さない（FR-10）。
- **NFR-4（決定性）**: 同じモデルに同じ結果（FR-15）。
- **NFR-5（一致）**: 画面の結果と成果物の結果が食い違わない（FR-14）。
- **NFR-6（応答性）**: 大きなモデルで UI を固めない（FR-16）。
- **NFR-7（ゼロコスト）**: 3D を使わない利用者に負荷を掛けない（FR-17。`P4`）。
- **NFR-8（到達性）**: 描画できない環境でも、できる範囲を提供する（FR-18）。

## 5. データ・保存への影響

- **表示・計測は保存データを変更しない**（FR-3/FR-13）。
- **視点・表示補助は UI 一時状態**であり保存しない（FR-4）。
- **検品結果は記録し得る**（`F-3D-14` の report の素）。記録は **additive / 名前空間分離**とし、`D4` に従う。
- **しきい値プリセットは設定データ**であり、編集データと分ける（`adr/0007` の層分離）。

## 6. 依存機能

- **F-3D-01**（安全読み込み）: 表示・計測の対象を供給。
- **F-CORE-06**（検品フレーム）: 三段検証の正本。本機能はその 3D 具体化（FR-12）。
- **F-PLT-05**（レンダラのロード）: 3D 描画基盤のロード規則（FR-17）。
- **F-PLT-03**（offload）: 重い計測・再描画（FR-16）。
- **F-3D-04**（scene graph 検査）: 構造の詳細（本機能は概観、詳細はそちら）。
- **F-3D-05 / 06 / 07**（原点・アンカー・判定）: 本機能の面の上で行う整備。
- **F-3D-14 / 15**（report / 書き出し）: 検品結果の利用先（FR-14）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: モデルを **3D 表示**でき、視点操作ができる（FR-1）。
- **AC-2**: **bounds・原点・足元・向きがモデルに重ねて**確認できる（FR-2）。
- **AC-3**: **表示・視点操作・計測でデータが変わらない**（FR-3/FR-13/NFR-1）。
- **AC-4**: 必須項目（サイズ・頂点数・三角形数・マテリアル数・テクスチャ枚数と最大サイズ・アニメーション数・bounds・原点）が**すべて表示**される（FR-5）。
- **AC-5**: 各数値に **なぜ見るのか**が伴う（FR-6/NFR-2）。
- **AC-6**: 問題が**理由つきの警告**として示される（FR-7/NFR-2）。
- **AC-7**: **警告が作業を止めない**（FR-8）。
- **AC-8**: **対象環境プリセットで評価**でき、**どのプリセットかが明示**される（FR-9/FR-10/NFR-3）。
- **AC-9**: しきい値を**調整でき、調整したことが判る**（FR-11）。
- **AC-10**: 検品が **`F-CORE-06` の三段に対応づく**（FR-12）。
- **AC-11**: **画面の検品結果と成果物の report が一致**する（FR-14/NFR-5）。
- **AC-12**: 同じモデルに**同じ数値・同じ警告**（FR-15/NFR-4）。
- **AC-13**: 大きなモデルで **UI が固まらず、進行が見える**（FR-16/NFR-6）。
- **AC-14**: **3D を導入していない利用者の起動時間・常駐メモリ・配布サイズが増えない**（FR-17/NFR-7）。
- **AC-15**: 特定 GPU API が必須にならず、**描画できない環境でも検品数値は得られる**（FR-18/NFR-8）。

## 8. 非目標

- **3D モデリング / 編集機能**（本コンセプトの 3D は**整える**のであって、**作る**のではない。系譜: 上流 §1 / Vision 7 章の非目標）。
- しきい値の確定（FR-9 のとおり**プリセットの枠組みだけ**を固定）。
- scene graph / node / mesh / material の詳細検査（**F-3D-04**）。
- 軽量化そのもの（**F-3D-10** / **F-3D-11**）と前後比較（**F-3D-12**）。
- report の形式（**F-3D-14**）。
- 描画ライブラリの選定（`G1` の評価が先。候補名を採用として書かない）。
- ゲームエンジンの再現（`F-2D-15` 非目標と同じ。**確認できれば十分**）。
