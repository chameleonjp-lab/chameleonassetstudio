## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **T-DONE-5**: 骨格を**検査し**、「右手・頭」等の**対応付けができる**。
- **T-DONE-3**: 検品できる（骨格は検品項目の一つ）。

逆算の理由: 3D モデルの多くは**骨を持ち、その骨が動きの土台**になる。しかし骨の名前も並びも**作った環境ごとにばらばら**であり、そのままでは「どれが右手か」すら機械には判らない。本機能は **骨を読み、標準の呼び名へ結び付ける**。

結び付けができると、`F-3D-06`（アンカー）が **「右手に置く」** と言えるようになり、書き出し先での動きの流用も語れるようになる。**対応付けは、それ自体が目的ではなく、他の機能を賢くするための土台**である。

### ⚠️ 範囲について（`APP-O-04` 判断待ち）

本文書は **現行の `T-DONE-5` の範囲——検査と対応付けまで**——で書く。**骨組みの当てはめ・肌の自動追従・動きの付与は含まない**（それらは `F-3D-16`/`17`/`18` として**保留**）。

上流は 2026-07-20 の改訂で、**画像から作った 3D モデルは骨を持たないため、テンプレート骨格の当てはめと自動追従までツール内で完了する**方針へ変更した。本コンセプトが同じ範囲を採るかは **`APP-O-04` として人間判断待ち**であり、**判断が出るまで勝手に広げない**。

## 1. ユーザーストーリー

- 制作者として、**このモデルに骨が入っているか**を知りたい。
- 制作者として、**骨の構造が壊れていないか**を確かめたい。
- 制作者として、**どの骨が「右手」なのか**を決めたい。
- 制作者として、**名前から自動で当ててくれる**と助かる。ただし**勝手に確定されたくない**。
- 制作者として、**対応付けても元のモデルが変わらない**と確信したい。
- 制作者として、**書き出し先で骨の制約に引っかからないか**を先に知りたい。

## 2. 用語

- **骨格（skeleton）**: モデルを動かすための骨の集まり。
- **追従（skin weight）**: 各頂点がどの骨にどれだけ従うか。
- **人型スロット**: 「頭」「右手」など、標準的に決められた役割の名前。
- **対応付け**: モデル内部の要素を、人型スロットへ結び付けること。

## 3. 機能要件（FR）

### 3.1 検出（何があるか）

- **FR-1** **骨格の有無・骨の数・追従情報の有無**を表示する（系譜: 上流 §4.1 の B0。`F-3D-03` の検品項目「スケルトン有無」を具体化）。
- **FR-2** 表示は **`F-3D-03` / `F-3D-04` と同じ指標・同じ言い方**を使う（別の呼び方を作らない）。

### 3.2 検査（壊れていないか）

- **FR-3** **骨の階層を辿れる**（`F-3D-04` の構造表示の枠に載せる。別系統の画面を作らない）。
- **FR-4** **基準姿勢の整合**を検査する（系譜: 上流 §4.1 の B1）。
- **FR-5** **初期姿勢の種類を推定して示す**（系譜: 同上。**推定であることを明示**する）。
- **FR-6** **追従情報の異常を警告**する（合計が想定と合わない・**頂点あたりの影響数が上限を超える**など。系譜: 同上）。
- **FR-7** 警告は **`F-CORE-06` FR-7a〜7f の形**（対象・実測値と推奨値と前提・理由・その先で何が起きるか・直し方とこのアプリで直せるか・無視してよい条件・検査版）を持つ。

### 3.3 対応付け（継承の核心）

- **FR-8** **既存の標準語彙を採用し、独自の語彙を作らない**（系譜: 上流 §4.2。**独自語彙は、書き出し先での流用も、他ツールとの往復も、すべて難しくする**）。
- **FR-9** **名前からの自動推定を行える**。ただし **推定は「候補の提示」までとし、確定は必ず利用者の操作**とする（系譜: 同上の明示。`F-3D-06` FR-9 / `F-2D-15` FR-9 と同じ規律。**名前の当てずっぽうで骨の役割を決めない**）。
- **FR-10** **手作業で修正できる**（自動推定が外れる前提を持つ）。
- **FR-11** 対応付けは **内部要素を指す番号を正とし、名前は表示と再確認のために持つ**（系譜: 上流 §4.2。`F-3D-06` FR-12b と同じ規則——**宣言点を 1 か所に限る**）。
- **FR-12** **どのバイト列に対する番号か**を明示し、**照合できなければ「未解決」と示す**（系譜: `3D-RISK-02`。`F-3D-06` FR-12c と同じ。**黙って別の骨へ結び付けない**）。
- **FR-13** 対応付けの結果は **非破壊の付随情報**として保存する（`F-3D-13`。**モデル自体を書き換えない**。`G5`）。

### 3.4 対応付けを使う

- **FR-14** 対応付けができていれば、**`F-3D-06` のアンカー配置を補助**できる（「右手に置く」と言える。系譜: 上流 §4.1 の B3）。**補助であって、自動配置ではない**（`F-3D-06` FR-8 の自動生成禁止と両立させる）。
- **FR-15** **人型として必要な要素が欠けていないか**を検査できる（系譜: 同上）。
- **FR-16** **書き出し先での動きの流用に関する注意**を、取り込み手順へ反映できる（`F-3D-15` FR-8）。

### 3.5 書き出し先の制約（継承）

- **FR-17** 書き出し先ごとの骨の制約（**骨の数の上限・頂点あたりの影響数・命名の規則**）を検査できる。
- **FR-18** その制約値は、**検品・書き出し前検査・取り込み手順の三か所が同じ所在から参照**する（系譜: `3D-RISK-11`。`F-3D-15` FR-20 と同じ。**別々に書くと必ずずれ、書き出しは成功するのに対象側で壊れる**）。

### 3.6 実行

- **FR-19** 検査・推定は **決定的**である（同じ入力に同じ結果。`F-3D-04` FR-24）。
- **FR-20** 重い検査は **UI から逃がす**（`PF3` / `F-PLT-03`）。**秒単位の処理に例外を作らない**。
- **FR-21** 検査は **read-only**（`F-3D-04` FR-8 / ADR-0014）。

### 3.7 将来の付与との境界（`APP-O-04` 判断待ち）

- **FR-22** **骨組みの当てはめ・肌の自動追従・動きの付与は、本機能の範囲外**とする（`F-3D-16`/`17`/`18` として保留）。
- **FR-23** 将来それらを採る場合、**骨を足した派生はモデルの構成が元と変わる**ため、**対応付け・アンカー・判定を派生側の番号へ張り直す必要がある**（系譜: `3D-RISK-02` が「実装時の最頻出バグ想定箇所」と名指しした点）。**その張り直しは専用の検証を要する操作**とする（`F-3D-06` FR-12d）。
- **FR-24** 将来それらを採る場合、**基準（足元・前方向・単位）の確定を前提条件とする**（系譜: `3D-RISK-12`。`F-3D-05` FR-22 が既に定めた順序）。

## 4. 非機能要件（NFR）

- **NFR-1（標準に乗る）**: 独自語彙を作らない（FR-8）。
- **NFR-2（推測しない）**: 自動推定は候補まで、確定は利用者（FR-9）。
- **NFR-3（参照の確かさ）**: どのバイト列への番号かが曖昧にならない（FR-11/FR-12）。
- **NFR-4（非破壊）**: 対応付けでモデルが変わらない（FR-13。`G5`）。
- **NFR-5（単一の所在）**: 制約値を二重に持たない（FR-18）。
- **NFR-6（決定性）**: 同じ入力に同じ結果（FR-19）。
- **NFR-7（read-only）**: 検査がデータを書き換えない（FR-21）。

## 5. データ・保存への影響

- 対応付けは **additive な付随情報**として保存する（`F-3D-13` / `D3` / `D4`）。**未対応環境でも正本が成立する**。
- **モデルはバイト不変**（FR-13）。
- **どのバイト列に対する対応付けか**を保持する（FR-12）。
- 検査結果は **`F-3D-14` の記録**に載る。

## 6. 依存機能

- **F-3D-04**（構造検査）: 階層表示と検査の枠（FR-3/FR-7）。
- **F-3D-03**（検品表示）: 指標と対象環境プリセット（FR-2）。
- **F-3D-06**（アンカー）: 対応付けの利用先（FR-14）と参照規則の共有（FR-11/FR-12）。
- **F-3D-13**（metadata）: 保存先（FR-13）。
- **F-3D-14**（記録）: 検査結果の記録先。
- **F-3D-15**（書き出し）: 制約の所在共有と取り込み手順（FR-16/FR-18）。
- **F-CORE-06**（検品）: 警告の形（FR-7）。
- **F-PLT-03**（offload）: 重い検査（FR-20）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: **骨格の有無・骨の数・追従情報の有無**が、`F-3D-03` と同じ言い方で示される（FR-1/FR-2）。
- **AC-2**: **骨の階層が `F-3D-04` の枠の中で辿れる**（FR-3）。
- **AC-3**: **基準姿勢の整合**が検査される（FR-4）。
- **AC-4**: 初期姿勢の推定が、**推定であると明示**して示される（FR-5）。
- **AC-5**: **追従情報の異常（影響数の超過を含む）が警告**される（FR-6）。
- **AC-6**: 警告が **`F-CORE-06` FR-7a〜7f の形**を持つ（FR-7）。
- **AC-7**: **独自語彙が作られず、既存の標準語彙が使われる**（FR-8/NFR-1）。
- **AC-8**: **自動推定が候補提示に留まり、確定は利用者の操作**による（FR-9/NFR-2）。
- **AC-9**: **手作業で修正できる**（FR-10）。
- **AC-10**: 対応付けが**番号を正、名前を表示・再確認用**として持つ（FR-11/NFR-3）。
- **AC-11**: **照合できなければ「未解決」**と示され、黙って別の骨へ結び付かない（FR-12）。
- **AC-12**: 対応付け後も**モデルがバイト不変**（FR-13/NFR-4）。
- **AC-13**: 対応付けを使った**アンカー配置の補助**が働く。ただし**自動配置ではない**（FR-14）。
- **AC-14**: **人型として必要な要素の欠落**が検査される（FR-15）。
- **AC-15**: 書き出し先の骨の制約が検査され、**制約値が三か所で同じ所在**を参照する（FR-17/FR-18/NFR-5）。
- **AC-16**: 同じ入力に**同じ検査・同じ推定結果**（FR-19/NFR-6）。
- **AC-17**: 検査が **read-only** である（FR-21/NFR-7）。
- **AC-18**: **骨組みの当てはめ・自動追従・動きの付与が本機能に含まれない**（FR-22）。

## 8. 非目標

- **骨組みの当てはめ・肌の自動追従・動きの付与**（FR-22。`F-3D-16`/`17`/`18` として **`APP-O-04` 判断待ちで保留**）。
- **頂点単位の追従情報の編集**（系譜: 上流 §4.1 の対象外。**外部ツールの仕事**）。
- **骨の自由な追加・削除による骨格編集**（同上）。
- **揺れもの・物理の骨の作成**（同上）。
- **本格的なリグ制作の代替**（Vision 7 章の非目標）。
- スロットの網羅（既存の標準語彙に従う。**独自に決めない**）。
- 自動推定の精度の保証（FR-9 のとおり**候補提示に留める**）。
