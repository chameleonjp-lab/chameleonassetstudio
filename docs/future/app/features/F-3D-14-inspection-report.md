## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **T-DONE-7**: metadata と **inspection report** を付けられる。
- **T-DONE-3**: 検品できる（**その結果を残す側**）。

逆算の理由: `F-3D-03`（概観）と `F-3D-04`（詳細）は**画面で見せる**ことを担う。しかし **画面の結果は、閉じれば消える**。ゲームへ持ち込む相手・後日の自分・他の制作者に対して、**「このモデルはこの基準で、この時点で、こう判定された」を証拠として残す**のが本機能である。

`F-CORE-06` が検品の**枠**、`F-3D-03`/`F-3D-04` が **中身**、本機能が **記録**にあたる。

## 1. ユーザーストーリー

- 制作者として、**検品結果を成果物と一緒に渡したい**。
- 制作者として、**どのモデルに対する検品か**が確実に判るようにしたい。
- 制作者として、**いつ・どの基準で調べたか**を残したい。
- 制作者として、**軽量化の前後で結果がどう変わったか**を比べたい。
- 制作者として、**画面で見たものと記録が食い違わない**でほしい。

## 2. 用語

- **記録（report）**: 検査結果をまとめたもの。
- **対象の特定値**: どのバイト列に対する検査かを一意に示す値。
- **検査版**: どの検査規則で調べたか。

## 3. 機能要件（FR）

### 3.1 何を残すか（継承）

- **FR-1** **指摘の一覧**を持つ（`F-CORE-06` FR-7a〜7f の中身をそのまま持つ——対象 / 実測値と推奨値と前提 / 理由 / その先で何が起きるか / 直し方とこのアプリで直せるか / 無視してよい条件 / 検査規則の版）。
- **FR-2** **実測値と範囲**を持つ（`F-3D-03` の必須項目と**同じ指標**）。
- **FR-3** **要約**を持つ（拒否・警告・情報の件数。系譜: 上流 §5 の summary。**全部読まなくても状況が判る**）。
- **FR-4** **どのバイト列に対する検査か**を必ず紐づける（系譜: 上流 §5「`sourceSha256` により必ず紐づける」。**別のモデルの記録が付いたままにならない**）。
- **FR-5** **いつ・どの前提（対象環境プリセット）・どの検査版で**行ったかを持つ（系譜: 同上）。

### 3.2 記録の残し方（継承）

- **FR-6** 記録は **追記型**とする（**検査のたびに新しい記録**を作り、既存を書き換えない。系譜: 上流 §5）。
- **FR-7** **最新の 1 件は必ず持つ**。**履歴は容量を見て任意**とする（系譜: 同上。**履歴で保存を膨らませない**）。
- **FR-8** 記録の作成は **read-only の検査の結果**であり、**検査自体がデータを書き換えない**（`F-CORE-06` FR-3 / ADR-0014）。

### 3.3 派生との対応

- **FR-9** **派生（軽量化後など）に対しても同じ検査を行い、記録を作れる**（`F-3D-04` FR-22）。**別の物差しで比べない**。
- **FR-10** 派生の記録は、**どの親に対する派生か**を辿れる（`F-3D-10` FR-14b の連なりと整合）。
- **FR-11** **前後の比較（`F-3D-12`）の数値根拠**を供給する。

### 3.4 一致と出力

- **FR-12** **画面で見た結果と記録が一致**する（`F-3D-03` FR-14 / `F-3D-04` FR-23）。**別々に作らない**。
- **FR-13** 記録は **成果物へ同梱できる**（`F-CORE-07` FR-4 / `F-3D-15`）。
- **FR-14** 同梱する記録に、**秘密情報が紛れ込まない**（`F-CORE-06` FR-11 の preflight。**外へ出す前に確かめる**）。
- **FR-15** **未検査・未対応の範囲を記録にも明記**する（`F-CORE-06` FR-7。**「調べていない」を「問題なし」として渡さない**）。

## 4. 非機能要件（NFR）

- **NFR-1（対応の確かさ）**: どのバイト列への検査か曖昧にならない（FR-4）。
- **NFR-2（追跡可能性）**: いつ・どの前提・どの検査版かが判る（FR-5）。
- **NFR-3（読める要約）**: 全部読まなくても状況が判る（FR-3）。
- **NFR-4（不変性）**: 記録を書き換えず、追記で残す（FR-6）。
- **NFR-5（保存の節度）**: 履歴で保存を膨らませない（FR-7）。
- **NFR-6（一致）**: 画面と記録が食い違わない（FR-12）。
- **NFR-7（正直さ）**: 未検査を明記する（FR-15）。

## 5. データ・保存への影響

- **最新 1 件を保存に含める**。**履歴は任意**（FR-7）。additive / 名前空間分離（`D4`）。
- **記録は元モデルを変更しない**（FR-8。`G5`）。
- **成果物への同梱は `F-3D-15` の構成に従う**（FR-13）。
- 記録は **対象の特定値・検査版・前提とともに**保存する（FR-4/FR-5）。これが無い記録は**後から意味を失う**。

## 6. 依存機能

- **F-CORE-06**（検品フレーム）: 指摘の中身の作法（FR-1）と秘密情報 preflight（FR-14）。
- **F-3D-03 / 04**: 検査の実行元（FR-2/FR-12）。
- **F-3D-01**（安全読み込み）: 対象の特定値（FR-4）。
- **F-3D-10 / 11 / 12**: 派生の検査と比較（FR-9〜FR-11）。
- **F-3D-13**（metadata）: 同じ対象への紐づけ（FR-4）。
- **F-3D-15**（書き出し）: 同梱先（FR-13）。
- **F-CORE-05**（保存形式）: 記録の器（`D4`）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 記録が **`F-CORE-06` FR-7a〜7f と同じ中身の指摘**を持つ（FR-1）。
- **AC-2**: **実測値が `F-3D-03` と同じ指標**で残る（FR-2）。
- **AC-3**: **要約（件数）**で状況が判る（FR-3/NFR-3）。
- **AC-4**: **どのバイト列に対する検査か**が必ず紐づく（FR-4/NFR-1）。
- **AC-5**: **いつ・どの前提・どの検査版か**が残る（FR-5/NFR-2）。
- **AC-6**: 記録が**追記型**であり、既存が書き換えられない（FR-6/NFR-4）。
- **AC-7**: **最新 1 件は必ずあり、履歴は任意**（FR-7/NFR-5）。
- **AC-8**: 検査自体が**データを書き換えない**（FR-8）。
- **AC-9**: **派生にも同じ検査**を行い、記録できる（FR-9）。
- **AC-10**: 派生の記録から**親を辿れる**（FR-10）。
- **AC-11**: **前後比較の数値根拠**を供給する（FR-11）。
- **AC-12**: **画面の結果と記録が一致**する（FR-12/NFR-6）。
- **AC-13**: **成果物へ同梱**できる（FR-13）。
- **AC-14**: 同梱前に**秘密情報が確かめられる**（FR-14）。
- **AC-15**: **未検査・未対応の範囲が記録にも明記**される（FR-15/NFR-7）。

## 8. 非目標

- 検査の実行そのもの（**F-3D-03** / **F-3D-04**）。
- 検査項目の定義（同上）。
- 記録の形式・項目名の確定（実装時に判断）。
- 自動修正・自動再検査（**制作者が実行する**）。
- 2D の検品記録（`F-2D-15` / `F-CORE-06`。**段・重大度・提示の作法は共通、中身は別**）。
- 書き出し構成（**F-3D-15**）。
