## 0. 完成系での位置づけ（逆算リンク）

由来する完成系（`features/README.md` 2 章）:

- **D-DONE-7**: PNG / WebP / Sprite Sheet / Atlas / JSON / ZIP を、preset と import notes つきで**書き出せる**。
- **T-DONE-1**: GLB / glTF を **安全に読み込める**。
- **D-DONE-8 / T-DONE-9**: 保存し、開き直して再開でき、**元ファイルを絶対に上書きしない**。

逆算の理由: **F-CORE-01（FR-8 原子的保存）・F-CORE-05（FR-12 部分書き込みの検出）・F-MOD-02（FR-7 原子的切替）は、いずれも「原子的に書ける手段がある」ことを前提にしていた**。その手段の正本が本機能である。加えて、ブラウザ制約を外す動機のうち**利用者に最も分かりやすい部分**——OS のファイルダイアログ、ドラッグ&ドロップ、関連付け——の実体でもある（F-PLT-01 FR-2 の詳細）。

関係マップのノード: `A1 Shell 外殻`（実行主体）、`D1`/`D2`（保存の器の入出力）、`G5 非破壊`（元ファイル不可侵）、`PF3`（非同期実行）。

## 1. ユーザーストーリー

- 制作者として、**保存中に電源が落ちても、前の保存が無事**でいてほしい。
- 制作者として、**素材をドラッグ&ドロップで放り込みたい**。毎回ダイアログを辿りたくない。
- 制作者として、**プロジェクトファイルをダブルクリックで開きたい**。
- 制作者として、**取り込んだ元ファイルが書き換えられていない**と確信したい。
- 制作者として、書き出し先を**自分で選べて**、書き出したものが**すぐ使える**状態であってほしい。

## 2. 用語

- **原子的書き込み（atomic write）**: 「完全に書けた」か「まったく書けていない」かのどちらかにする書き込み。中途半端な状態を外から見せない。
- **部分書き込み**: 書き込み途中で中断され、内容が不完全なファイル。
- **退避（backup）**: 上書き前の内容を復元可能な形で残すこと（F-CORE-05 FR-6）。
- **利用者が選んだ範囲**: ダイアログや D&D で明示的に指定された対象（任意のファイルシステム走査ではない）。

## 3. 機能要件（FR）

### 3.1 原子的な保存

- **FR-1** プロジェクト保存を **原子的に行う**。中断（電源断・クラッシュ・強制終了）が起きても、**直前の保存済みファイルを壊さない**（F-CORE-01 FR-8 の実体）。
- **FR-2** **部分書き込みを検出できる**形にする（F-CORE-05 FR-11/FR-12）。壊れたファイルを「正常」として読み込まない。
- **FR-3** 上書き前の**退避を残せる**（F-CORE-05 FR-6 の移行時退避を含む）。
- **FR-4** 書き込みの完了を**確実にする**（バッファに残したまま「保存した」と報告しない）。
- **FR-5** 保存先が書けない場合（容量不足・権限不足・取り外し済みメディア等）、**理由を文章で示し、データを失わせない**（`S-DONE-4`）。

### 3.2 取り込みと元データ保護

- **FR-6** 取り込んだ**元ファイルを上書きしない**（`G5`。F-CORE-03 FR-2 の実行層での保証）。取り込みは**読み取りのみ**。
- **FR-7** **安全な読み込み**を行う（`T-DONE-1`）: 想定外の大きさ・壊れた内容・不正な構造を、**アプリを壊さずに拒否**できる。
- **FR-8** 読み込み対象は **利用者が選んだ範囲に限る**（勝手にディレクトリを走査しない。`A8` / F-CORE-10 の最小権限）。

### 3.3 OS 連携（利用者体験）

- **FR-9** **ネイティブなファイルダイアログ**（開く / 保存 / 書き出し先選択）を使う。
- **FR-10** **ドラッグ&ドロップ**で素材を取り込める。
- **FR-11** **プロジェクトファイルの関連付け**（ダブルクリックで開く）に対応する。
- **FR-12** **最近使った項目**を提供する（F-CORE-01 FR-5 / F-CORE-08 と接続）。
- **FR-13** 書き出し結果を **OS 上で確認しやすく**する（保存先を開く等）。

### 3.4 実行特性

- **FR-14** ファイル I/O は **UI を固めない**（F-PLT-03 に乗せる）。大きなファイルでも操作を止めない。
- **FR-15** 大きなファイルを**一度に全部メモリへ載せない**方法を持つ（必要に応じて分割・逐次処理）。
- **FR-16** ZIP 等のまとまった書き出しも、**途中失敗で不完全な成果物を残さない**（原子性を書き出しにも適用）。

## 4. 非機能要件（NFR）

- **NFR-1（データ非損失）**: いかなる中断でも、**直前の保存済みデータを失わない**（FR-1/FR-3）。
- **NFR-2（非破壊の絶対性）**: 元ファイルを書き換えない（FR-6。例外なし）。
- **NFR-3（安全性）**: 不正・破損・巨大な入力でアプリが壊れない（FR-7）。
- **NFR-4（最小権限）**: 利用者が選んだ範囲の外へ触れない（FR-8 / `A8`）。
- **NFR-5（応答性）**: 大きな I/O でも UI が固まらない（FR-14 / `PF3`）。
- **NFR-6（オフライン）**: すべてローカルで完結する。
- **NFR-7（明快さ）**: 失敗理由が利用者に伝わる言葉で示される（FR-5）。

## 5. データ・保存への影響

- 本機能は **`D1`（保存の器）の入出力の実行層**。器の**形式は F-CORE-05 が決め**、本機能は「それを安全に書き・読む」責務を持つ。
- **原子性の実現方式**（一時ファイル入れ替え / ジャーナル等）は**実装判断**であり、ここでは要件のみ定める（F-CORE-01 Open question と対）。
- 取り込んだ元ファイルは**参照または複製の保持**であり、**原本を書き換えない**（F-CORE-03 の Source 保持と対）。
- 一時ファイル・退避の置き場所と後始末を定める（残骸を放置しない）。

## 6. 依存機能

- **F-PLT-01**（外殻）: I/O とダイアログの実行主体。
- **F-PLT-03**（offload）: 非同期実行（FR-14）。
- **F-CORE-05**（保存形式）: 器の形式・検証・退避方針（FR-2/FR-3）。
- **F-CORE-01**（ライフサイクル）: 保存・開くの呼び出し元（FR-1）。
- **F-CORE-03**（非破壊）: 元データ保護の対象定義（FR-6）。
- **F-CORE-10**（権限）: アクセス範囲の制限（FR-8）。
- **F-CORE-07**（書き出しフレーム）: ZIP 等の成果物生成（FR-16）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 保存の**途中で強制終了**しても、直前の保存済みファイルが**壊れず開ける**（FR-1、F-CORE-01 AC-2 と対）。
- **AC-2**: **部分書き込みのファイルが検出**され、正常として読み込まれない（FR-2）。
- **AC-3**: 取り込んだ元ファイルが、いかなる操作後も **バイト一致**（FR-6、F-CORE-03 AC-6 と対）。
- **AC-4**: 壊れた／巨大な入力を与えても、**アプリが壊れず理由が示される**（FR-7/NFR-3）。
- **AC-5**: **D&D・ネイティブダイアログ・関連付け**で開ける（FR-9/FR-10/FR-11）。
- **AC-6**: 容量不足・権限不足で保存に失敗しても、**データを失わず理由が分かる**（FR-5）。
- **AC-7**: 大きなファイルの読み書き中も **UI が応答**する（FR-14）。
- **AC-8**: ZIP 書き出しが途中失敗しても、**不完全な成果物が残らない**（FR-16）。

## 8. 非目標

- 原子性の**実装方式の決定**（外殻方式 `PF5` 確定後の実装判断）。
- 保存の**器の形式**（F-CORE-05）。
- 書き出しの**中身**（preset / README / import notes は F-CORE-07 と各 export 機能）。
- クラウド保存・同期（本コンセプトの非目標）。
- 自動保存の方針（F-CORE-02）。
