## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **D-DONE-6**: **出す前に、使える素材かどうかを確かめられる**。
- **D-DONE-7**: 対象で**そのまま使える形**で書き出せる（その前提となる確認）。

逆算の理由: 制作の失敗は、**書き出したあと、エンジンへ入れた瞬間に判る**ことが多い。原点がずれている、判定が抜けている、命名が規約に合わない、tile が割り切れない——**気づくのが遅いほど、直す手戻りが大きい**。

したがって本機能の役割は、**エンジンへ入れる前に、エンジンで起きることを先に見せる**ことである。継承する上流の枠組みも同じ立場を取る——**「ゲームエンジンを作らない。ただし書き出す前に、素材がゲームでどう見えるかを確認できる必要がある」**（系譜: `2D_COMPLETE_PRODUCT_SPEC.md` §5.5）。

## 1. ユーザーストーリー

- 制作者として、**書き出す前に、ゲームでどう見えるか**を確かめたい。
- 制作者として、**接地・原点・判定が正しいか**を、絵に重ねて見たい。
- 制作者として、**タイルの継ぎ目やループ**が破綻していないか見たい。
- 制作者として、**何が問題で、なぜ問題なのか**を知りたい（「エラー」だけでは直せない）。
- 制作者として、**直し方の提案が、勝手に適用されない**でほしい。
- 制作者として、**この対象向けとして完成しているか**を判定してほしい。

## 2. 用語

- **検品**: 出力前に、素材が使える状態かを確かめること。
- **アセット契約（Asset Contract）**: 「この対象向けのこの素材」として満たすべき条件の集合（系譜: `2D_COMPLETE_PRODUCT_SPEC.md` §6）。
- **適合チェック**: 特定の対象・素材種別に対して、契約を満たすか確かめること。

## 3. 機能要件（FR）

### 3.1 見て確かめる（プレビュー）

- **FR-1** **原点・アンカー・当たり判定を絵に重ねて**確認できる（`F-2D-09` / `F-2D-10` の情報を可視化する。系譜: 上流 §5.5）。
- **FR-2** **アニメーションを再生**しながら確認できる（接地の安定、判定の追従。`F-2D-07`）。
- **FR-3** **タイルのつながり・継ぎ目・ループ**を確認できる（`F-2D-11` の tile 設定と接続）。
- **FR-4** 確認は **read-only** であり、**表示のためにデータを変更しない**（`G5` / `F-CORE-06`。系譜: ADR-0014 の「検証は read-only」）。

### 3.2 検査（理由つきで指摘する）

- **FR-5** 素材の状態を**理由つきで検査**する（画像サイズ、透明な縁、命名、フレーム、判定、アンカー、tileSize、atlas の余白など。系譜: 上流 §5.5）。**「不正」とだけ言わない**。
- **FR-6** 検査結果は **`F-CORE-06` の三段（構造 / 意味 / 出力 preflight）に対応づける**（本機能は**その 2D 具体化**であり、別系統の検証を作らない）。
- **FR-7** 各指摘に **どこが・なぜ・どうすれば**が伴う（`F-CORE-06` と同じ規律）。
- **FR-8** **警告と拒否を区別**する。**警告は進行を止めない**が、**出力を壊す条件は止める**（`F-CORE-06` / `F-CORE-07`）。

### 3.3 修正案（自動で確定しない — 継承）

- **FR-9** 修正案を提示できる。ただし **自動確定しない**（系譜: 上流 §5.5 の明示。**「直しておきました」をしない**）。
- **FR-10** 修正は **プレビューできる**（適用前に結果が見える）。
- **FR-11** 修正の適用は **取り消せる**（`F-CORE-04` の履歴に乗る）。
- **FR-12** 複数の修正をまとめて当てる場合、**`F-2D-14` の一括規律**（実行前分類・既定除外・全件原子的）に従う。

### 3.4 対象への適合（アセット契約）

- **FR-13** **対象と素材種別を選んで、適合を判定**できる（例: 「この対象向けの敵キャラクター」）。
- **FR-14** 適合の判定は **契約として明示された条件の集合**に基づく（見た目・原点・動き・判定・余白・名前・出力構成）。**条件が揃うまで完成扱いにしない**（系譜: 上流 §6）。
- **FR-15** **どの条件を満たし、どれを満たしていないか**を一覧できる（**残りが見えないと、終われない**）。
- **FR-16** 適合の記録は **`F-2D-16` の互換性ラベルの根拠**になる。**記録の無いものを `verified` として扱わない**（系譜: `2D_EXPORT_COMPATIBILITY_MATRIX.md` 3 章）。
- **FR-17** 適合していない対象向けの出力を、**「対応済み」と表示しない**（系譜: 同上 1 章「『対応』という言葉を曖昧にしない」）。

### 3.5 実行

- **FR-18** 検査は **決定的**である（同じ入力に同じ指摘）。
- **FR-19** 重い検査・プレビュー再生は **UI から逃がす**（`PF3` / `F-PLT-03`）。
- **FR-20** 検査対象・進行状況・打ち切り条件を示す（大量アセットで**終わらない検査にしない**）。

## 4. 非機能要件（NFR）

- **NFR-1（read-only）**: 確認も検査もデータを変更しない（FR-4。`G5`）。
- **NFR-2（説明可能性）**: どこが・なぜ・どうすれば、が伴う（FR-5/FR-7）。
- **NFR-3（自動確定しない）**: 修正案を勝手に当てない（FR-9/NFR-1 と対）。
- **NFR-4（決定性）**: 同じ入力に同じ結果（FR-18）。
- **NFR-5（正直さ）**: 満たしていない条件を隠さない（FR-15/FR-17）。
- **NFR-6（応答性）**: 検査で UI を固めない（FR-19）。

## 5. データ・保存への影響

- **検査自体は保存データを変更しない**（FR-4）。
- **適合の判定結果は記録し得る**（`F-2D-16` の `verified` 根拠。FR-16）。記録は **additive / 名前空間分離**とし、`D4` に従う。
- **記録は対象・対象バージョンに紐づく**（系譜: 互換性マトリクスの「`verified` は永続的な宣伝文句ではない」）。**古い記録を現在の保証として使わない**。
- 修正の適用は **`F-CORE-04` の履歴**に乗る（FR-11）。

## 6. 依存機能

- **F-CORE-06**（検品フレーム）: 三段検証の正本。本機能はその 2D 具体化（FR-6）。
- **F-2D-09 / F-2D-10**（原点・アンカー / 判定）: 可視化と検査の対象（FR-1）。
- **F-2D-07**（フレーム）: 再生確認（FR-2）。
- **F-2D-11 / F-2D-12**（tile / atlas）: 継ぎ目・余白の確認（FR-3/FR-5）。
- **F-2D-03**（Canvas）: 重ね表示の面（FR-1）。
- **F-2D-14**（バッチ）: 複数修正の一括（FR-12）。
- **F-CORE-04**（履歴）: 修正の取り消し（FR-11）。
- **F-2D-16**（書き出し preset）: 適合記録の利用先（FR-16）。
- **F-PLT-03**（offload）: 重い検査（FR-19）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 原点・アンカー・判定を**絵に重ねて確認**できる（FR-1）。
- **AC-2**: アニメーションを**再生しながら**確認できる（FR-2）。
- **AC-3**: 確認・検査で**データが変更されない**（FR-4/NFR-1）。
- **AC-4**: 指摘に**どこが・なぜ・どうすれば**が伴う（FR-7/NFR-2）。
- **AC-5**: **警告と拒否が区別**され、警告は進行を止めない（FR-8）。
- **AC-6**: 修正案が**自動確定されない**（FR-9/NFR-3）。
- **AC-7**: 修正を**適用前にプレビュー**でき、**取り消せる**（FR-10/FR-11）。
- **AC-8**: 複数修正の一括が **`F-2D-14` の規律**（実行前分類・全件原子的）に従う（FR-12）。
- **AC-9**: 対象・素材種別ごとに、**満たした条件と残りが一覧**できる（FR-13/FR-15/NFR-5）。
- **AC-10**: **記録の無いものが `verified` として扱われない**（FR-16）。
- **AC-11**: 適合していない出力が**「対応済み」と表示されない**（FR-17）。
- **AC-12**: 同じ入力に**同じ指摘**が出る（FR-18/NFR-4）。
- **AC-13**: 重い検査で **UI が固まらず**、進行と打ち切りが判る（FR-19/FR-20）。

## 8. 非目標

- **ゲームエンジンを作ること**（系譜: 上流 §5.5 の明示。**確認できれば十分**であり、実行環境の再現を目指さない）。
- 検査項目の網羅（対象と素材種別に応じて育てる。**枠組みだけを固定**する）。
- 自動での修正確定（FR-9）。
- 対象別 preset の中身と出力構成（**F-2D-16**）。
- 三段検証そのものの定義（**F-CORE-06**）。
- 性能プロファイリング（**F-PLT-04**）。
