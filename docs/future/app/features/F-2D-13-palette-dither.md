## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **D-DONE-2**: ラスタ／ベクタを**非破壊で編集・修正**できる（`F-2D-05` FR-12 が「色の制約はここ」と委ねた先）。
- **S-DONE-2**（モジュール）: **必要な機能だけを足せる**。

逆算の理由: `F-2D-05` は「描く」までを担い、**「使ってよい色を制約する」**は担っていない。ドット絵・レトロ調・エンジン側の色数制約では、**色の制約こそが制作手法そのもの**である。

そして本機能は、コンセプト全体にとって別の意味を持つ。**「モジュールとして足す機能」の最初の実例**であり、`P4`（未使用ゼロコスト）と `A4`（モジュール化）が**抽象論ではなく具体で試される場所**である。ここで原則が守れなければ、install-on-demand は成立しない。

## 1. ユーザーストーリー

- 制作者として、**使う色を決められた数に制限**して描きたい。
- 制作者として、**既存の絵から実際に使われている色を取り出し**たい。
- 制作者として、**色を置き換え**たいが、**置き換える対象を自分で決め**たい（勝手に全体へ広がると困る）。
- 制作者として、**限られた色数でも階調を出す**手段（ディザ）が欲しい。
- 制作者として、**この機能を使わないなら、アプリが重くならない**でほしい。
- 制作者として、**この機能を外しても、作ったデータが壊れない**でほしい。

## 2. 用語

- **パレット**: 使用を許す色の集合。
- **抽出**: 既存の画像から、実際に使われている色を集めること。
- **量子化 / 減色**: 色数をパレットへ落とし込むこと。
- **ディザ**: 少ない色数で中間調を表現するために、画素の配置で色を混ぜて見せる手法。

## 3. 機能要件（FR）

### 3.1 パレットの抽出（継承）

- **FR-1** 画像から**実際に使われている色を抽出**できる。抽出は **入力非破壊**である（系譜: 上流 §8。**元画像を読むだけ**）。
- **FR-2** 抽出は **決定的**である。**同じ入力・同じ設定なら常に同じパレット**になる（系譜: 上流の「RGB 量子化・代表平均色・画素数・coverage の決定的な算出」）。
- **FR-3** 抽出結果は **色そのものだけでなく、使われ方（画素数・占有率）も併せて示す**（系譜: 上流。**どれが主要色か**が判らないと選べない）。
- **FR-4** **透明の扱いを明示**する（しきい値でどこから不透明とみなすか。系譜: 上流の alpha しきい値）。
- **FR-5** 抽出の**上限（色数）を設ける**（無制限に走らせない。系譜: 上流の 1〜32 色）。上限に達した場合、**黙って切らずその旨を示す**。

### 3.2 色の置換（継承 — 暗黙拡大の禁止）

- **FR-6** 抽出した色を選んで**置換**できる。
- **FR-7** **置換の対象を明示**する（対象のレイヤー／パーツを利用者が指定する）。**暗黙に全レイヤー・全アセット・プロジェクト全体へ広げない**（系譜: `2D_2_VARIANT_BATCH_PLAN.md` の明示。**「便利だから広げる」が最も事故を生む**）。
- **FR-8** 近い色をまとめて置換する**許容度（tolerance）**を持てる（系譜: 上流）。**既定は狭く**し、広い置換は利用者の明示による。
- **FR-9** 置換は**実行前に結果を確認できる**（前後比較）。

### 3.3 パレットによる制約とディザ

- **FR-10** **パレットを制約として適用**できる（描画・貼り付けがパレット外の色を生まないようにする）。
- **FR-11** **ディザを適用**できる。ディザは **決定的**であり、**同じ入力・同じ設定なら同じ結果**になる（FR-2 と同じ規律。ドット絵では**再現できない結果は使えない**）。
- **FR-12** ディザは **派生**であり、**元の階調（Source）を消費しない**（`G5` / `F-CORE-03`）。**やり直せる**。
- **FR-13** **パレット外の色を黙って作らない**。制約下で表現できない色が生じる場合、**loss として示す**（`F-CORE-07` / `F-2D-07` と同じ規律）。

### 3.4 編集層と出力層の区別

- **FR-14** **編集時のパレット制約**と、**書き出し時の減色 / インデックスカラー化**を**混同しない**。前者は制作上の制約、後者は**出力層の操作**であり、**保存データの色を書き換えない**（`F-2D-12` FR-1 と同じ境界）。
- **FR-15** 書き出し側で減色する場合、**その結果と loss を示す**（`F-CORE-07` / `F-2D-16`）。

### 3.5 モジュールとしての作法（本機能の核心）

- **FR-16** **未導入なら、起動時間・常駐メモリ・配布サイズに 1 バイトも乗らない**（`P4`。本機能はこの原則の**最初の実証対象**）。
- **FR-17** **撤去してもプロジェクトデータを失わない**（`D3`。撤去後もアセットは開けて編集でき、書き出せる）。
- **FR-18** 本機能が付けるデータは **additive / 名前空間分離**であり、**未導入環境でも往復で壊れない**（`D4` / `F-CORE-05`）。**未導入環境で開いて保存しても、パレット情報が消えない**。
- **FR-19** 撤去後に**再導入したら、以前のパレット情報が再び使える**（往復。`F-MOD-02` FR と対）。
- **FR-20** 本機能が追加するツール・操作は、**Core と同じ非破壊・履歴の規律**に従う（`F-CORE-09` FR-11 / `F-2D-05` FR-12。**モジュールだからといって作法を緩めない**）。
- **FR-21** 必要な権限（能力）を**宣言し、宣言外のことをしない**（`F-CORE-10`）。

### 3.6 実行

- **FR-22** 抽出・量子化・ディザは**重い処理であり、UI から逃がす**（`PF3` / `F-PLT-03`）。**キャンセルで中途半端な結果を残さない**（系譜: 上流の Worker + 同期 fallback）。
- **FR-23** 一時的なパレット状態（選択中の色・作業中の候補）は **UI 一時状態**であり、**保存データに混ぜない**（系譜: 上流の「Asset / Layer / Texture に結び付いた一時 palette state」。`F-CORE-01` 6 章）。**保存する意図のあるパレットとは明確に分ける**。

## 4. 非機能要件（NFR）

- **NFR-1（決定性）**: 抽出もディザも、同じ入力が同じ結果になる（FR-2/FR-11）。
- **NFR-2（非破壊）**: 元画像・元の階調が残る（FR-1/FR-12。`G5`）。
- **NFR-3（限定性）**: 操作対象が明示され、勝手に広がらない（FR-7）。
- **NFR-4（ゼロコスト）**: 未導入時に一切の負荷を掛けない（FR-16。`P4`）。
- **NFR-5（可逆性）**: 撤去・再導入でデータが往復する（FR-17/FR-18/FR-19。`D3`）。
- **NFR-6（一貫性）**: モジュール提供機能も Core と同じ作法（FR-20）。
- **NFR-7（応答性）**: 重い処理で UI を固めない（FR-22）。

## 5. データ・保存への影響

- **パレットは保存し得る制作データ**（どの色で作ったかは制作の意図そのもの）。ただし **additive / 名前空間分離**とし、`D4` の境界に従う（FR-18）。
- **一時状態（選択中の色など）は保存しない**（FR-23）。
- **ディザ結果は派生**であり、元の階調と別に持つ（FR-12。`F-CORE-03`）。
- **書き出し時の減色は保存データを変えない**（FR-14）。

## 6. 依存機能

- **F-2D-05**（ラスタ編集）: 載る土台。委譲元（FR-20）。
- **F-2D-04**（レイヤー / パーツ）: 対象の明示単位（FR-7）。
- **F-CORE-03 / 04**: 非破壊・履歴（FR-12/FR-20）。
- **F-CORE-05**（保存形式）: additive / 名前空間（FR-18）。
- **F-CORE-09 / 10**（Host / 権限）: モジュールとしての登録と能力宣言（FR-20/FR-21）。
- **F-MOD-02**（導入 / 撤去）: ゼロコストと往復の実証相手（FR-16〜19）。
- **F-PLT-03**（offload）: 重い処理（FR-22）。
- **F-2D-14**（バッチ & バリアント）: 色置換を**一括対象の代表操作**として使う。
- **F-CORE-07 / F-2D-16**（書き出し）: 出力層の減色と loss（FR-14/FR-15）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 抽出が**入力非破壊**で、**同じ入力に同じパレット**を返す（FR-1/FR-2/NFR-1）。
- **AC-2**: 抽出結果に**使われ方（画素数・占有率）が伴う**（FR-3）。
- **AC-3**: 上限に達したとき、**黙って切らずに示される**（FR-5）。
- **AC-4**: 置換の**対象が明示され、暗黙に全体へ広がらない**（FR-7/NFR-3）。
- **AC-5**: 置換を**実行前に前後比較で確認できる**（FR-9）。
- **AC-6**: ディザが**決定的**で、**元の階調が残る**（FR-11/FR-12/NFR-2）。
- **AC-7**: パレット外の色が**黙って作られず、loss が示される**（FR-13）。
- **AC-8**: **書き出し時の減色が保存データの色を変えない**（FR-14、`F-2D-12` AC-1 と同じ境界）。
- **AC-9**: **未導入時に起動時間・常駐メモリ・配布サイズが増えない**（FR-16/NFR-4、`F-PLT-04` の計測で確認）。
- **AC-10**: **撤去してもアセットが開けて編集でき、書き出せる**（FR-17/NFR-5）。
- **AC-11**: **未導入環境で開いて保存しても、パレット情報が消えない**（FR-18、`D3` の往復）。
- **AC-12**: **再導入で以前のパレット情報が再び使える**（FR-19）。
- **AC-13**: 追加ツールが **Core と同じ非破壊・履歴の規律**に従う（FR-20、`F-2D-05` AC-8 と対）。
- **AC-14**: 一時状態が**保存データに混ざらない**（FR-23）。
- **AC-15**: 重い処理を**キャンセルしても中途半端な結果が残らない**（FR-22、`F-PLT-03` AC-3 と対）。

## 8. 非目標

- 量子化アルゴリズム・ディザ方式の確定（実装時に判断。**決定性という要件だけを固定**する）。
- 色管理（カラープロファイル・広色域）の本格対応。必要なら別判断。
- 自動での色調補正・「いい感じ」の自動生成（`G2` の AI 境界。**推測で色を変えない**）。
- 一括適用の仕組み（**F-2D-14**）。
- 書き出し形式ごとのインデックスカラー対応の詳細（**F-2D-16**）。
- ラスタ編集ツールそのもの（**F-2D-05**）。
