## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **T-DONE-2**: よくある他形式も**取り込める**。
- **T-DONE-1**: 安全に読み込める（**その規律を、増やした形式にも等しく効かせる**）。

逆算の理由: `F-3D-01` は**一つの形式**に対する安全規律を定めた。本機能は **「形式を増やす」という行為そのもの**を扱う。

ここで注意すべき上流の判断がある。上流は当初 OBJ を後続候補としていたが、**「材質・アニメーションの表現力が低く、中心形式へ集約する」**として対象外へ移し、再判断項目として残した（系譜: 上流 §1）。**本コンセプトの `T-DONE-2` は他形式の取り込みを含む**ため、この判断をそのまま制約として引き継ぐことはしない。しかし**判断の理由——表現力の差を抱えたまま「対応」と言うと、後で必ず破綻する——は継承する**。

したがって本機能の中身は **「どの形式に対応するか」ではなく「形式を増やしてよい条件と、増やしたときに守ること」** である。

## 1. ユーザーストーリー

- 制作者として、**手元にある形式が読めるか**を知りたい。
- 制作者として、**読めるとして、何が失われるか**を先に知りたい。
- 制作者として、**「対応」と書いてあるのに実際は使えない**、を避けたい。
- 制作者として、**形式が増えても、安全性が下がらない**と確信したい。
- 制作者として、**付随ファイルを伴う形式**も扱いたい。

## 2. 用語

- **中心形式**: アプリ内部で基準として扱う形式。
- **束（bundle）**: 本体と付随ファイルの組。
- **集約**: 取り込み時に中心形式の表現へ寄せること。

## 3. 機能要件（FR）

### 3.1 入口を一つに保つ

- **FR-1** 形式が増えても、**`F-3D-01` の安全規律をすべての形式に等しく適用**する（preflight・参照範囲の限定・全件成功でのみ確定・原本 verbatim 保持・失敗理由の表示・中断で何も残さない）。**形式ごとに別の入口を作らない**。
- **FR-2** 形式ごとの扱いを **「どう扱われるか」で表示**する（`F-2D-02` FR-2 / ADR-0016 と同じ）。**形式名だけで「対応」と表現しない**。
- **FR-3** 対象外の形式は **理由と代替手順を示して明示的に断る**（`F-2D-02` / `F-3D-01` FR-3 と同じ）。

### 3.2 表現力の差を隠さない（継承の核心）

- **FR-4** 形式によって **持てない情報がある**（材質の表現・アニメーション・階層・付随情報など）。**その差を取り込み前に示す**。
- **FR-5** 中心形式の表現へ**集約する場合、集約で失われるものを loss として示し、確定前に確認を求める**（`F-2D-02` FR-17 / `F-2D-11` FR-10 と同じ規律）。
- **FR-6** **表現力の差を抱えたまま「対応」と言わない**（系譜: 上流 §1 が OBJ を集約対象とした判断の理由。**読めることと、使えることは違う**）。
- **FR-7** 形式固有の構造を**保ったまま編集できる**のか、**画素・幾何として取り込むだけ**なのかを**区別して示す**（`F-2D-06` FR-11/FR-12 の SVG と同じ構図）。

### 3.3 形式を増やす条件（ゲート）

- **FR-8** 新しい形式を扱う前に、少なくとも次を確かめる:
  1. **安全な検証を設計できるか**（先頭の判定・上限・参照範囲・失敗時の扱い）。
  2. **表現力の差を説明できるか**（何が失われ、何が保たれるか。FR-4）。
  3. **解析に外部の部品が要る場合、ライセンス検証を通せるか**（`G1` / `F-MOD-04`）。
  4. **対象環境で現実的に動くか**（重い形式を「一応読める」で抱え込まない。系譜: 上流 §1 が FBX / Blender file を対象外にした理由）。
  5. **検品（`F-3D-03`/`F-3D-04`）と書き出し（`F-3D-15`）が成立するか**（**入口だけ作って出口が無い形式を増やさない**）。
- **FR-9** 条件を満たさないうちは、**「対応」と表示しない**（`F-3D-15` FR-16 の区分規律を、**入口側にも適用**する）。
- **FR-10** 形式の追加は **モジュールとして足せる**（`A4`）。ただし **同じ安全規律・同じ表示規律に従う**（`F-2D-13` FR-20 / `F-3D-15` FR-29 と同じ）。

### 3.4 束（付随ファイルを伴う形式）の受け取り（継承）

- **FR-11** 束は **複数ファイルの選択**と **書庫（アーカイブ）**の 2 通りで受け取れる（系譜: 上流 §2）。
- **FR-12** **フォルダのドラッグ&ドロップは補助**であり、**必須経路にしない**（系譜: 同上。**一部の端末で使えないため、それしか道が無い状態を作らない**。`F-UX-04` と接続）。
- **FR-13** 本体が参照する位置は、**同時に渡されたファイルの集合の中でだけ解決**する（系譜: 同上 / `F-3D-01` FR-5）。
- **FR-14** **外部の所在（ネットワーク）は解決しない**。検出したら**警告を出し、その部分を欠落として扱って続行**する（系譜: 上流 §3.4。**自動取得を既定にしない**）。
- **FR-15** 埋め込み形式の参照は許可し、**上限の計算に含める**（系譜: 同上）。
- **FR-16** **上位を辿る表記・先頭の区切り・別表記による回避を拒否**する（系譜: 同上。`F-3D-01` FR-5 / `F-3D-15` FR-22 と同じ）。
- **FR-17** 書庫は **展開後の合計サイズと項目数の上限**を持つ（系譜: 同上。**膨張攻撃への備え**）。

### 3.5 上限と拒否の分け方（継承 — 重要）

- **FR-18** **拒否するのは、資源の枯渇に直結するものに限る**。それ以外は **警告を出したうえで表示を試みる**（系譜: 上流 §3.3 の既定。**判らないものを全部拒否すると、実際の素材が入らなくなる**）。
- **FR-19** **上限値は暫定として扱い、実測で確定する**（系譜: 同上「確定は Gate 後実測」。`F-PLT-04` と接続）。**確定値の所在は一つ**にする（`F-3D-03` FR-11a）。
- **FR-20** **未知の塊を捨てない**。保持したうえで**警告する**（系譜: 上流 §3.2 の未知 chunk の扱い。`D3` の未知データ非破壊と同じ思想）。
- **FR-21** **宣言された種別や拡張子を主根拠にしない**（系譜: 上流 §3.1「信用しない」。**中身で判断する**）。

### 3.6 失敗の扱い（継承）

- **FR-22** 失敗は **理由と対象を添えて示す**（どの部分・どの参照か。系譜: 上流 §3.5）。
- **FR-23** **隔離は件数と容量の上限**を持つ（系譜: 同上。大きすぎるものは実体を持たない）。**隔離の対象は「読めない実体」に限る**（`F-3D-01` FR-7）。
- **FR-24** **中断は常に可能**とし、**途中生成物を残さない**（系譜: 同上。`F-3D-01` FR-17）。

## 4. 非機能要件（NFR）

- **NFR-1（規律の一様さ）**: 形式が増えても安全性が下がらない（FR-1）。
- **NFR-2（正直さ）**: 何が失われるかを先に示す（FR-4/FR-5）。
- **NFR-3（言葉の厳密さ）**: 読めることと使えることを混同させない（FR-6/FR-9）。
- **NFR-4（出口まで見る）**: 入口だけ作らない（FR-8-5）。
- **NFR-5（到達性）**: 特定の操作方法に依存しない（FR-12）。
- **NFR-6（現実的な厳しさ）**: 拒否を資源枯渇に限り、判らないものを一律に締め出さない（FR-18/FR-20）。
- **NFR-7（原子性）**: 失敗・中断で何も残さない（FR-24）。

## 5. データ・保存への影響

- **原本は verbatim 保持**（`F-3D-01` FR-10）。集約した結果は**派生**（`F-CORE-03`）。
- **保持しないものは loss として示す**（FR-5。`F-3D-01` FR-11）。
- 形式ごとの扱い（集約したか、構造を保ったか）を**記録し得る**。additive / 名前空間分離（`D4`）。
- **未知の塊は保持**する（FR-20。`D3`）。

## 6. 依存機能

- **F-3D-01**（安全読み込み）: 規律の供給元。本機能はそれを**広げる**（FR-1）。
- **F-CORE-06**（検品）: 構造検証・理由付き拒否・loss 提示（FR-5/FR-22）。
- **F-PLT-02**（ファイル I/O）: 束の受け取りと権限境界（FR-11/FR-13）。
- **F-MOD-04**（ライセンス検証）: 解析部品の門（FR-8-3）。
- **F-3D-03 / 04**（検品）・**F-3D-15**（書き出し）: 形式追加の成立条件（FR-8-5）。
- **F-PLT-04**（計測）: 上限値の実測（FR-19）。
- **F-UX-04**（端末対応方針）: 受け取り経路の到達性（FR-12）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 形式が増えても **`F-3D-01` の規律が等しく適用**される（FR-1/NFR-1）。
- **AC-2**: 形式ごとの扱いが**「どう扱われるか」で表示**される（FR-2）。
- **AC-3**: 対象外が**理由と代替手順つきで断られる**（FR-3）。
- **AC-4**: **何が失われるかが取り込み前に示される**（FR-4/NFR-2）。
- **AC-5**: 集約の loss が**確定前に開示され、確認なしに進まない**（FR-5）。
- **AC-6**: **構造を保つのか、幾何として取り込むだけか**が区別される（FR-7）。
- **AC-7**: 形式追加が **5 つの条件を満たすまで「対応」と表示されない**（FR-8/FR-9/NFR-3/NFR-4）。
- **AC-8**: モジュール提供の形式も**同じ規律**に従う（FR-10）。
- **AC-9**: 束を**複数ファイル選択と書庫の両方**で受け取れる（FR-11）。
- **AC-10**: **フォルダ操作が必須経路になっていない**（FR-12/NFR-5）。
- **AC-11**: 参照が**同時に渡された集合の中でだけ解決**される（FR-13）。
- **AC-12**: **外部の所在が解決されず、警告のうえ欠落として続行**される（FR-14）。
- **AC-13**: **上位を辿る表記等が拒否**される（FR-16）。
- **AC-14**: 書庫の**展開後サイズと項目数の上限**が働く（FR-17）。
- **AC-15**: **拒否が資源枯渇に直結するものに限られ**、それ以外は警告のうえ試行される（FR-18/NFR-6）。
- **AC-16**: **上限値が暫定として扱われ、確定値の所在が一つ**である（FR-19）。
- **AC-17**: **未知の塊が捨てられず、警告される**（FR-20）。
- **AC-18**: **拡張子や宣言種別が主根拠にされない**（FR-21）。
- **AC-19**: 失敗が**理由と対象つきで示される**（FR-22）。
- **AC-20**: **隔離に件数・容量の上限**があり、対象が「読めない実体」に限られる（FR-23）。
- **AC-21**: **中断で途中生成物が残らない**（FR-24/NFR-7）。

## 8. 非目標

- **対応形式の確定**（本文書は**増やす条件**を定めるものであり、どの形式を採るかは別判断）。
- 重い専用形式・専用プロジェクト形式の取り込み（FR-8-4。系譜: 上流が FBX / Blender file を対象外とした理由）。
- 専用形式の**完全な読み書き・ランタイム互換**を名乗ること（`F-3D-15` FR-19 と同じ）。
- 書き出した一式を**通常の取り込み経路の入力形式にする**こと（系譜: 上流 §1 の明示。**往復の確認はテストで行うものであり、利用者向けの経路ではない**。`F-2D-11` FR-8 の「配布物を元へ戻す操作ではない」と同じ思想）。
- 外部からの自動取得（FR-14）。
- 解析部品の選定（`G1` の評価が先。**候補名を採用として書かない**）。
