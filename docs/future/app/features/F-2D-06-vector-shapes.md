## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **D-DONE-1**: **図形**から 2D アセットを新規作成できる（`F-2D-01` FR-1 が委ねた起点の実体）。
- **D-DONE-2**: ラスタ／**ベクタ**を非破壊で編集・修正できる。

逆算の理由: `F-2D-01` が「図形の実体は F-2D-06」と委ねた部分であり、**UI / icon / gimmick などの制作で中心になる**手段。ラスタと違い、**解像度に依らず作り直せる**のが本質的な価値である。

## 1. ユーザーストーリー

- 制作者として、**四角・丸・線・多角形**を組み合わせてアイコンを作りたい。
- 制作者として、**あとからサイズを変えても、ぼやけない**でほしい。
- 制作者として、**書き出すときは普通の画像**として使えてほしい。
- 制作者として、図形を**あとから編集し直せる**と嬉しい（一度描いたら終わりは困る）。

## 2. 用語

- **図形（shape）**: 矩形・円・線・多角形・パスなど、**数値で定義された形**。
- **ラスタ化（rasterize）**: 図形を画素に変換すること。
- **解像度非依存**: 拡大縮小しても定義が劣化しないこと。

## 3. 機能要件（FR）

### 3.1 図形の作成と編集

- **FR-1** 基本図形（**矩形・円 / 楕円・線・多角形・パス**）を作成できる。
- **FR-2** 図形の**塗り・線・角の丸み**等の見た目を設定できる。
- **FR-3** 図形は**あとから編集できる**（頂点・サイズ・見た目）。**一度描いたら数値情報が失われる状態にしない**。
- **FR-4** 図形を**組み合わせ・整列**できる（複数選択・グループ）。`F-2D-04` の構造と整合させる。

### 3.2 解像度非依存と非破壊

- **FR-5** 図形は **数値定義として保持**する。**拡大縮小で定義が劣化しない**。
- **FR-6** **ラスタ化は派生**であり、**図形定義を消費しない**（`G5` / F-CORE-03）。ラスタ化後も**図形として編集を続けられる**。
- **FR-7** **図形をラスタ層へ確定（焼き込み）することもできる**が、その場合も **`F-2D-08` の bake と同じ規律**——**元の定義を残し、再確定できる**——に従う。

### 3.3 座標と出力の境界（継承）

- **FR-8** 図形の座標は **共通アセット座標**で保持する（ADR-0001 / `F-2D-03` FR-6）。
- **FR-9** **書き出し時の解像度倍率・trim 等は出力層の操作**であり、**図形定義や保存座標を変更しない**（系譜: ADR-0004 の思想）。
- **FR-10** 書き出しでラスタ化する場合、**その解像度で意図どおりになる**こと（`F-2D-16` / F-CORE-07 と接続）。**loss があるなら示す**（F-CORE-07 / F-2D-07 と同じ規律）。

### 3.4 取り込みとの関係

- **FR-11** **外部ベクタ形式（SVG 等）の取り込みは、既定では画素として取り込む**（`F-2D-02` FR-1 の分類）。**ベクタ構造を保持したまま編集できる取り込み（editable-import）は、別途の判断**とする（系譜: ADR-0016 が別 ADR としたのと同じ扱い）。
- **FR-12** 上記の**違いを利用者に明示**する（「取り込んだ SVG は画素になる」vs「アプリ内で作った図形は編集できる」を混同させない）。

### 3.5 編集の土台

- **FR-13** 図形操作は **Core の履歴に乗り**（F-CORE-04）、**非破壊**である（F-CORE-03）。
- **FR-14** 選択・ハンドル操作は **`F-2D-03` の共通基盤**に乗る（操作感の一貫性）。

## 4. 非機能要件（NFR）

- **NFR-1（解像度非依存）**: 定義が拡大縮小で劣化しない（FR-5）。
- **NFR-2（非破壊）**: ラスタ化・焼き込みで定義を失わない（FR-6/FR-7。`G5`）。
- **NFR-3（正確さ）**: 画面で置いた位置と保存座標が一致（FR-8）。
- **NFR-4（明快さ）**: 「編集できる図形」と「画素になった取り込み」の違いが分かる（FR-12）。
- **NFR-5（応答性）**: 図形数が増えても操作が重くならない。

## 5. データ・保存への影響

- 図形は **数値定義として保存**する（画素として保存しない）。**保存の器は F-CORE-05**。
- ラスタ化結果は**派生**であり、定義とは別に持つ（F-CORE-03）。
- **出力倍率・trim は保存値に影響しない**（FR-9。ADR-0004 の境界）。

## 6. 依存機能

- **F-2D-01**（新規作成）: 「図形から作る」起点の呼び出し元。
- **F-2D-03**（Canvas）: 座標・操作面（FR-8/FR-14）。
- **F-2D-04**（レイヤー & パーツ）: 図形が属する層・グループ（FR-4）。
- **F-CORE-03 / 04**: 非破壊・履歴（FR-13）。
- **F-2D-05**（ラスタ編集）: 焼き込み先（FR-7）。
- **F-2D-16 / F-CORE-07**（書き出し）: ラスタ化の解像度と loss（FR-10）。
- **F-2D-02**（取り込み）: SVG 等の分類（FR-11）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 基本図形を作成・編集でき、**あとから頂点やサイズを変えられる**（FR-1/FR-3）。
- **AC-2**: 拡大縮小しても**定義が劣化しない**（FR-5/NFR-1）。
- **AC-3**: **ラスタ化しても図形定義が残り**、編集を続けられる（FR-6/NFR-2）。
- **AC-4**: 焼き込みでも**元の定義が残り、再確定できる**（FR-7、`F-2D-08` AC-2 と同じ規律）。
- **AC-5**: 書き出しの**倍率・trim が保存座標や図形定義を変えない**（FR-9）。
- **AC-6**: **取り込んだ SVG が画素になること**と、**アプリ内図形が編集できること**の違いが明示される（FR-11/FR-12）。
- **AC-7**: 図形操作が**履歴に乗り、Source を変更しない**（FR-13）。
- **AC-8**: 画面で置いた位置と**保存座標が一致**する（NFR-3）。

## 8. 非目標

- **本格的なドローツールの代替**（Illustrator 級）。Vision 7 章の非目標に準じる。
- **ベクタ保持での SVG 取り込み（editable-import）**（FR-11。別途の判断）。
- ベクタのまま書き出す形式（現時点では画素として出す前提。必要なら別判断）。
- 図形種別の網羅（実装時／モジュールで判断）。
- テキスト組版（必要なら別機能／モジュール）。
