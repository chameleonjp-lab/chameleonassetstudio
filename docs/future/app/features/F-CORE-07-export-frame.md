## 0. 完成系での位置づけ（逆算リンク）

由来する完成系（`features/README.md` 2 章）:

- **D-DONE-7**: PNG / WebP / Sprite Sheet / Atlas / JSON / ZIP を、**対象別 preset と import notes つき**で書き出せる。
- **T-DONE-8**: GLB + metadata + report + README + import notes の ZIP を、**対象別 preset つき**で書き出せる。
- **S-DONE-4**: 失敗・制限が文章で分かり、手動で必ず回復できる。

逆算の理由: 書き出しは **制作物が外の世界へ出る唯一の出口**である。ここで「何を、どうゲームへ入れればよいか」まで届かなければ、**それまでの全機能の価値が利用者に届かない**。

そして本コンセプトの差別化仮説 2（`APP_COMPETITIVE_LANDSCAPE.md` 4 章）は、まさにここに賭けている——**「作れる」ではなく「外部エンジンで確実に使える状態か」を保証する**。その保証を成立させる器が本機能である。

関係マップのノード: `A2 Core 契約`（export フレームは Core の一部）、`G3 差別化仮説`（確かさを価値にする）、`G5 非破壊`（書き出しは派生）、`A4 Feature Modules`（preset を足す側）。

## 1. ユーザーストーリー

- 制作者として、書き出した ZIP を開けば **何をどう使えばいいか分かる**でほしい。
- 制作者として、**対象エンジンごとに適した形**で出したい（毎回自分で変換したくない）。
- 制作者として、「対応」と書いてあるものが**本当に読み込める**と信じたい。
- 制作者として、書き出しが途中で失敗しても、**壊れた成果物を掴まされたくない**。
- 制作者として、**自分の作ったものの権利**が、使ったモジュールに侵食されないと確認したい。

## 2. 用語

- **成果物（Artifact）**: 書き出しで生成される一式（ファイル群 / ZIP）。
- **preset**: 対象（エンジン・用途）別の出力設定のまとまり。
- **import notes**: 「対象側でどう取り込むか」を書いた手順書。
- **互換性ラベル**: 対象への対応度合いの表明。**`generic` / `candidate` / `verified`**（系譜: 上流の互換性マトリクス 2 章）。
- **attribution**: 帰属表示（F-MOD-04 FR-9）。

## 3. 機能要件（FR）

### 3.1 器の構造

- **FR-1** 成果物は**一貫した構造**を持つ（どの対象・どのエディションでも、置き場所の考え方が同じ）。
- **FR-2** 成果物に **README を同梱**する（何が入っているか・何をすればよいか）。
- **FR-3** 成果物に **import notes を同梱**する（対象側での取り込み手順）。
- **FR-4** 必要に応じて **metadata / inspection report を同梱**する（3D の `T-DONE-8`、2D の検品結果）。
- **FR-5** **attribution を同梱**できる（F-MOD-04 FR-9 の履行先）。
- **FR-6** **ZIP 等のまとまった形**と、**素のファイル群**の双方を出せる（対象に応じて選べる）。

### 3.2 互換性の正直さ（継承した規律）

- **FR-7** 対象ごとに **互換性ラベル**を持つ: `generic`（汎用出力）/ `candidate`（外部実行確認前）/ `verified`（確認済み）。
- **FR-8** **`verified` は記録に裏づけられる**。対象ツール名・対象バージョン・fixture・手順・期待結果の記録が無いものを `verified` と表示しない（系譜: 上流 3 章）。
- **FR-9** **`verified` は対象バージョンに紐づく**。対象ツールの新しい版で挙動が変わりうるため、**永続的な宣伝文句として扱わない**（系譜: 上流 3 章）。
- **FR-10** **未検証を「対応」と名乗らない**（`APP_PRODUCT_VISION.md` の非目標／上流の禁止事項を継承）。ラベルと**未対応範囲**を成果物と UI の双方で示す。

### 3.3 生成の性質

- **FR-11** 書き出しは **派生**であり、**Source と Document を変更しない**（`G5` / F-CORE-03。ADR-0004「出力は派生」の思想を継承）。
- **FR-12** **原子的に生成**する。途中失敗で**不完全な成果物を残さない**（F-PLT-02 FR-16）。
- **FR-13** **再現性**を持つ。同じプロジェクト・同じ preset・同じアプリ版なら、**同じ成果物**になる。
- **FR-14** 書き出しは重い処理になりうるため、**UI を固めず・進捗を示し・キャンセルできる**（F-PLT-03）。
- **FR-15** 失敗時は、**何が出せて何が出せなかったか**を文章で示す（`S-DONE-4`）。部分成功を「成功」と報告しない。

### 3.4 拡張との関係

- **FR-16** **モジュールは preset と import notes を足せる**。ただし**器の構造・README 同梱の原則を壊せない**（Arch 5 章「export は Core の器を通す」）。
- **FR-17** モジュール由来の preset も、**同じ互換性ラベルの規律**に従う（未検証を `verified` にしない）。

## 4. 非機能要件（NFR）

- **NFR-1（正直さ）**: 対応度合いを誇張しない（FR-7〜FR-10）。
- **NFR-2（非破壊）**: 書き出しが元データと編集内容を変えない（FR-11）。
- **NFR-3（完全性）**: 不完全な成果物を外へ出さない（FR-12）。
- **NFR-4（再現性）**: 同条件で同結果（FR-13）。
- **NFR-5（自己説明性）**: 成果物だけを見て、次に何をすればよいか分かる（FR-2/FR-3）。
- **NFR-6（応答性）**: 大きな書き出しでも UI を止めない（FR-14）。
- **NFR-7（オフライン）**: 書き出しはローカルで完結する。

## 5. データ・保存への影響

- 書き出し設定（選んだ preset・出力先）は、**プロジェクトに保存してよい情報**と**一時的な選択**を区別する（保存する場合も、UI 一時状態とは分ける。F-CORE-01 6 章）。
- 成果物は **プロジェクトの外**に出るものであり、**保存の器（F-CORE-05）の一部ではない**。
- **Source は成果物に必ずしも含めない**（再編集のためプロジェクト側に保持する。F-CORE-03 FR-10）。

## 6. 依存機能

- **F-CORE-03**（非破壊）: 書き出し対象は派生結果（FR-11）。
- **F-CORE-05**（保存形式）: プロジェクトからの入力元。
- **F-CORE-06**（検品）: inspection report の供給元（FR-4）。
- **F-PLT-02**（ファイル I/O）: 原子的な成果物生成（FR-12）。
- **F-PLT-03**（offload）: 非同期・進捗・キャンセル（FR-14）。
- **F-MOD-04**（ライセンス）: attribution の要否（FR-5）。
- **F-2D-16 / F-3D-15**（各 export preset）: 本器の利用者。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 成果物を開くと、**README と import notes があり、次にすべきことが分かる**（FR-2/FR-3/NFR-5）。
- **AC-2**: 対象ごとに**互換性ラベルが表示**され、**未対応範囲が明示**される（FR-7/FR-10）。
- **AC-3**: **記録の無い対象が `verified` と表示されない**（FR-8）。
- **AC-4**: 書き出し後も **Source と Document が不変**（FR-11、F-CORE-03 AC-1 と対）。
- **AC-5**: 書き出しを途中で中断・失敗させても、**不完全な成果物が残らない**（FR-12、F-PLT-02 AC-8 と対）。
- **AC-6**: 同じプロジェクト・同じ preset で **同じ成果物**が得られる（FR-13）。
- **AC-7**: 大きな書き出し中も **UI が応答し、進捗が出て、キャンセルできる**（FR-14）。
- **AC-8**: **モジュール由来の preset** も同じ器の構造と互換性ラベルの規律に従う（FR-16/FR-17）。
- **AC-9**: attribution が必要な場合、**成果物に同梱**できる（FR-5、F-MOD-04 AC-6 と対）。

## 8. 非目標

- **対応形式・対象エンジンの確定**（各 export 機能 `F-2D-16` / `F-3D-15` と、実際の検証）。
- preset の**中身**（対象ごとの具体的な出力設定）。
- 外部ツールとの**直接連携**（本コンセプトも「まずファイルで渡す」を継承。`APP_PRODUCT_VISION.md` 6 章）。
- 成果物の**配布・公開**（本コンセプトの非目標）。
- 検品ロジックそのもの（F-CORE-06）。
