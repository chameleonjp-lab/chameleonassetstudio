## 0. 完成系での位置づけ（逆算リンク）

由来する完成系（`features/README.md` 2 章）:

- **S-DONE-1**: Home / Project Dashboard から **2D・3D いずれのプロジェクトへも入れる**。
- **S-DONE-2**: **最小構成で軽く起動**する（＝入口はいちばん最初に「軽い」を証明する場所）。
- **S-DONE-3**: 2D と 3D が、別最適化されながら**同じ操作感**で行き来できる。
- **D-DONE-8**: 開き直して**再開**できる（`F-CORE-01` FR-5 / FR-12 の入口）。

逆算の理由: ここは **利用者が最初に触れる画面**であり、`P1`（非採用の法則）の複数項目が**同時に評価される場所**である——起動が速いか（重すぎないか）、迷わず始められるか（使い勝手）、見て分かるか（UI）、不安がないか（UX）。**最小構成の軽さが最初に露見する場所**でもある（`P4` / F-PLT-04 の冷間起動測定はここを含む）。

また `A3`（Edition Runtime）の**分岐点**でもある: ここでエディションが決まって初めて、F-PLT-05 が必要な一方のレンダラだけを載せる。

関係マップのノード: `P1 非採用の法則`（最初の評価点）、`P5 目的分離`（入口は共有・編集画面は分ける）、`A3 Edition Runtime`（分岐点）、`P4 ゼロコスト`。

## 1. ユーザーストーリー

- 制作者として、**起動したらすぐ、続きから再開**したい。
- 制作者として、**最近の作業がすぐ見つかる**と嬉しい。探し回りたくない。
- 制作者として、**2D と 3D のどちらも同じ入口**から入りたい（別アプリのように感じたくない）。
- 制作者として、**初めて起動したときに何をすればいいか**が分かるとありがたい。
- 制作者として、**まだ入れていない機能の宣伝で画面が散らかる**のは嫌だ。

## 2. 用語

- **Home / Dashboard**: プロジェクトの一覧・作成・再開を担う入口画面。
- **エディション**: プロジェクトの種別（2D / 3D）。保存データの属性（F-CORE-01 FR-1）。
- **最近使った項目**: 直近に開いたプロジェクトの一覧（F-PLT-02 FR-12 と接続）。

## 3. 機能要件（FR）

### 3.1 入口としての役割

- **FR-1** **プロジェクトの新規作成**へ入れる（エディション = 2D / 3D を選ぶ。F-CORE-01 FR-1）。
- **FR-2** **既存プロジェクトを開ける**（ファイル選択・最近使った項目の双方から。F-CORE-01 FR-4/FR-5）。
- **FR-3** **最近使った項目**を提示する（F-PLT-02 FR-12 と接続）。**存在しなくなった項目**（移動・削除済み）を、**そうと分かる形**で扱う（黙って消さない・黙ってエラーにしない）。
- **FR-4** **2D と 3D のプロジェクトを同じ一覧**で扱い、**エディションが一目で分かる**ようにする（`S-DONE-1` / `P5`）。
- **FR-5** **前回の続きから再開**しやすくする（F-CORE-01 FR-12。自動で開くかは設定。**既定は Dashboard 表示**）。
- **FR-6** **クラッシュ後の復旧候補**があれば、ここで提示する（F-CORE-02 の入口。F-CORE-01 FR-13）。

### 3.2 軽さと分岐

- **FR-7** Dashboard の表示に **Edition Runtime やレンダラを必要としない**。**どちらのレンダラも載せずに**一覧・作成・選択ができる（`P4` / F-PLT-05 FR-1）。
- **FR-8** プロジェクトの**エディションが決まった時点**で、**必要な一方だけ**をロードする（F-PLT-05 FR-1 の判定入力を供給）。
- **FR-9** 一覧表示のために**全プロジェクトを読み込まない**（軽量メタだけで一覧する。F-MOD-01 の Catalog と同じ考え方）。
- **FR-9a** 一覧は **軽い縮小画像で表す**。**選択したものだけ**、必要になった時点で編集面・プレビューを起動する（系譜: 上流 `EXTERNAL_GITHUB_REFERENCE_CATALOG.md` `IDEA-2D-08` / `IDEA-3D-08`、および `EXTERNAL_GITHUB_REFERENCE_REVIEW_2026-07-26.md` の「一覧で重い 3D viewer を全件起動しない」）。
- **FR-9b** **一覧の描画で、3D 描画基盤や重い復号器を初期化しない**（系譜: 同上 `IDEA-3D-08`「一覧で WebGL を初期化しない」。`P4` / FR-7 の具体化。**一覧が重いアプリは、開いた瞬間に見限られる**）。
- **FR-9c** 一覧に出す代表画像と、**編集・プレビューで扱う実体を同一物として扱わない**（系譜: 同上 `IDEA-3D-08`「card media と runtime model を同一物と誤記しない」。代表画像が最新でない場合がある、という前提を持つ）。

### 3.3 見せ方の規律

- **FR-10** **未インストール機能の宣伝で画面を散らかさない**（F-MOD-01 FR-6 と同じ規律）。モジュールの発見は文脈時とカタログ内に限る。
- **FR-11** **初回起動時に、最小限の道筋**を示す（`F-UX-05` オンボーディングと接続。押しつけない）。
- **FR-12** 2D と 3D で **UI の作法を揃える**（`S-DONE-3`）。入口は共有し、**編集画面は分ける**（系譜: 上流の画面方針／Vision 4.3）。

### 3.4 失敗の扱い

- **FR-13** 開けないプロジェクト（破損・新しすぎる版・権限不足）について、**理由を文章で示す**（`S-DONE-4`）。**一覧全体を壊さない**（1 件の問題で Dashboard が使えなくならない）。
- **FR-14** 移行が必要なプロジェクトは、**開く前にそれと分かる**（F-CORE-05 FR-4 の移行導線と接続）。

## 4. 非機能要件（NFR）

- **NFR-1（軽さの証明）**: Dashboard の表示が最小構成の起動予算内に収まる（`PF1` / F-PLT-04 の冷間起動測定対象）。
- **NFR-2（ゼロコスト）**: レンダラ・モジュール実体を読み込まずに機能する（FR-7/FR-9）。
- **NFR-3（応答性）**: プロジェクト数が増えても一覧が待たされない（重い読み取りは `PF3`）。
- **NFR-4（堅牢性）**: 1 件の破損が一覧全体を壊さない（FR-13）。
- **NFR-5（明快さ）**: 初見でも次にすべきことが分かる（FR-11）。
- **NFR-6（オフライン）**: すべてローカルで完結する。

## 5. データ・保存への影響

- **最近使った項目・Dashboard の表示設定はアプリ環境レベル**の情報であり、**プロジェクト保存の器（F-CORE-05）に含めない**。
- 一覧に必要な情報（名前・エディション・更新日時・サムネイル等）は**軽量メタ**として扱い、**プロジェクト全体を読み込まない**（FR-9）。メタの持ち方（器から読むか、別途索引を持つか）は実装判断。
- Dashboard は**プロジェクトを書き換えない**（開く前に内容を変更しない。`G5`）。

## 6. 依存機能

- **F-CORE-01**（ライフサイクル）: 作成・開く・再開の実体（FR-1/FR-2/FR-5）。
- **F-CORE-02**（自動保存・復旧）: 復旧候補の供給（FR-6）。
- **F-CORE-05**（保存形式）: エディション・版の判定、移行要否（FR-4/FR-14）。
- **F-PLT-02**（ファイル I/O）: ダイアログ・最近使った項目（FR-2/FR-3）。
- **F-PLT-05**（レンダラのロード）: エディション判定の受け手（FR-8）。
- **F-UX-01 / F-UX-05**（デザインシステム・オンボーディング）: 見せ方の土台（FR-11/FR-12）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 起動して Dashboard が表示された時点で、**どちらのレンダラも載っていない**（FR-7、F-PLT-05 AC-1 と対）。
- **AC-2**: 2D・3D 双方のプロジェクトが**同じ一覧**に並び、**エディションが判別できる**（FR-4）。
- **AC-3**: 最近使った項目から**再開**でき、**存在しない項目がそうと分かる**（FR-3/FR-5）。
- **AC-4**: プロジェクトを開くと、**そのエディションのレンダラだけ**がロードされる（FR-8）。
- **AC-5**: 破損した 1 件があっても、**一覧全体は使える**（FR-13/NFR-4）。
- **AC-6**: 移行が必要なプロジェクトが、**開く前に分かる**（FR-14）。
- **AC-7**: クラッシュ後、**復旧候補が提示**される（FR-6、F-CORE-02 と対）。
- **AC-8**: 未インストール機能の宣伝で**画面が散らからない**（FR-10）。
- **AC-9**: プロジェクト数が多くても**一覧が待たされない**（NFR-3、F-PLT-04 の測定対象）。

## 8. 非目標

- **画面デザイン・情報設計の細部**（`F-UX-01` デザインシステムと実装時）。
- 編集画面そのもの（各エディション仕様）。**入口は共有するが編集画面は分ける**（Vision 4.3 / 上流の画面方針）。
- プロジェクトの**検索・タグ・整理機能**の作り込み（必要になった時点で別途）。
- クラウド同期・共有（本コンセプトの非目標）。
- オンボーディングの詳細（`F-UX-05`）。
