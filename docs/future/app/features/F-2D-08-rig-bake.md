## 0. 完成系での位置づけ（逆算リンク）

由来する完成系（`features/README.md` 2 章）:

- **D-DONE-4**: フレームアニメーションと**簡易リグ焼き込み**を扱える。
- **D-DONE-2**: 非破壊で編集・修正できる。

逆算の理由: `D-DONE-4` の残り半分。**F-2D-07 が用意したフレームへ、リグの動きを「確定（bake）」する**側であり、**F-2D-04 の「bake 済みは変えず、次回 bake から反映」境界**の相手方でもある。

本コンセプトが「Blender 級の本格リグ制作を目指さない」（`APP_PRODUCT_VISION.md` 7 章）以上、ここは **「簡易だが、確実に壊れない」** ことに価値がある。**bake は生成物を作る操作＝失敗すると気づきにくい**ため、**検証と拒否の規律**が中心になる。

関係マップのノード: `F-2D-04`（動かす対象）、`F-2D-07`（bake 先）、`F-CORE-06`（preflight）、`G5 非破壊`。

## 1. ユーザーストーリー

- 制作者として、**パーツを動かして**アニメーションを作りたい（1 コマずつ描かずに済む）。
- 制作者として、作った動きを**フレームとして確定**し、書き出せる形にしたい。
- 制作者として、**左右反転版**を作っても**動きが破綻しない**でほしい。
- 制作者として、**bake が途中で失敗したときに、作業が壊れていない**でほしい。
- 制作者として、**巨大な結果を作ろうとして固まる**のは避けたい。

## 2. 用語

- **リグ**: パーツの親子関係と姿勢（pivot・回転・移動・スケール）で動きを表す仕組み。
- **bind pose**: 基準姿勢。
- **keyframe pose**: 時間上の姿勢。
- **bake（焼き込み）**: リグの結果をフレームとして確定すること。
- **parity（同等性）**: 元と反転版など、対応するもの同士が**規則どおり一致している**こと。

## 3. 機能要件（FR）

### 3.1 リグと bake

- **FR-1** **パーツの親子関係と姿勢**（pivot・移動・回転・スケール）を扱える（`F-2D-04` の Part 上に載る）。
- **FR-2** 姿勢に**時間軸（keyframe）** を与えられる。時間の意味は **`F-2D-07` の規範に従う**（独自の時間計算を持たない）。
- **FR-3** リグの結果を **フレームとして bake** できる（`F-2D-07` のフレームを生成）。
- **FR-4** **bake は非破壊**である。**リグ定義は残り**、**再 bake できる**（`G5` / F-CORE-03）。
- **FR-5** **bake 済みのフレームは、後からリグ構成が変わっても遡って書き換わらない**。**次回 bake から反映**する（`F-2D-04` FR-14 と対）。

### 3.2 bake 前の安全確認（継承 — 重要）

- **FR-6** bake の前に **構造 preflight** を行う（系譜: ADR-0022）: **有限値であること・参照が解決すること・親子循環が無いこと・所属の制約を満たすこと**。
- **FR-7** **生成量を割り当て前に見積もる**（生成フレーム数・状態数・サイズ等）。**フレーム数の算出結果が有限かつ 1 以上の安全な整数であることを、ループや領域確保に入る前に確認**する（系譜: ADR-0022）。
- **FR-8** 見積もりが**上限を超える場合、原子的に拒否**する（系譜: ADR-0022）。**途中まで作って止まる状態を作らない**。
- **FR-9** **拒否したとき、プロジェクト・履歴・自動保存を変更しない**（系譜: ADR-0022）。**失敗が何も壊さない**。

### 3.3 反転（継承）

- **FR-10** **左右反転版を作れる**。反転は**規則に従う**（系譜: ADR-0022 / ADR-0005）:
  - 反転軸は**アセットの原点 x**
  - **pivot の x を軸で鏡映**し、**y は変えない**
  - 姿勢は **x 位置を反転・回転を反転・スケールは維持**
  - **回転の可動域は上下限を入れ替えて符号反転**
  - **時間・fps・ループ・長さは変えない**
- **FR-11** 反転で **ID を再採番する場合、完全な対応表で全参照を張り替える**（親子・所属・フレーム参照・アニメーション参照・姿勢の参照・event の参照）。**張り替え漏れを許さない**（系譜: ADR-0022 / ADR-0002）。
- **FR-12** **event の名前を自動変更しない**（利用者が付けた意味を勝手に書き換えない）。
- **FR-13** **未解決参照・循環・非有限値・制約違反を、黙って落とさない／旧 ID のまま残さない**。**理由つきで拒否**する。**既存の違反データを自動で直さない**（系譜: ADR-0022。F-CORE-06 の「自動修復しない」と整合）。

### 3.4 parity（同等性）の検証（継承 — 比較を緩めない）

- **FR-14** 元と反転版の**同等性を検証**できる。比較は**厳格**に行う（系譜: ADR-0022）:
  - 位置・スケール・正規化した回転は**絶対差の許容のみ**（**相対許容を使わない**）
  - **配列順・可視性・不透明度・参照・時間は完全一致**
- **FR-15** **正規化してよい対象を限定**する（系譜: ADR-0022）: **対応が完全に証明された ID・作成/更新時刻・自動生成の表示名のみ**。
  **配列順・参照・時間・姿勢・可視性・不透明度・画素は正規化しない**（＝**比較を都合よく緩めない**）。
- **FR-16** **保存・再読込のあとにも同等性が保たれる**ことを確認できる（系譜: ADR-0022 の reload 後再実行）。

### 3.5 実行

- **FR-17** bake は重い処理になりうるため、**UI を固めず・進捗を示し・キャンセルできる**（`PF3` / F-PLT-03）。
- **FR-18** bake・反転は**履歴に乗る**（F-CORE-04）。**キャンセルは中途半端な生成物を残さない**（F-PLT-03 FR-5）。

## 4. 非機能要件（NFR）

- **NFR-1（失敗が壊さない）**: 拒否・失敗・キャンセルで、プロジェクト・履歴・自動保存が変わらない（FR-9/FR-18）。
- **NFR-2（非破壊）**: リグ定義と Source が残り、再 bake できる（FR-4。`G5`）。
- **NFR-3（厳格な検証）**: 同等性の判定を緩めない（FR-14/FR-15）。
- **NFR-4（決定性）**: 同じ入力・同じ版なら同じ bake 結果になる。
- **NFR-5（予測可能性）**: 生成量が事前に分かり、超過は実行前に止まる（FR-7/FR-8）。
- **NFR-6（応答性）**: 大きな bake でも UI が固まらない（FR-17）。

## 5. データ・保存への影響

- **リグ定義と bake 結果（フレーム）は別物**として持つ。bake は**派生**であり、**リグ定義を消費して失わない**（F-CORE-03）。
- **反転版は新しいアセットとして作る**場合、**ID の完全な対応表**を伴う（FR-11）。**元は変更しない**。
- **拒否時の write-set はゼロ**（FR-9）。
- 上限値（生成量の限度）は**未決**とし、`F-PLT-04` の実測と人間承認で決める（10 章）。

## 6. 依存機能

- **F-2D-04**（レイヤー & パーツ）: 動かす対象・bake 済み境界（FR-1/FR-5）。
- **F-2D-07**（フレーム）: bake 先・時間の規範（FR-2/FR-3）。
- **F-CORE-06**（検品）: 構造 preflight（FR-6）。
- **F-CORE-03 / 04**: 非破壊・履歴（FR-4/FR-18）。
- **F-PLT-03**（offload）: 非同期・進捗・キャンセル（FR-17）。
- **F-PLT-04**（計測）: 上限値の決定材料（FR-8）。
- **F-2D-09 / F-2D-10**: 反転時に同じ規則で扱う対象（アンカー・当たり判定）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: パーツを動かして keyframe を作り、**フレームとして bake** できる（FR-1〜FR-3）。
- **AC-2**: bake 後も**リグ定義が残り、再 bake できる**（FR-4/NFR-2）。
- **AC-3**: リグ構成を変えても、**既存の bake 済みフレームが遡って変わらない**（FR-5、`F-2D-04` AC-9 と対）。
- **AC-4**: bake 前に**構造 preflight** が走り、不正なら**実行前に拒否**される（FR-6）。
- **AC-5**: 生成量が**割り当て前に見積もられ**、上限超過は**原子的に拒否**される（FR-7/FR-8/NFR-5）。
- **AC-6**: 拒否・失敗・キャンセル時に、**プロジェクト・履歴・自動保存が変わらない**（FR-9/NFR-1）。
- **AC-7**: 反転が**規則どおり**（軸・pivot・姿勢・可動域・時間不変）に行われる（FR-10）。
- **AC-8**: 反転で **ID の張り替え漏れが無く**、**未解決参照は理由つきで拒否**される（FR-11/FR-13）。
- **AC-9**: **event 名が自動変更されない**（FR-12）。
- **AC-10**: 同等性検証が**絶対差のみ**で行われ、**配列順・参照・時間は完全一致**が要求される（FR-14/FR-15）。
- **AC-11**: **保存・再読込の後にも同等性が保たれる**（FR-16）。

## 8. 非目標

- **本格的なリグ制作・アニメーション制作**（Blender 級）。`APP_PRODUCT_VISION.md` 7 章の非目標。
- IK・物理・自動ウェイト等の高度なリグ機能（必要ならモジュール／将来判断）。
- 補間曲線の作り込み（`F-2D-07` の非目標と同じ）。
- 3D のリグ・モーション（3D 側の別機能）。
- 上限値そのものの確定（`F-PLT-04` の実測 + 人間承認）。

## 10. Open questions

- **生成量の上限値**（フレーム数・状態数・サイズ）。`F-PLT-04` の実測 + 人間承認で決める。
