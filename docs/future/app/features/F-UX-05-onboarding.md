## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **S-DONE-2**: **最小構成で軽く起動**し、必要な機能だけをインストールして広げられる。使わない機能の重さを負わない。
- **S-DONE-1**: Home から 2D・3D いずれのプロジェクトへも入れる。

逆算の理由: **本コンセプトの主張が、最初に試される場所**である。

Vision は「重すぎるなら使われない、使い勝手が悪ければ使われない」と置き、Architecture は「必要な機能だけを入れる」と答えた。しかし**初回起動は、その答えが裏目に出やすい場面**でもある——**最小構成で起動するということは、最初は何も入っていないということ**。ここで「何もできない」「何を入れればいいか分からない」と感じさせたら、install-on-demand は**利点ではなく障害**になる。

したがって本機能の要は、**「軽く起動すること」と「すぐ何かできること」を両立させる**ことである。

## 1. ユーザーストーリー

- 制作者として、**入れてすぐ、何かを作り始められる**と嬉しい。
- 制作者として、**最初に長い説明を読まされたくない**。
- 制作者として、**何を追加すればいいか、必要になった時に分かる**と助かる。
- 制作者として、**勝手に色々インストールされたくない**。
- 制作者として、**最初の起動が速い**ことで、この道具の性格を感じ取りたい。
- 制作者として、**あとで見返せる**なら、最初は読み飛ばしたい。

## 2. 用語

- **最小構成**: 追加を何もしていない状態。
- **道筋（path）**: 次に何をすればよいかの案内。
- **空の状態**: まだ何も作っていない画面。

## 3. 機能要件（FR）

### 3.1 最小構成で何ができるかを示す

- **FR-1** **最小構成のまま、代表的な作業を最後まで通せる**（作成 → 編集 → 書き出し）。**「まず何か入れないと始まらない」状態にしない**。
- **FR-2** **最小構成でできることを、最初に示す**（**できないことの一覧から始めない**）。
- **FR-3** 空の状態は、**目的と次の操作を短く示す**（`F-UX-01` FR-2。**空白のまま放置しない**）。

### 3.2 押しつけない（継承）

- **FR-4** **長い説明や手順の踏破を強制しない**（**読み飛ばせる**）。
- **FR-5** **あとから見返せる**（一度きりにしない。**最初は急いでいる**）。
- **FR-6** **未導入機能の勧誘で画面を散らかさない**（`F-CORE-08` FR-10 / `F-MOD-01` FR-6 と同じ規律。**最初の画面が広告売り場にならない**）。
- **FR-7** **勝手にモジュールを導入しない**（`F-MOD-02` の明示的な導入。**「おすすめ」を既定で入れない**）。

### 3.3 必要になった時に示す

- **FR-8** **文脈に応じて「この作業にはこの機能が要る」と示せる**（`F-MOD-06` へ委ねる。本機能は**初回の入口**を担う）。
- **FR-9** **示すことと、入れることを分ける**（**提示は情報、導入は利用者の決定**）。
- **FR-10** 用途に応じた**まとまり（プロファイル）を選べる**場合、それは**選択肢であって既定ではない**（`F-MOD-05` へ委ねる）。

### 3.4 軽さを体感させる（継承）

- **FR-11** **初回起動でも、未導入機能の実体を読まない**（`P4` / `F-CORE-08` FR-7/FR-9b。**最初の起動こそ、ゼロコストが最も見られる瞬間**）。
- **FR-12** **起動の速さが最初の評価**になることを前提に置く（`P1` の非採用の法則。**遅ければ、その先の良さは見てもらえない**）。
- **FR-13** **初回起動の時間は計測対象**である（`F-PLT-04`。**主張ではなく実測**）。

### 3.5 2D / 3D の入口

- **FR-14** **どちらのエディションへも入れる**（`S-DONE-1` / `F-CORE-08`）。
- **FR-15** **エディションの選択を、最初に強要しない**（**決めてから始める、を必須にしない**。ただし**選んだ後の分岐は明確**にする——`F-2D-01` FR / `P5`）。

### 3.6 到達性と伝わり方

- **FR-16** 案内は **`F-UX-02` の到達性**を満たす（**最初の体験で置き去りにされる利用者を作らない**）。
- **FR-17** 案内の文章は **`F-UX-03` の要件**に従う（専門用語に頼らない・次の一手が分かる）。

## 4. 非機能要件（NFR）

- **NFR-1（即座に使える）**: 最小構成のまま仕事が終わる（FR-1）。
- **NFR-2（押しつけない）**: 説明も導入も強制しない（FR-4/FR-7）。
- **NFR-3（散らからない）**: 勧誘で画面を埋めない（FR-6）。
- **NFR-4（軽さの体感）**: 初回起動が速く、未導入の実体を読まない（FR-11/FR-12）。
- **NFR-5（実測）**: 起動の速さを測る（FR-13）。
- **NFR-6（到達性）**: 最初の体験で置き去りにしない（FR-16）。

## 5. データ・保存への影響

- **保存データに影響しない**。
- 「案内を見たか」等の状態を持つ場合、**利用者設定として編集データと分ける**（`adr/0007`）。
- **初回起動時に、プロジェクトデータを勝手に作らない**（`F-CORE-01`。**空のまま始められる**）。

## 6. 依存機能

- **F-CORE-08**（Dashboard）: 最初の画面（FR-3/FR-14）。
- **F-MOD-01**（カタログ）: 発見の場（FR-6/FR-8）。
- **F-MOD-02**（導入）: 明示的な導入（FR-7）。
- **F-MOD-05 / 06**（プロファイル / 文脈連動）: 束ねた提示と文脈提示（FR-8/FR-10）。
- **F-UX-01 / 02 / 03**（作法・到達性・文章）: 案内の質（FR-3/FR-16/FR-17）。
- **F-PLT-04**（計測）: 初回起動の実測（FR-13）。
- **F-2D-01 / F-3D-01**（各エディションの起点）: 最初の作業の受け皿（FR-1）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: **最小構成のまま、作成 → 編集 → 書き出しが通る**（FR-1/NFR-1）。
- **AC-2**: **最小構成でできることが最初に示される**（FR-2）。
- **AC-3**: **空の状態に、目的と次の操作**がある（FR-3）。
- **AC-4**: **説明の踏破が強制されない**（FR-4/NFR-2）。
- **AC-5**: 案内が**あとから見返せる**（FR-5）。
- **AC-6**: **未導入機能の勧誘で画面が散らからない**（FR-6/NFR-3）。
- **AC-7**: **勝手にモジュールが導入されない**（FR-7/NFR-2）。
- **AC-8**: **示すことと入れることが分かれている**（FR-9）。
- **AC-9**: まとまりの提示が**既定ではなく選択肢**である（FR-10）。
- **AC-10**: **初回起動で未導入機能の実体が読まれない**（FR-11/NFR-4）。
- **AC-11**: **初回起動の時間が計測**される（FR-13/NFR-5）。
- **AC-12**: **どちらのエディションへも入れ**、**選択が強要されない**（FR-14/FR-15）。
- **AC-13**: 案内が **`F-UX-02` の到達性**を満たす（FR-16/NFR-6）。
- **AC-14**: 案内の文章が **`F-UX-03` の要件**に従う（FR-17）。
- **AC-15**: **初回起動でプロジェクトデータが勝手に作られない**（5 章）。

## 8. 非目標

- 詳しい使い方の教育（**必要な時に必要な場所で示す**。長い教材を最初に置かない）。
- 画面・文言・手順の確定（実装時に判断）。
- プロファイルの中身（**F-MOD-05**）と文脈連動の提示（**F-MOD-06**）。
- 利用者の登録・アカウント（Vision 7 章の非目標。**アカウント無しで完結する**）。
- 使用状況の外部送信（**オフライン前提**。必要なら別判断）。
- 初回限定の特別扱い（FR-5。**あとからでも同じ情報へ到達できる**）。
