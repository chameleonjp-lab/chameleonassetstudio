## 0. 完成系での位置づけ（逆算リンク）

由来する完成系（`features/README.md` 2 章）と成功条件:

- **S-DONE-2**: 最小構成で軽く起動し、**使わない機能の重さを負わない**。
- `APP_PRODUCT_VISION.md` 8 章 成功条件 1: 最小構成が、同種の重量級ツールより**明確に速く・軽く起動する**。

逆算の理由: ここまでに詳細化した機構は、**測れることを暗黙の前提にしている**。

| これまでの主張 | 出所 | 測らないとどうなるか |
|---|---|---|
| 未インストール機能はゼロコスト | `P4` / Arch 7 章 | 検証不能な願望のまま |
| 撤去でコストが戻る（残渣ゼロ） | F-MOD-02 NFR-1 | 「戻った」と言い張るだけになる |
| 宣言 footprint と実測を突き合わせる | F-MOD-03 FR-13 | 突き合わせる相手が存在しない |
| 導入済みでも起動時に載せない | F-CORE-09 FR-5 | 遅延ロードが効いているか分からない |

**測定が無ければ、これまでの 10 機能の中核的な約束は「証拠のない主張」に留まる。** 本機能はそれを証拠にする `PF2` の正本である。

また `APP-R-01`（外殻方式は**実測後に確定**）が示すとおり、**候補を測る物差しは、外殻を選ぶ前に必要**である。ゆえに F-PLT-01（外殻）より本機能を先に固める。

関係マップのノード: `PF2 計測・退行検知`（本機能が実現）、`PF1 性能予算`（数値の置換先）、`P4 未使用ゼロコスト`（検証対象）、`PF5 外殻方式`（評価基準の供給先）。

## 1. ユーザーストーリー

- 制作者として、「軽い」と言われるより、**実際に軽い**ことを体感したい。
- 制作者として、更新のたびに**少しずつ重くなっていく**ことが無いと信じたい。
- （開発側として）**どの変更が重くしたのか**を後から特定できるようにしたい。
- （開発側として）宣言された footprint が**実態と合っているか**を確かめたい。

## 2. 用語

- **指標（metric）**: 測る対象（起動時間、常駐メモリ等）。
- **固定 fixture**: 測定に使う、内容が固定された代表プロジェクト（同一性をハッシュで担保）。
- **固定 matrix**: 測定する環境の組み合わせ（OS × ハード × ビルド種別）。
- **baseline**: 比較の基準となる過去の測定結果。
- **退行（regression）**: baseline からの悪化。
- **停止条件**: 「これが欠けている間は数値を採用しない」という条件（系譜: H3 プロトコル 8 章）。

## 3. 機能要件（FR）

### 3.1 何を測るか

- **FR-1** 指標を定義する（概念例。実数は未決）:
  - **冷間起動時間**（最小構成 / モジュール導入後）
  - **常駐メモリ**（空プロジェクト / 代表プロジェクト）
  - **最小インストーラサイズ**
  - **入力応答**（代表操作の手応え）
  - **代表操作の所要時間**（重い処理を含む）
  - **モジュール導入/撤去の前後差分**
- **FR-2** **固定 fixture** を用意し、**同一性をハッシュで担保**する（別物を測って比較しない）。
- **FR-3** **固定 matrix**（対象 OS・実機・ビルド種別）を先に決める。

### 3.2 どう測るか（手順を先に固定する）

- **FR-4** **結果 schema を固定**し、比較可能な形で記録する（いつ・どの commit・どの fixture・どの環境・どの指標）。
- **FR-5** **測定方法を先に固定し、数値 budget は実測後に決める**。数値を先に置いて辻褄を合わせない（系譜: H3 の `M1` の考え方）。
- **FR-6** **未測定範囲を明記**する。測っていないものを「問題なし」と扱わない。
- **FR-7** **測定不能・未対応を 0 として集計しない**（系譜: H3 停止条件）。欠測は欠測として残す。
- **FR-8** **代替測定を本物の代替として扱わない**（例: 開発ビルドや簡易ハーネスの値を、製品ビルド・実機の結果として扱わない。系譜: H3 の「Node core 結果を製品 path の代替にしない」）。
- **FR-9** 実行条件（省電力状態、温度、バックグラウンド負荷、再起動・クラッシュの有無）を**記録**する。

### 3.3 何を証明するか

- **FR-10** **ゼロコスト検証**: 「未導入」「導入済み・未ロード」「有効」の 3 状態で測り、**未使用が起動・常駐・サイズに乗らない**ことを示せる（`P4` / F-CORE-09 FR-5）。
- **FR-11** **コスト戻り検証**: 導入 → 撤去で指標が**導入前の水準へ戻る**ことを示せる（F-MOD-02 NFR-1 の残渣ゼロ）。
- **FR-12** **宣言 footprint と実測の突き合わせ**結果を出力する（F-MOD-03 FR-13）。
- **FR-13** **外殻候補の比較材料**を同一手順で出せる（`PF5` / F-PLT-01 の評価基準。`APP-R-01` は実測後に確定と定めている）。

### 3.4 退行を止める

- **FR-14** baseline と比較し、**退行を検出**できる。
- **FR-15** 退行はレビュー／CI で**止められる**（`APP-RISK-02`「ゼロコスト原則の崩れ」、`APP-RISK-03`「重い依存の Core への染み出し」の早期検知）。

### 3.5 数値採用の停止条件（継承）

- **FR-16** 次のいずれかが欠ける間は、**数値 budget を確定（accepted）にしない**:
  - 固定 matrix の対象環境の結果が揃っていない。
  - fixture の同一性（ハッシュ）が確認できない。
  - 未対応・測定不能を 0 として集計している（FR-7 違反）。
  - 実行条件（省電力・温度・バックグラウンド）を記録していない（FR-9 違反）。
  - 代替測定を本物として扱っている（FR-8 違反）。
  - **人間が数値の採用を承認していない**。
- **FR-17** 「**測定方法を固定した**」ことと「**数値を採用した**」ことを**区別して扱う**（前者の完了は後者の完了を意味しない）。

## 4. 非機能要件（NFR）

- **NFR-1（再現性）**: 同じ commit・同じ fixture・同じ環境なら結果が再現する。
- **NFR-2（可搬性）**: 同じ手順を別環境でも実行できる。
- **NFR-3（非侵襲）**: 計測が製品の挙動を変えない。計測機構が製品の常駐コストにならない（`P4` と矛盾しない）。
- **NFR-4（透明性）**: 何を測り、何を測っていないかが読み手に分かる（FR-6）。
- **NFR-5（正直さ）**: 悪い結果を丸めない。欠測・失敗をそのまま残す。

## 5. データ・保存への影響

- 測定結果・baseline は**開発側の記録**であり、**プロジェクト保存の器（F-CORE-05）に含めない**。利用者のプロジェクトへ計測データを混ぜない。
- 固定 fixture は測定専用の資産として管理する（利用者データを勝手に測定へ使わない）。

## 6. 依存機能

- **F-MOD-02**（導入/撤去）: コスト戻り検証の対象（FR-11）。
- **F-MOD-03**（依存/footprint）: 宣言値の供給元（FR-12）。
- **F-CORE-09**（Host / 遅延ロード）: 3 状態測定の対象（FR-10）。
- **F-PLT-01**（ネイティブ外殻）: 本機能が評価基準を供給する（FR-13。**本機能が先**）。
- **F-PLT-03**（offload）: 応答性測定の対象。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 固定 fixture と固定 matrix が定義され、**fixture の同一性が確認**できる（FR-2/FR-3）。
- **AC-2**: 結果が固定 schema で記録され、**過去と比較**できる（FR-4）。
- **AC-3**: 「未導入 / 導入済み・未ロード / 有効」の 3 状態の差から、**未使用がゼロコスト**であることを示せる（FR-10）。
- **AC-4**: 導入 → 撤去で指標が**導入前へ戻る**ことを示せる（FR-11）。
- **AC-5**: 宣言 footprint と実測の**乖離が出力**される（FR-12）。
- **AC-6**: baseline からの**退行が検出され、止められる**（FR-14/FR-15）。
- **AC-7**: **未測定範囲・欠測が明記**され、0 で埋められていない（FR-6/FR-7）。
- **AC-8**: 停止条件を満たさない限り、**数値 budget が accepted にならない**（FR-16/FR-17）。

## 8. 非目標

- **数値 budget そのものの確定**（実測と人間承認の後。本機能は手順と停止条件まで）。
- 外殻方式の**採用判断**（F-PLT-01 / `APP-R-01`。本機能は比較材料を供給するだけ）。
- CI 基盤・計測ハーネスの実装（実装時）。
- 利用者向けの性能可視化 UI（別途）。
- 上流 `tools/h3` の実装を**そのまま流用する決定**（本コンセプトは別系統。継承するのは**進め方**であり、コードの採用は別判断）。
