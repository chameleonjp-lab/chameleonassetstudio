## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **T-DONE-4**: 原点・足元・向き・スケールを整え、3D アンカーと **3D 当たり判定（box / sphere / capsule）**を付けられる。
- **T-DONE-8**: metadata つきで書き出せる。

逆算の理由: 2D の `F-2D-10`（当たり判定）に対応する **3D 版**であり、`F-3D-06`（アンカー）と対で **`T-DONE-4` を完成**させる。

本機能の設計判断で最も重要なのは、**何を作らないか**である。上流は初期の形状を **box / sphere / capsule に限定**し、**mesh collider を作らない**と決めた。理由は明快で、**重くなりやすく、エンジン差も大きい**（系譜: 上流 §4.2）。これは 2D で **polygon を境界として扱った** ADR-0010 と**同じ判断構造**である——**表現力の不足より、重さとエンジン差による「動くはずが動かない」を避ける**。

## 1. ユーザーストーリー

- 制作者として、**当たる範囲**を決めたい。
- 制作者として、**体・攻撃・取得・検知**などを**目的別に分けたい**。
- 制作者として、**判定が重くなりすぎない**と確信したい。
- 制作者として、**勝手に判定を作られたくない**。
- 制作者として、**書き出し先で判定がずれない**でほしい。

## 2. 用語

- **判定（collider）**: エンジン側で当たり判定に使う簡単な形。
- **目的（purpose）**: その判定が何のためか（体 / 攻撃 / 取得 / 検知 / 任意）。
- **mesh collider**: モデルの形そのものを判定に使う方式。**初期対象外**。

## 3. 機能要件（FR）

### 3.1 形状の限定（継承の核心）

- **FR-1** 形状は **box / sphere / capsule** を扱う（系譜: 上流 §4.2）。
- **FR-2** **mesh collider を作らない**（系譜: 同上。**重くなりやすく、エンジン差も大きい**）。
- **FR-3** 形状を増やす場合、**導入前に確認する条件を決め切ってから有効にする**（系譜: ADR-0010 の polygon 境界と同じ規律。**「あると便利」だけで足さない**）。少なくとも **対象エンジンでの再現性・負荷・書き出し表現**を確認する。
- **FR-4** **限定された形状だけで制作が完了する**ことを前提に置く（`F-2D-10` と同じ。**足りない形状が制作の行き止まりにならない**）。

### 3.2 付与と目的

- **FR-5** 判定を**追加・移動・サイズ変更・削除**できる。
- **FR-6** 判定は **目的**を持てる（体 / 攻撃 / 取得 / 検知 / 任意。系譜: 上流 §4.2 の `purpose`）。**目的の一覧を閉じない**。
- **FR-7** 判定は **名前を持ち、名前は一意**である（外部参照のため。`F-3D-06` FR-5 と同じ）。
- **FR-8** 1 つのモデルに**複数の判定**を持てる（体と攻撃を同時に持つのが普通）。

### 3.3 推測で作らない（継承）

- **FR-9** **判定を自動生成しない**（系譜: ADR-0018 / `F-2D-10` / `F-2D-11` FR-7 と同じ。**bounds から自動で箱を作って「付けました」としない**）。
- **FR-10** **候補の提示は可**とする（bounds から初期サイズを示すなど）。**確定は制作者が行う**（`F-3D-06` FR-9 と同じ）。

### 3.4 基準・出力との関係

- **FR-11** 判定の座標は **`F-3D-05` が決めた基準**に従う（`F-3D-06` FR-11 と同じ）。
- **FR-12** **対象エンジンごとの軸・単位変換で、判定の保存値を変えない**（変換は書き出し側。`F-3D-05` FR-15）。
- **FR-13** **未対応形状・未対応の目的を出力先が持たない場合、理由つきで警告**する（`F-CORE-06` の出力検証 / `F-2D-10` FR と同じ）。**黙って落とさない**。

### 3.5 非破壊と編集の土台

- **FR-14** 判定は **元モデルを変更しない**追加情報である（`G5` / `F-CORE-03`）。
- **FR-15** 操作は **Core の履歴に乗る**（`F-CORE-04`）。
- **FR-16** 配置は **`F-3D-03` の面の上で、モデルに重ねて**行える（**当たり範囲は見て決めるもの**）。

## 4. 非機能要件（NFR）

- **NFR-1（軽さの保証）**: 形状が限定され、重い判定を作れない（FR-1/FR-2）。
- **NFR-2（境界の規律）**: 形状追加は条件を決めてから（FR-3）。
- **NFR-3（推測しない）**: 自動生成しない（FR-9）。
- **NFR-4（非破壊）**: 元モデルが不変（FR-14。`G5`）。
- **NFR-5（正直さ）**: 出力先で表せないものを黙って落とさない（FR-13）。
- **NFR-6（可視性）**: 絵に重ねて置ける（FR-16）。

## 5. データ・保存への影響

- 判定は **additive な追加情報**として保存する（`D3` / `D4`。**未対応環境でも正本が成立する**。`F-2D-10` と同じ）。
- **元モデルはバイト不変**（FR-14）。
- **書き出し時の変換は保存値を変えない**（FR-12）。

## 6. 依存機能

- **F-3D-05**（基準整備）: 座標の土台（FR-11）。
- **F-3D-03**（ビューポート）: 重ね表示と配置操作（FR-16）。
- **F-CORE-06**（検品）: 妥当性検証・未対応形状の警告（FR-13）。
- **F-CORE-03 / 04**: 非破壊・履歴（FR-14/FR-15）。
- **F-3D-06**（アンカー）: `T-DONE-4` の対。
- **F-3D-13 / 14 / 15**（metadata / report / 書き出し）: 出力先。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: **box / sphere / capsule** を付与できる（FR-1）。
- **AC-2**: **mesh collider が作られない**（FR-2/NFR-1）。
- **AC-3**: 形状追加が**条件を決め切るまで有効にならない**（FR-3/NFR-2、`F-2D-10` の polygon 規律と同じ）。
- **AC-4**: **限定された形状だけで制作が完了**できる（FR-4）。
- **AC-5**: 判定を**追加・移動・サイズ変更・削除**でき、**複数持てる**（FR-5/FR-8）。
- **AC-6**: **目的を付けられ**、一覧が**閉じていない**（FR-6）。
- **AC-7**: 名前が**一意**である（FR-7）。
- **AC-8**: **判定が自動生成されない**（FR-9/NFR-3）。
- **AC-9**: 候補が提示されても、**確定は制作者が行う**（FR-10）。
- **AC-10**: **書き出し時の軸・単位変換で保存値が変わらない**（FR-12）。
- **AC-11**: 出力先で**表せないものが理由つきで警告**され、黙って落ちない（FR-13/NFR-5）。
- **AC-12**: 付与後も**元モデルがバイト不変**（FR-14/NFR-4）。
- **AC-13**: 操作が**履歴に乗り、取り消せる**（FR-15）。
- **AC-14**: **モデルに重ねて配置**できる（FR-16/NFR-6）。

## 8. 非目標

- **mesh collider**（FR-2。**重さとエンジン差**が理由。将来やるなら FR-3 の条件を先に決める）。
- 凸包・自動分割などの生成（FR-9 と同じ理由）。
- 物理挙動（質量・摩擦・反発）の設定。**判定の形**が本機能の範囲であり、**物理の設定はエンジン側**。
- 骨格に追従する判定（**F-3D-08** と連動。必要なら別判断）。
- アンカー（**F-3D-06**）。
- 対象エンジンごとの変換（**F-3D-15**）。
