## 0. 完成系での位置づけ（逆算リンク）

由来する完成系（`features/README.md` 2 章）:

- **D-DONE-8**: 保存し、開き直して再開でき、**クラッシュしても復旧できる**。
- **S-DONE-4**: 失敗・制限が文章で分かり、**手動で必ず回復できる**。

逆算の理由: **F-CORE-01 FR-13**（クラッシュ後に未保存だった直近の一貫状態を復旧候補として提示）と **F-CORE-08 FR-6**（Dashboard で復旧候補を提示）は、**どちらもこの機能の存在を前提に書かれていた**。その実体が本機能である。

これは **Core 群（F-CORE-01〜10）の最後の 1 機能**でもある。

関係マップのノード: `F-CORE-01`（復旧されたセッションを開く経路）、`F-CORE-08`（提示先）、`G5 非破壊`（自動保存が正本を汚さない）、`D1`（器の形式）。

## 1. ユーザーストーリー

- 制作者として、**アプリが落ちても作業が消えない**でほしい。
- 制作者として、復旧するかどうかを**自分で選びたい**。勝手に上書き復元されたくない。
- 制作者として、**自動保存が作業の邪魔をしない**でほしい（保存のたびに固まるのは困る）。
- 制作者として、**大きな変更の前に戻れる点**があると安心できる。
- 制作者として、**復旧データがディスクを埋め尽くさない**でほしい。

## 2. 用語

- **自動保存**: 利用者の明示操作によらず、作業内容を残す仕組み。
- **復旧領域（作業コピー）**: 自動保存の書き込み先。**利用者の保存ファイル（可搬正本）とは別**（系譜: ADR-0006 (e) の区別）。
- **復旧候補**: 再起動時に「戻せます」と提示できる状態。
- **復旧点**: 破壊的操作の前に作る、戻れる地点（系譜: ADR-0006 (b)）。

## 3. 機能要件（FR）

### 3.1 自動保存

- **FR-1** 作業内容を**自動的に保存**する（時間契機・操作契機のいずれか、または両方。具体は未決）。
- **FR-2** **自動保存は利用者の保存ファイル（可搬正本）を上書きしない**。**別の復旧領域（作業コピー）へ書く**（系譜: ADR-0006 (e)）。**「保存した」と「自動保存された」を混同させない**。
- **FR-3** 自動保存が**作業を妨げない**（UI を固めない。`PF3` / F-PLT-03）。
- **FR-4** 自動保存の**契機・間隔を設定でき、無効化もできる**。
- **FR-5** 自動保存は **原子的に書く**（中途半端な自動保存を残さない。F-PLT-02 FR-1）。

### 3.2 復旧

- **FR-6** クラッシュ・強制終了後の再起動時、**復旧候補を提示**する（F-CORE-08 FR-6 / F-CORE-01 FR-13 への供給）。
- **FR-7** **復旧するかどうかは利用者が選ぶ**。**黙って上書き復元しない**。
- **FR-8** 復旧候補は**一貫状態**である（壊れた・中途半端なものを候補にしない。FR-5 と対）。
- **FR-9** 復旧を**選ばなかった場合でも、候補を即座に捨てない**（誤操作からの取り返しを残す）。保持と掃除の方針を持つ（FR-13）。
- **FR-10** 復旧の結果は **F-CORE-01 の「開く」経路に乗る**（別経路を作らない。F-CORE-01 FR-13）。

### 3.3 破壊的操作前の復旧点（継承）

- **FR-11** **破壊的操作の前に復旧点を作る**（系譜: ADR-0006 (b)）。対象例: 移行（F-CORE-05 FR-6 の退避と整合）、一括変更、大きな取り込み。
- **FR-12** **削除の取り消しの余地**を残す（黙って消えたまま戻せない状態を作らない）。

### 3.4 境界と節度

- **FR-13** 復旧領域の**場所・保持期間・世代・掃除**を定める。**無限に溜めない**（ディスクを圧迫しない）。
- **FR-14** 自動保存・復旧領域は **Source（元データ）を書き換えない**（`G5` / F-CORE-03）。
- **FR-15** **UI 一時状態を編集データに混ぜない**（F-CORE-01 6 章の分離を、自動保存でも守る）。
- **FR-16** 自動保存の存在で「**保存済み**」と誤認させない。未保存の変更がある状態は、**未保存として示す**（F-CORE-01 FR-10 の保存確認は依然として働く）。

## 4. 非機能要件（NFR）

- **NFR-1（データ非損失）**: クラッシュ時に、直近の一貫した作業状態を失わない。
- **NFR-2（非破壊）**: 自動保存が可搬正本と Source を汚さない（FR-2/FR-14。例外なし）。
- **NFR-3（応答性）**: 自動保存が体感的な引っかかりを生まない（FR-3）。
- **NFR-4（節度）**: 復旧データがディスクを圧迫しない（FR-13）。
- **NFR-5（明快さ）**: 何が復旧できるのか・いつの状態なのかが分かる（FR-6/FR-16）。
- **NFR-6（オフライン）**: ローカルで完結する。

## 5. データ・保存への影響

- **復旧領域は可搬正本とは別**（系譜: ADR-0006 (e) の「ローカル作業コピー / 可搬正本」の区別を継承）。**復旧領域＝配布・共有の対象ではない**。
- 復旧領域の中身は **F-CORE-05 の器の形式**に従う（別形式を作らない。開き直せることが前提）。
- **UI 一時状態は含めない**（FR-15）。セッション状態（ズーム等）を復旧に含めるかは F-CORE-01 6 章の分離に従い、**含めても Document とは別レイヤー**とする。
- 破壊的操作前の復旧点は、**移行時の退避（F-CORE-05 FR-6）と役割が重なる**。両者の関係（同一機構にするか）は未決（10 章）。

## 6. 依存機能

- **F-CORE-01**（ライフサイクル）: 復旧されたセッションを開く経路（FR-10）。
- **F-CORE-05**（保存形式）: 復旧領域の器の形式、移行時退避との整合（FR-11）。
- **F-CORE-08**（Dashboard）: 復旧候補の提示先（FR-6）。
- **F-PLT-02**（ファイル I/O）: 原子的書き込み・保存先の扱い（FR-5）。
- **F-PLT-03**（offload）: 自動保存を UI から逃がす（FR-3）。
- **F-CORE-03**（非破壊）: Source 不可侵（FR-14）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 作業中に強制終了させても、**再起動時に復旧候補が提示**される（FR-6）。
- **AC-2**: 復旧候補が**一貫状態**で、開いて作業を続けられる（FR-8/FR-10）。
- **AC-3**: **復旧するかどうかを利用者が選べ**、選ばなければ**勝手に上書きされない**（FR-7）。
- **AC-4**: 自動保存が動いても、**利用者の保存ファイルが更新されていない**（FR-2、`G5`）。
- **AC-5**: 自動保存中も **UI が応答**し、引っかかりを感じない（FR-3/NFR-3）。
- **AC-6**: **未保存の変更があれば「未保存」と示され**、閉じる際の確認が働く（FR-16、F-CORE-01 AC-5 と対）。
- **AC-7**: 破壊的操作（移行等）の前に**戻れる点があり、戻せる**（FR-11、F-CORE-05 AC-1 と対）。
- **AC-8**: 復旧データが**保持方針に従って掃除**され、無限に増えない（FR-13/NFR-4）。
- **AC-9**: 自動保存・復旧のいずれでも、取り込んだ **Source がバイト不変**（FR-14）。

## 8. 非目標

- **保存間隔・保持世代の具体値**（実測と運用で決める。F-PLT-04 と連動）。
- 版管理・履歴の永続化（Undo 履歴の永続は F-CORE-04 の Open question）。
- クラウドバックアップ・同期（本コンセプトの非目標）。
- 不正 import の隔離（取り込み時の安全性は F-PLT-02 FR-7 / F-CORE-06 FR-12 の境界）。
- 自動修復（壊れたデータを勝手に直さない。F-CORE-06 の方針と同じ）。
