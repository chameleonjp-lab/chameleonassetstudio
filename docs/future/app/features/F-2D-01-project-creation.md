## 0. 完成系での位置づけ（逆算リンク）

由来する完成系（`features/README.md` 2 章）:

- **D-DONE-1**: **空キャンバス／テンプレート／画像取り込み／図形／パーツ**から 2D アセットを新規作成できる。
- **S-DONE-1**: Home / Project Dashboard から入れる（F-CORE-08 FR-1 の受け手）。

逆算の理由: ここは **2D パイプラインの起点**であり、上流方針が繰り返し強調してきた一点——**「Chameleon は画像取り込み専用の変換ツールではない」**（`PRODUCT_DIRECTION_2D_TO_3D.md` 3 章）——が最初に形になる場所である。

つまり本機能は「**何から作り始められるか**」を定義する。ここが画像取り込みだけに痩せると、**製品の性格そのものが「変換ツール」に落ちる**。逆にここが揃えば、以降の編集・整備・検品・書き出しがすべて「制作ツール」として意味を持つ。

関係マップのノード: `A3 Edition Runtime`（2D 側）、`F-CORE-01`（プロジェクト生成の受け皿）、`P5 目的分離`。

## 1. ユーザーストーリー

- 制作者として、**白紙から描き始めたい**ときがある。
- 制作者として、**よくあるサイズ・用途はテンプレートから始めたい**（毎回設定したくない）。
- 制作者として、**手持ちの画像を持ち込んで**そこから整えたい。
- 制作者として、**図形を組み合わせて**簡単なアイコンやパーツを作りたい。
- 制作者として、**前に作ったものを土台に**新しいものを作りたい。
- 制作者として、作り始めの選択で**あとから詰まりたくない**（最初の選択が取り返しのつかない分岐にならないでほしい）。

## 2. 用語

- **起点（origin of creation）**: 新規作成の出発点（空 / テンプレート / 画像 / 図形 / 既存アセット）。
- **テンプレート**: 用途別の初期設定（キャンバスサイズ、既定レイヤー構成など）のひな型。
- **アセット種別**: character / item / background / tile・tileset / gimmick / effect / ui・icon（上流の分類を継承）。

## 3. 機能要件（FR）

### 3.1 起点の選択

- **FR-1** 次の**起点から作成できる**（`D-DONE-1`）:
  - **空キャンバス**（サイズ指定）
  - **テンプレート**（用途別のひな型）
  - **画像取り込み**（実体は F-2D-02）
  - **図形**（実体は F-2D-06）
  - **既存アセット / パーツから**（複製・派生。F-CORE-03 の Variant と接続）
- **FR-2** **アセット種別**（character / item / background / tile / gimmick / effect / ui・icon）を選べる。種別は後続の既定（検品項目・書き出し preset）に影響する。
- **FR-3** **起点は「入口」であって「牢屋」ではない**。ある起点で作り始めても、**後から別の要素を足せる**（画像から始めても図形を足せる／空から始めても画像を取り込める）。

### 3.2 プロジェクトとの関係

- **FR-4** 作成は **F-CORE-01 の Project 生成に乗る**（本機能は「空の Project を用意し、起点に応じた初期内容を入れる」まで）。**独自の保存経路を作らない**。
- **FR-5** 作成時に決めた内容（キャンバスサイズ・種別など）は、**後から変更できる余地**を残す（できない場合は、作成時に**それと分かる**ようにする）。
- **FR-6** **エディションは 2D で固定**され、作成後に 3D へ変換しない（`P5` / F-CORE-01 FR-1。別プロジェクトにする）。

### 3.3 テンプレート

- **FR-7** テンプレートは**用途が分かる名前と説明**を持ち、何が設定されるかが**作成前に分かる**。
- **FR-8** テンプレートは**出発点であり拘束ではない**（適用後に自由に変えられる）。
- **FR-9** テンプレートを**モジュールが追加できる**（`A4` / F-CORE-09 の拡張点）。ただし**器の作法を壊さない**。

### 3.4 迷わせない

- **FR-10** **最小の選択で始められる**（既定値があり、詳細設定は任意）。`P1`（使い勝手）の観点で、最初の画面で立ち止まらせない。
- **FR-11** 各起点が**何に向いているか**を短く示す（初見でも選べる）。
- **FR-12** 作成に失敗した場合（無効なサイズ・読めない画像等）、**理由を文章で示し、やり直せる**（`S-DONE-4`）。

## 4. 非機能要件（NFR）

- **NFR-1（軽さ）**: 作成画面の表示に重い依存を要求しない（Dashboard からの遷移で `P4` を崩さない。F-CORE-08 FR-7 と連続）。
- **NFR-2（応答性）**: 大きなサイズ・大きな画像を選んでも UI を固めない（`PF3`）。
- **NFR-3（非破壊）**: 画像・既存アセットを起点にしても、**元を書き換えない**（`G5` / F-CORE-03）。
- **NFR-4（明快さ）**: 選択の結果が予測できる（FR-7/FR-11）。
- **NFR-5（オフライン）**: すべてローカルで完結する。

## 5. データ・保存への影響

- 作成された Project は **F-CORE-05 の器**に従う。本機能は独自形式を作らない。
- **アセット種別**は保存データの属性として持つ（検品・書き出しの既定に影響）。**UI 一時状態とは分ける**。
- 画像・既存アセットを起点にした場合、**元は Source として保持**され、編集は派生になる（F-CORE-03 FR-1/FR-3.1）。
- テンプレート自体の保存形式・置き場所は未決（10 章）。

## 6. 依存機能

- **F-CORE-01**（ライフサイクル）: Project 生成の受け皿（FR-4）。
- **F-CORE-08**（Dashboard）: 作成への入口（F-CORE-08 FR-1）。
- **F-CORE-03**（非破壊）: 画像・既存アセット起点での Source 保持（NFR-3）。
- **F-2D-02**（画像取り込み）/ **F-2D-06**（図形）: 起点の実体。
- **F-2D-03**（Canvas）: 作成後の編集面。
- **F-CORE-09**（Host）: テンプレート拡張の登録経路（FR-9）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: **5 つの起点すべて**（空 / テンプレート / 画像 / 図形 / 既存アセット）から作成できる（FR-1、`D-DONE-1`）。
- **AC-2**: **アセット種別を選べ**、それが後続の既定に反映される（FR-2）。
- **AC-3**: ある起点で作り始めても、**後から他の要素を足せる**（FR-3）。
- **AC-4**: 作成された Project が **F-CORE-01 の通常の保存・再開経路**で扱える（FR-4）。
- **AC-5**: 画像・既存アセットを起点にしても、**元がバイト／意味上不変**（NFR-3、F-CORE-03 AC-6 と対）。
- **AC-6**: **既定値だけで作成を完了**でき、詳細設定は任意（FR-10）。
- **AC-7**: 作成失敗時に**理由が示され、やり直せる**（FR-12）。
- **AC-8**: モジュール提供のテンプレートが、**標準のものと同じ作法**で扱われる（FR-9）。

## 8. 非目標

- **テンプレートの中身の確定**（どの用途をいくつ用意するか。実装時／運用で決める）。
- 画像取り込みの詳細（**F-2D-02**）。
- 図形描画の詳細（**F-2D-06**）。
- キャンバスの操作・表示（**F-2D-03**）。
- 3D プロジェクトの作成（3D 側の機能。`P5` により混ぜない）。
- 作成 UI の画面デザイン（`F-UX-01`）。
