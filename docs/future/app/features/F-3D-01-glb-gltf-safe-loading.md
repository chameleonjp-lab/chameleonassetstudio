## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **T-DONE-1**: GLB / glTF（+bin+textures）を**安全に**読み込める（壊れ・危険を検知）。
- **T-DONE-9**: 保存・再開でき、**元の 3D モデルを絶対に上書きしない**。

逆算の理由: **3D パイプラインの入口**であり、`F-2D-02`（画像取り込み）と同じく **外部の信頼できないファイルがアプリへ入る場所**。ここが甘いと、後段の検品・軽量化・書き出しがすべて砂上の楼閣になる。

そして 3D では、この入口が 2D より**危険で複雑**である。glTF は **1 つのファイルで完結しない**——`.gltf` が `.bin` と複数のテクスチャを**外部参照**する。参照の解決範囲を限定しなければ、**取り込みがファイルシステムの読み取り経路になる**。

なお本コンセプトが 3D で最初に狙う価値も、上流の結論と同じである——**「生成ではなく、検品と軽量化」**（系譜: 上流 §15。**生成 3D の出力先ではなく、生成 3D をゲーム素材へ整える場所**）。

## 1. ユーザーストーリー

- 制作者として、**外部で作った / 生成した 3D モデルを読み込み**たい。
- 制作者として、**壊れたファイルで、アプリが壊れない**でほしい。
- 制作者として、**読めない理由を知りたい**（黙って失敗されると困る）。
- 制作者として、**元のモデルファイルが絶対に変わらない**と確信したい。
- 制作者として、**大きなモデルでも、進行が見えて、待てる**ようにしたい。

## 2. 用語

- **付随ファイル**: `.gltf` が参照する `.bin`・テクスチャなど、**モデル本体以外の必要ファイル**。
- **preflight**: 本体の解析を始める前に、安全に確認できる範囲だけを調べること。
- **隔離**: 取り込めなかったものを、本編に影響しない場所へ退避すること。

## 3. 機能要件（FR）

### 3.1 対象と分類

- **FR-1** **単一ファイル形式（GLB）と、付随ファイルを伴う形式（glTF + bin + textures）**を扱える（系譜: 上流 §3.1 の初期候補）。
- **FR-2** 形式ごとの扱いを **「どう扱われるか」で表示**する（`F-2D-02` FR-2 / ADR-0016 と同じ規律）。**形式名だけで「対応」と表現しない**。
- **FR-3** 未対応形式は **理由と代替手順を示して明示的に断る**。**対応しているかのように見せない**（系譜: 上流 §3.1 が FBX / Blender file を初期対象外とした前例。**重い形式を「一応読める」で抱え込まない**）。

### 3.2 安全（信頼しない入力としての扱い — 継承）

- **FR-4** 解析を始める前に、**安全に確認できる範囲だけの preflight**（サイズ・形式の妥当性・宣言された規模）を行い、**上限超過を理由つきで拒否**する（系譜: ADR-0020 の bounded preflight。**巨大ファイルで解析器を走らせてから落ちる、をしない**）。
- **FR-5** **付随ファイルの参照解決範囲を限定**する。**取り込み対象の外を指す参照・絶対パス・上位ディレクトリを辿る参照・外部ネットワーク参照を拒否**する（**取り込みをファイル読み取り経路にしない**。系譜: 上流 §12 と ADR-0020 のパス外参照拒否）。
- **FR-6** **未解決の参照を黙って無視しない**。欠けている付随ファイルは**列挙して示す**（`F-2D-08` の「未解決参照を黙って落とさない」と同じ思想）。
- **FR-7** 壊れたファイル・想定外の構造は **理由つきで拒否**する。**隔離は「読めない実体」に限り、構成の不一致は隔離せず理由つきで拒否**する（`F-2D-02` FR-8 / `F-2D-11` FR-15 と同じ）。
- **FR-8** **取り込みは全件成功でのみ確定**する。1 件でも失敗したら**何も保存しない**（`F-2D-02` FR-9 / ADR-0020）。
- **FR-9** 特定の GPU API を**必須にしない**（系譜: 上流 §14 の「3D 対応を理由に WebGPU 必須にしない」。**動く端末を狭めない**）。

### 3.3 非破壊（元を絶対に上書きしない — 継承）

- **FR-10** **元のモデルファイルを Source として verbatim 保持**する（`G5` / `F-CORE-03`。系譜: 上流 §12「元ファイルを保持する」・§14「元の 3D モデルを絶対に上書きしない」）。
- **FR-11** 付随ファイルも**必要な範囲を保持**し、**どれを保持しどれを保持しないかを示す**（保持しないものは **loss として提示**。`F-2D-11` FR-11 と同じ規律）。
- **FR-12** 整備・軽量化・書き出しはすべて **派生に対して**行う（`F-CORE-03`。**元へ書き戻す経路を作らない**）。

### 3.4 正直さ

- **FR-13** 取り込みで **保持しないもの・再現しないものを、確定前に開示**し、**確認を求める**（`F-2D-02` FR-17 / `F-2D-11` FR-10 と同じ）。
- **FR-14** **読み込み失敗の理由を表示**する（系譜: 上流 §12）。**「読み込めませんでした」だけにしない**。
- **FR-15** **専用形式の完全な読み書きを名乗らない**（`F-2D-16` FR-5 と同じ規律）。

### 3.5 実行

- **FR-16** **大きなファイルの読み込みで UI を固めない**（系譜: 上流 §12。`PF3` / `F-PLT-03`）。
- **FR-17** **進行を表示**し、**取消できる**。取消で**中途半端な状態を残さない**（FR-8 と対）。
- **FR-18** 付随ファイル群の読み取りは、**ネイティブ I/O の権限境界**に従う（`F-PLT-02` / `F-CORE-10`）。**宣言外の場所を読まない**。

### 3.6 エディション境界

- **FR-19** **3D の読み込み基盤は 3D エディション / モジュールにのみ載る**。**2D しか使わない利用者のコストを増やさない**（`P4`。系譜: 上流 §12 の「3D 関連は 2D の bundle size を不必要に増やさない・可能なら lazy load」——**本コンセプトではこれを工夫ではなく構造で満たす**）。
- **FR-20** 外部ライブラリの採用は **ライセンス検証ゲートを通る**（`G1` / `F-MOD-04`。系譜: 上流 §8「ライセンス確認が終わっていない候補を dependencies に追加してはいけない」）。**コードだけでなく、モデル重み・学習データ制限・商用条件・再配布条件まで確認する**。

## 4. 非機能要件（NFR）

- **NFR-1（安全）**: 不正・巨大・パス外参照で壊れない（FR-4/FR-5/FR-7）。
- **NFR-2（非破壊）**: 元ファイルがバイト不変（FR-10。`G5`）。
- **NFR-3（原子性）**: 失敗・取消で何も残らない（FR-8/FR-17）。
- **NFR-4（正直さ）**: 保持しないもの・失敗理由を示す（FR-13/FR-14）。
- **NFR-5（応答性）**: 大きなモデルで UI を固めない（FR-16）。
- **NFR-6（ゼロコスト）**: 3D を使わない利用者に負荷を掛けない（FR-19。`P4`）。

## 5. データ・保存への影響

- **元モデルと付随ファイルは Source として verbatim 保持**（FR-10/FR-11。`F-CORE-03` / `F-CORE-05`）。
- 3D の情報は **2D の保存データの意味を変えない**（系譜: 上流 §2.1 / §14「2D の `asset.json` を 3D のために破壊しない」。本コンセプトでは **`D3` / `D4` の名前空間分離**として満たす）。
- 取り込み時の出所情報（どのファイルから来たか、hash 等）を**記録し得る**。**保持しないものは loss として示す**（FR-11）。

## 6. 依存機能

- **F-CORE-03**（非破壊）: Source 保持と派生分離（FR-10/FR-12）。
- **F-CORE-05**（保存形式）: 器と名前空間（`D4`）。
- **F-CORE-06**（検品）: 構造検証・理由付き拒否・loss 提示（FR-4/FR-7/FR-13）。
- **F-PLT-02**（ファイル I/O）: 付随ファイル群の読み取り境界（FR-18）。
- **F-PLT-03**（offload）: 重い解析（FR-16）。
- **F-PLT-05**（レンダラのロード）: 3D のみの読み込み（FR-19）。
- **F-CORE-10**（権限）: 宣言外の読み取りを防ぐ（FR-18）。
- **F-MOD-04**（ライセンス検証）: 外部ライブラリ採用の門（FR-20）。
- **F-3D-03**（ビューポート & 検品表示）: 読み込んだ結果の確認先。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 単一ファイル形式と付随ファイル形式の**両方を扱える**（FR-1）。
- **AC-2**: 未対応形式が**理由と代替手順つきで断られる**（FR-3）。
- **AC-3**: 解析前の **preflight で上限超過が理由つきで拒否**される（FR-4/NFR-1）。
- **AC-4**: **取り込み対象の外・上位ディレクトリ・外部ネットワークを指す参照が拒否**される（FR-5/NFR-1）。
- **AC-5**: **欠けている付随ファイルが列挙**され、黙って無視されない（FR-6）。
- **AC-6**: 構成の不一致が**隔離されず、理由つきで拒否**される（FR-7）。
- **AC-7**: 1 件でも失敗したら**何も保存されない**（FR-8/NFR-3）。
- **AC-8**: 取り込み後も**元ファイルがバイト不変**（FR-10/NFR-2）。
- **AC-9**: **保持しないものが確定前に開示**され、確認なしに進まない（FR-11/FR-13/NFR-4）。
- **AC-10**: **読み込み失敗の理由が表示**される（FR-14）。
- **AC-11**: 大きなモデルで **UI が固まらず、進行が見え、取消できる**（FR-16/FR-17/NFR-5）。
- **AC-12**: **宣言外の場所を読まない**（FR-18）。
- **AC-13**: **3D を導入していない利用者の起動時間・常駐メモリ・配布サイズが増えない**（FR-19/NFR-6、`F-2D-13` AC-9 と同じ規律）。
- **AC-14**: 特定 GPU API が**必須にならない**（FR-9）。
- **AC-15**: 外部ライブラリが**ライセンス検証を通らずに入らない**（FR-20）。

## 8. 非目標

- **3D 生成 AI の内蔵**（系譜: 上流 §2.2 / §9 / §14。**生成は外部処理**であり、初期依存にしない。`G2` の AI 境界）。
- 重い形式（FBX / 専用プロジェクト形式）の初期対応（FR-3。必要なら別判断）。
- 専用形式の**完全な読み書き・ランタイム互換**を名乗ること（FR-15）。
- 表示・検品の中身（**F-3D-03** / **F-3D-04**）。
- 軽量化（**F-3D-10** / **F-3D-11**）。
- 採用ライブラリの選定（`G1` の評価が先。本文書では候補名を採用として書かない）。
