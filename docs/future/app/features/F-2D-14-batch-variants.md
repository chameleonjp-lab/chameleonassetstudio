## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **D-DONE-5**: **同じ工程を、量に対して適用できる**（整理・詰め直しに続く「まとめる」段の最後）。
- **D-DONE-2**: 非破壊で編集・修正できる（**一括でも非破壊**であること）。

逆算の理由: 実制作では **1 体のキャラクターで終わらない**。色違い・左右向き・装備違い・解像度違いが並び、**同じ変更を何十件へ当てる**場面が必ず来る。ここが弱いと、道具としては「作れるが、作り続けられない」。

同時に、**本機能は最も壊しやすい機能**でもある。一括処理は**一度の誤操作で多数のアセットを壊せる**。したがって本仕様の重心は「便利さ」ではなく **「壊さないための条件」** に置く。

## 1. ユーザーストーリー

- 制作者として、**色違い・左右向きを、元から作り直せる**ようにしたい。
- 制作者として、元を直したとき、**派生も追従させたい**——ただし **勝手に上書きされたくない**。
- 制作者として、**手で直した部分を、再生成で消されたくない**。
- 制作者として、**同じ変更を複数のアセットへまとめて**当てたい。
- 制作者として、**実行前に、何がどう変わるかを見て**から決めたい。
- 制作者として、**途中で失敗したら、中途半端な状態を残さないで**ほしい。
- 制作者として、一括の結果を **1 回で取り消せる**と嬉しい。

## 2. 用語

- **バリアント（variant）**: 元（base）から派生した別バージョン（色違い・左右向き・装備違い・解像度違い）。
- **linked / manual**: 元から**再生成できる**関係を持つものが linked、**関係だけ記録し再生成しない**ものが manual。
- **レシピ（recipe）**: linked バリアントを再生成するための手順と対象の宣言。
- **バッチ**: 同じ操作を複数の対象へまとめて適用すること。
- **fingerprint**: 元と派生が「いつの状態で同期したか」を表す決定的な値。

## 3. 機能要件（FR）

### 3.1 関係の持ち方（継承）

- **FR-1** 派生関係の**正本を 1 か所に持つ**（アセット本体へ重複して持たせない。系譜: ADR-0003 の Project-level registry）。
- **FR-2** 関係情報は **optional / additive** であり、**無くても各アセットが単独で成立**する（`D3`。系譜: ADR-0003 の「field 不在は全 Asset standalone」）。
- **FR-3** **単なる複製・反転コピーを、自動で関係へ登録しない**（系譜: ADR-0003。**利用者が意図していない関係を作らない**）。
- **FR-4** 1 つのアセットが属する関係は**高々 1 つ・1 役割**とする（系譜: ADR-0003 の F1。**関係が入り組むほど、何が正しいか判らなくなる**）。
- **FR-5** 元（base）の削除は、**付け替えか関係解除まで拒否**する。関係解除は**メンバーを削除せず単独へ戻す**（系譜: ADR-0003）。

### 3.2 再生成（linked）— 勝手に更新しないこと（継承の核心）

- **FR-6** **元を保存しただけでは、派生を更新しない**（系譜: ADR-0003 の V1。**背景での自動追従を行わない**）。更新は**明示の確認 / 実行まで起きない**。
- **FR-7** レシピは **書き換える範囲（write-set）を明示**する。**範囲外は常に保持**する（識別子・名前・作成時刻・関係所属を含む。系譜: `2D_2_VARIANT_BATCH_PLAN.md`）。
- **FR-8** **write-set 内に手動変更が 1 件でもあれば、その write-set 全体を保護**する（系譜: 同上。**項目単位の自動マージを初回から行わない**——「たぶんこっちが正しい」を機械に決めさせない）。
- **FR-9** 再生成で **識別子を再採番しない**（系譜: 同上。`F-2D-08` の「完全 map」と同じ思想）。元に対象要素が増えた場合だけ**新しい識別子を一度生成して対応表へ追加**し、**削除は事前提示**する。
- **FR-10** **元素材（Source）の追加・削除・上書きが必要になる差分は、再生成の対象にしない**。**理由つきで対象外（ineligible）**とし、明示的な作り直しへ戻す（系譜: 同上。`G5`）。
- **FR-11** **fingerprint は、更新可否と警告の根拠にだけ使う**。**自動の競合解消に使わない**（系譜: 同上）。
- **FR-12** fingerprint は **識別子・表示名・更新時刻に依存しない**（構造と対象データの決定的な値から作る）。**持ち出し・取り込みで識別子が変わっても保持できる**（系譜: 同上）。

### 3.3 バリアントの範囲

- **FR-13** **再生成できる種類（linked）と、記録だけの種類（manual）を分ける**（系譜: ADR-0003 の T1。**再生成の安全性が確かめられたものだけを linked にする**）。
- **FR-14** **出力倍率違い（1x / 2x / 3x）をバリアントとして複製しない**（系譜: 同上。**それは出力層の話**であり、`F-2D-12` FR-3 / `F-2D-16` が担う）。
- **FR-15** 再生成が安全に成立しない条件（欠落した素材、未対応の付随情報など）は、**理由つきで対象外**にする（FR-10 と同じ規律）。

### 3.4 バッチ（一括適用）— 壊さないための条件

- **FR-16** 実行前に、**全対象を分類して提示**する（適用可 / 警告あり / 対象外 / 手動調整あり / 更新不要）。**理由・変更内容・見積りを、正本を変更する前に示す**（系譜: `2D_2_VARIANT_BATCH_PLAN.md` の B1）。
- **FR-17** 対象外・更新不要は**実行対象にできない**。**手動調整ありは既定で除外**し、警告は**明示確認を必須**とする（系譜: 同上。**既定を安全側へ倒す**）。
- **FR-18** **確定は全件原子的**である。検証・生成・容量・保存のいずれかが失敗したら、**全件を無変更にする**（系譜: 同上）。**開始後の部分成功を許可しない**。
- **FR-19** **対象の初期選択を全体へ広げない**。**上限を設ける**（系譜: 同上の「1〜16 件・同じアセットは 1 対象まで・初期選択をプロジェクト全体へ広げない」。**「全部選択」を既定にしない**）。
- **FR-20** 準備中は **対象ごとの進行と取消**を示す。**確定（原子的な保存）の開始後は取消せない**ことを**明示**する（系譜: 同上。**取り消せると誤解させない**）。
- **FR-21** 一括は **1 回の履歴操作**として扱い、**取り消し・やり直しも同じ原子経路**を使う（系譜: 同上の H1。`F-CORE-04`）。
- **FR-22** データを変更する前に**復旧点**を作り、**復旧点を作れなければ確定しない**（系譜: 同上。`F-CORE-02`）。
- **FR-23** **元素材（Source）・対象外・除外した対象・関係を持たないアセット・書き出し済み成果物を変更しない**（系譜: 同上。`G5`）。

### 3.5 出力との境界

- **FR-24** **制作上の関係情報を、出力成果物へ持ち出さない**（系譜: ADR-0003 の「Family metadata は再編集用の保存にだけ含め、ゲーム向け出力へ追加しない」。**外へ出るのは素材であって、制作の都合ではない**）。

## 4. 非機能要件（NFR）

- **NFR-1（不意打ちのなさ）**: 明示しない限り何も更新されない（FR-6）。
- **NFR-2（手作業の尊重）**: 手で直した箇所を機械が消さない（FR-8）。
- **NFR-3（原子性）**: 失敗しても中途半端が残らない（FR-18/FR-22）。
- **NFR-4（限定性）**: 対象が明示され、既定が安全側（FR-17/FR-19）。
- **NFR-5（非破壊）**: 一括でも Source を変更しない（FR-23。`G5`）。
- **NFR-6（正直さ）**: 変わるもの・変わらないもの・できないものを事前に示す（FR-16/FR-20）。
- **NFR-7（可逆性）**: 一括が 1 回で取り消せる（FR-21）。

## 5. データ・保存への影響

- 関係情報は **optional / additive** で保存し、**名前空間分離**に従う（FR-1/FR-2。`D4` / `F-CORE-05`）。
- **未導入・未対応の環境で開いて保存しても、関係情報が消えない**（`D3` の往復）。
- **出力成果物には関係情報を含めない**（FR-24）。
- 一括の確定は **1 履歴単位**として保存経路に乗る（FR-21。`F-CORE-04` / `F-CORE-01`）。

## 6. 依存機能

- **F-CORE-04**（履歴）: 1 一括 = 1 履歴（FR-21）。
- **F-CORE-02**（復旧点）: 変更前の復旧点（FR-22）。
- **F-CORE-01 / 05**（保存・形式）: 原子的な確定と additive 保存（FR-18/FR-1）。
- **F-CORE-06**（検品）: 実行前分類と理由提示（FR-16）。
- **F-CORE-07**（書き出し）: 関係情報を出さない境界（FR-24）。
- **F-2D-13**（パレット）: **一括対象の代表操作**（色置換）。
- **F-2D-11 / F-2D-12**（整理 / 詰め直し）: 量に適用する工程の隣接。
- **F-PLT-03**（offload）: 大量準備の実行（FR-20）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 関係情報が**無くても各アセットが単独で成立**する（FR-2/`D3`）。
- **AC-2**: 複製・反転コピーが**自動で関係登録されない**（FR-3）。
- **AC-3**: **元を保存しただけでは派生が更新されない**（FR-6/NFR-1）。
- **AC-4**: 再生成が **write-set 外を保持**する（識別子・名前・作成時刻・関係所属）（FR-7）。
- **AC-5**: **手動変更がある write-set は既定で保護され、勝手に上書きされない**（FR-8/NFR-2）。
- **AC-6**: 再生成で**識別子が再採番されない**（FR-9、`F-2D-08` AC と同じ規律）。
- **AC-7**: **Source の追加・削除・上書きを要する差分が、理由つきで対象外**になる（FR-10/NFR-5）。
- **AC-8**: fingerprint が**自動の競合解消に使われない**（FR-11）。
- **AC-9**: fingerprint が**持ち出し・取り込みで識別子が変わっても保持**される（FR-12）。
- **AC-10**: **出力倍率違いがバリアントとして複製されない**（FR-14）。
- **AC-11**: 実行前に**全対象が分類され、理由と変更内容が示される**（FR-16/NFR-6）。
- **AC-12**: **手動調整ありが既定除外**され、**警告は明示確認を要する**（FR-17/NFR-4）。
- **AC-13**: 失敗時に**全件が無変更**になり、部分成功が残らない（FR-18/NFR-3）。
- **AC-14**: **初期選択が全体へ広がらず、上限が働く**（FR-19）。
- **AC-15**: **確定開始後は取消せないことが明示**される（FR-20）。
- **AC-16**: 一括が **1 回で取り消せる**（FR-21/NFR-7）。
- **AC-17**: **復旧点を作れなければ確定しない**（FR-22）。
- **AC-18**: **除外した対象・関係を持たないアセット・書き出し済み成果物が変更されない**（FR-23）。
- **AC-19**: **出力成果物に関係情報が含まれない**（FR-24）。

## 8. 非目標

- **項目単位の自動マージ**（FR-8。手動調整との衝突解決を機械に任せない）。
- **背景での自動同期**（FR-6）。
- 装備違い・手修正版解像度の**自動再生成**（manual として記録するに留める。FR-13）。
- 任意の操作をすべて一括対象にすること（**対象は安全性を確かめた操作から広げる**。系譜: 上流 O1 が「全操作の汎用 batch 化」を退けたのと同じ理由）。
- 上限値・UI・対象登録の具体（実装時に判断）。
- 出力倍率の扱い（**F-2D-12** / **F-2D-16**）。
