## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **T-DONE-7**: **metadata** と inspection report を付けられる。
- **T-DONE-9**: 保存・再開でき、元の 3D モデルを絶対に上書きしない。

逆算の理由: `F-3D-05`（基準）・`F-3D-06`（アンカー）・`F-3D-07`（判定）は、それぞれ**何を決めるか**を担った。本機能は **それらを一つのまとまりとして持ち、外へ渡せる形にする**——つまり **器**である。

`F-CORE-05` が保存形式の正本であるのに対し、本機能は **3D 固有の中身**（基準・アンカー・判定・実測値・出所・利用条件）が、その器のどこに、どんな規律で載るかを定める。

## 1. ユーザーストーリー

- 制作者として、**付けた情報がひとまとまりで保存される**と安心できる。
- 制作者として、**このモデルの利用条件**を記録しておきたい。
- 制作者として、**どこから来たモデルか**を後から辿りたい。
- 制作者として、**モデル本体と付随データが食い違わない**でほしい。
- 制作者として、**この機能を持たない環境で開いても、情報が消えない**でほしい。

## 2. 用語

- **付随データ（metadata）**: モデル本体に対して、アプリが付ける情報。
- **実測値（stats）**: 検品で得た数値（面数・材質数など）。
- **利用条件**: そのモデルを使ってよい範囲。
- **出所（provenance）**: どこから来たか。

## 3. 機能要件（FR）

### 3.1 何を持つか

- **FR-1** **基準**（`F-3D-05` の単位・上向き・前方向・原点モード・スケール）を持つ。**不明を正当な値として持てる**（`F-3D-05` FR-1）。
- **FR-2** **アンカー**（`F-3D-06`）と**当たり判定**（`F-3D-07`）を持つ。
- **FR-3** **範囲（bounds）と実測値**を持つ（`F-3D-03` / `F-3D-04` の検査結果に由来）。
- **FR-4** **利用条件**を持つ。
- **FR-5** **出所**を持てる（元ファイル名・取り込み時の特定値など。`F-3D-01` FR-11）。

### 3.2 利用条件の扱い（継承 — 二重管理を避ける）

- **FR-6** **利用者が申告した利用条件を正とする**（系譜: 上流 `3D-RISK-05`「利用条件の二重管理」）。
- **FR-7** モデルに**埋め込まれた利用条件は参考として転記**し、**申告と矛盾しても自動で上書きしない**。**矛盾は警告として示す**（系譜: 同上。**機械が権利を判定しない**）。
- **FR-8** **未確認を「未確認」として持てる**（`F-3D-05` FR-1 と同じ思想。**空欄を「制限なし」と読ませない**）。書き出しでは**「利用条件未確認」と明示**する（`F-3D-15`）。

### 3.3 本体との対応（継承）

- **FR-9** 付随データは **どのバイト列に対するものか**を紐づけて持つ（`F-3D-14` FR-4 と同じ規律。**別のモデルの情報が付いたままにならない**）。
- **FR-10** モデル内部の要素を指す情報は、**`F-3D-06` FR-12b の宣言点**に従う。**照合できなければ「未解決」**とする（系譜: `3D-RISK-02`）。
- **FR-11** **元モデルを変更しない**（`G5`。付随データは常に外付け）。

### 3.4 器としての規律（継承）

- **FR-12** 付随データは **additive** であり、**未対応の環境で開いて保存しても失われない**（`D3` / `D4` / `F-CORE-05`）。
- **FR-13** **項目を足し続けるだけにしない**。追加のたびに**版の扱いを判断する**（系譜: 上流 `3D-RISK-10`「additive の積み上げによる契約の劣化」。**optional を積み増すだけでは、版管理が一度も試されないまま破綻する**）。
- **FR-14** **2D の保存データの意味を変えない**（系譜: 上流 §2.1 / §14。名前空間分離で満たす）。
- **FR-15** **一時状態を混ぜない**（選択・表示切替・視点は保存しない。`F-3D-04` FR-7）。

## 4. 非機能要件（NFR）

- **NFR-1（対応の確かさ）**: どのモデルに対する情報かが曖昧にならない（FR-9）。
- **NFR-2（権利の慎重さ）**: 機械が利用条件を上書きしない（FR-7）。
- **NFR-3（未確認の明示）**: 空欄を「制限なし」と読ませない（FR-8）。
- **NFR-4（非破壊）**: 元モデルが不変（FR-11。`G5`）。
- **NFR-5（往復）**: 未対応環境でも失われない（FR-12。`D3`）。
- **NFR-6（版の健全さ）**: optional の積み増しだけで済ませない（FR-13）。

## 5. データ・保存への影響

- 本機能は **保存内容そのもの**を扱う。器の正本は `F-CORE-05`、名前空間の境界は `D4`。
- **元モデルは Source として不変**（FR-11）。付随データは別（`F-CORE-03`）。
- **利用条件は申告が正**（FR-6）。埋め込み由来は参考として区別できる形で持つ。
- **書き出しに何を含めるかは `F-3D-15` の判断**（制作上の関係情報は出さない。`F-2D-14` FR-24 と同じ思想）。

## 6. 依存機能

- **F-CORE-05**（保存形式・移行）: 器と版の正本（FR-12/FR-13）。
- **F-3D-05 / 06 / 07**: 中身の供給元（FR-1/FR-2）。
- **F-3D-03 / 04**: 実測値と検査結果（FR-3）。
- **F-3D-01**（安全読み込み）: 出所と元バイト列の特定値（FR-5/FR-9）。
- **F-3D-14**（report）: 検査記録との紐づけ（FR-9）。
- **F-3D-15**（書き出し）: 外へ出す形（FR-8）。
- **F-3D-09**（VRM 検出）: 埋め込み利用条件の転記元（FR-7）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 基準・アンカー・判定・範囲・実測値・利用条件・出所が**一つのまとまりとして保存**される（FR-1〜FR-5）。
- **AC-2**: 基準の**不明が正当な値として保存**される（FR-1）。
- **AC-3**: **利用者の申告が正**であり、埋め込み情報で**自動上書きされない**（FR-6/FR-7/NFR-2）。
- **AC-4**: 申告と埋め込みの**矛盾が警告として示される**（FR-7）。
- **AC-5**: **未確認が未確認として保持**され、書き出しで明示される（FR-8/NFR-3）。
- **AC-6**: 付随データが**どのバイト列に対するものか紐づく**（FR-9/NFR-1）。
- **AC-7**: 内部要素を指す情報が**照合できなければ「未解決」**になる（FR-10）。
- **AC-8**: 元モデルが**バイト不変**（FR-11/NFR-4）。
- **AC-9**: **未対応環境で開いて保存しても失われない**（FR-12/NFR-5）。
- **AC-10**: 項目追加のたびに**版の扱いが判断**される（FR-13/NFR-6）。
- **AC-11**: **2D の保存データの意味が変わらない**（FR-14）。
- **AC-12**: **一時状態が保存に混ざらない**（FR-15）。

## 8. 非目標

- 保存形式そのものの定義（**F-CORE-05**）。
- 項目名・schema の確定（実装時に判断。**規律だけ**を固定する）。
- 利用条件の**自動判定**（FR-7。**機械が権利を決めない**）。
- 検査記録の形式（**F-3D-14**）。
- 書き出しの構成（**F-3D-15**）。
- 中身を決める操作そのもの（**F-3D-05 / 06 / 07**）。
