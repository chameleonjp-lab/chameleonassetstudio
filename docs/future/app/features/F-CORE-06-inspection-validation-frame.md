## 0. 完成系での位置づけ（逆算リンク）

由来する完成系（`features/README.md` 2 章）:

- **D-DONE-6**: 「エンジンで使える状態か」を**検品できる**（命名・サイズ・原点・atlas 整合）。
- **T-DONE-3**: ファイルサイズ・ポリゴン数・マテリアル・テクスチャ・bounds・妥当性・VRM を**検品できる**。
- **T-DONE-7**: **metadata と inspection report** を付けられる。
- **S-DONE-4**: 失敗・制限が文章で分かり、**手動で必ず回復できる**。

逆算の理由: 差別化仮説 2（`APP_COMPETITIVE_LANDSCAPE.md` 4 章）は「**検品と互換性の確かさを商品価値にする**」と述べた。F-CORE-07（書き出し）はその「互換性」側を器として担ったが、**「検品」側の正本が未定義**で、F-CORE-07 FR-4 が求める inspection report の**供給元が存在しなかった**。

本機能は `A2`（Core 契約）の**最後の未確定要素**でもある（Arch 2 章が挙げる Core の構成要素のうち、Validation / Inspection フレームだけが残っていた）。

関係マップのノード: `A2 Core 契約`（本機能で完成）、`F-CORE-07`（report の供給先）、`G3 差別化仮説`、`G5 非破壊`。

## 1. ユーザーストーリー

- 制作者として、書き出す前に **「このままで大丈夫か」** を知りたい。
- 制作者として、問題があるなら **どこが・なぜ・どうすればよいか** を知りたい。
- 制作者として、**勝手に直されたくない**。何が起きたか分からないまま変更されるのが一番困る。
- 制作者として、**警告と停止を区別**してほしい（軽微な指摘で作業を止められたくない）。
- 制作者として、**API キーのような秘密が配布物に混ざらない**よう守ってほしい。

## 2. 用語（三段検証・系譜より）

- **構造検証**: データの形が定義どおりか（schema レベル）。
- **意味検証**: 参照が切れていないか、循環が無いか等、**形は正しいが意味が壊れている**状態の検出。
- **出力検証（preflight）**: 対象・preset に対して**出して問題ないか**の確認。
- **重大度**: 止める / 警告 / 情報。

## 3. 機能要件（FR）

### 3.1 三段の検証（継承）

- **FR-1** 検証を **三段**に分ける: **構造検証 / 意味検証 / 出力検証（preflight）**（系譜: ADR-0014 決定 1）。
- **FR-2** **段ごとに失敗時の既定動作を分ける**（系譜: ADR-0014 決定 4）:
  - **構造検証の失敗** → **保存・書き出しを止める**（正本を壊さない）。
  - **意味検証の失敗** → **修復を求め、何が不足しているかを示す**。**自動修復・自動削除で黙って直さない**。
  - **出力検証の失敗** → preset ごとに **警告 または 停止**。**保存正本は止めない**（編集は続けられる）。
- **FR-3** **検証は read-only**。検証それ自体がデータを書き換えない（系譜: ADR-0014 決定 6）。検証結果の保存や自動修復の既定適用は、**別途の判断**とする。

### 3.2 結果の提示と report

- **FR-4** 結果を **人が読める形**で示す: **何が・どこで・なぜ・どうすればよいか**（`S-DONE-4`）。
- **FR-5** 結果を **inspection report** としてまとめ、**書き出し成果物に同梱できる**形にする（F-CORE-07 FR-4 の供給元。`T-DONE-7`）。
- **FR-6** **重大度を区別**して示す（止める / 警告 / 情報）。軽微な指摘で作業を止めない。
- **FR-7** **未検証・未対応の範囲を明示**する（「チェックしていない」を「問題なし」と見せない。F-CORE-07 FR-10 / F-PLT-04 FR-6 と同じ規律）。

### 3.3 拡張との関係

- **FR-8** **モジュールが検証ルールを足せる**（Core の拡張点経由。`A9` / F-CORE-09 FR-1）。
- **FR-9** モジュール由来のルールも、**同じ三段・同じ重大度・同じ提示の作法**に従う。
- **FR-10** ルールを提供するモジュールが**未導入でも、プロジェクトは開けデータは壊れない**（該当チェックが行われないだけ。`D3`）。ただし **「未チェック」であることを示す**（FR-7）。

### 3.4 秘密情報と境界

- **FR-11** **秘密情報の検出を preflight 段に位置づける**（API キー・トークン・個人情報等が、拡張領域や provenance に紛れ込んだまま**配布物へ出る**のを防ぐ。系譜: ADR-0014 決定 5）。**保存自体は止めず、外へ出す前に警告する**。
- **FR-12** **不正入力（信頼しないファイル）の検査は本機能の関心ではない**。それは取り込み時の安全性（F-PLT-02 FR-7）の範囲であり、**境界を混ぜない**（系譜: ADR-0014 決定 7）。

### 3.5 エディション差

- **FR-13** **2D と 3D で検品の中身は異なる**（2D: 命名・サイズ・原点・atlas 整合／3D: ポリゴン数・マテリアル・bounds・スケール・VRM 等）。ただし**段・重大度・提示の作法は共通**にする（`S-DONE-3`）。

### 3.6 実行

- **FR-14** 重い検証は **UI を固めず、進捗を示し、キャンセルできる**（F-PLT-03）。

## 4. 非機能要件（NFR）

- **NFR-1（非破壊）**: 検証がデータを変更しない（FR-3。`G5`）。
- **NFR-2（決定性）**: 同じデータ・同じ版なら同じ結果になる。
- **NFR-3（明快さ）**: 指摘が利用者の言葉で伝わり、次の行動が分かる（FR-4）。
- **NFR-4（正直さ）**: 未チェック範囲を隠さない（FR-7）。
- **NFR-5（一貫性）**: モジュール由来のルールでも作法が変わらない（FR-9）。
- **NFR-6（応答性）**: 大きなプロジェクトの検証で UI を止めない（FR-14）。

## 5. データ・保存への影響

- **検証は read-only**。保存データを書き換えない（FR-3）。
- **検証結果（report）をプロジェクトに保存するかは未決**。保存する場合、**編集データとは分離**し、UI 一時状態とも混ぜない（F-CORE-01 6 章 / ADR-0014 決定 6 の「結果の保存は別判断」を継承）。
- report は **成果物側**に同梱されうる（F-CORE-07）。これはプロジェクトの編集データではない。

## 6. 依存機能

- **F-CORE-05**（保存形式）: 構造検証の対象定義。
- **F-CORE-03**（非破壊）: read-only 原則の土台。
- **F-CORE-07**（書き出し）: report の同梱先／preflight の対象 preset。
- **F-CORE-09**（Host）: モジュール検証ルールの登録経路（FR-8）。
- **F-PLT-03**（offload）: 重い検証の非同期化（FR-14）。
- **F-2D-15 / F-3D-14**（各検品）: 本フレームの利用者。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 構造検証の失敗で、**保存・書き出しが止まる**（正本を壊さない）（FR-2）。
- **AC-2**: 意味検証の失敗で、**不足が示され、勝手に自動修復されない**（FR-2）。
- **AC-3**: 出力検証の失敗が **警告 / 停止として区別**され、**保存正本は止まらない**（FR-2/FR-6）。
- **AC-4**: 検証の前後で**データがバイト／意味上不変**（FR-3/NFR-1）。
- **AC-5**: 指摘が **何が・どこで・なぜ・どうすれば**を伝える（FR-4）。
- **AC-6**: **未チェック範囲が明示**され、「問題なし」と混同されない（FR-7）。
- **AC-7**: **モジュール由来のルール**が同じ三段・重大度で扱われ、**未導入でもプロジェクトが開ける**（FR-8/FR-9/FR-10）。
- **AC-8**: 拡張領域や provenance に**秘密情報が含まれる場合、配布物へ出す前に警告**される（保存は止まらない）（FR-11）。
- **AC-9**: report が **F-CORE-07 の成果物へ同梱**できる（FR-5、F-CORE-07 AC-1 と対）。

## 8. 非目標

- **検証ルールの網羅**（2D / 3D の具体チェックは `F-2D-15` / `F-3D-14` と各モジュール）。
- 秘密情報**検出アルゴリズム**の確定（系譜でも preflight 実装時に確定とされている）。
- **自動修復の既定適用**（黙って直さない方針。導入するなら別途の判断）。
- 取り込み時の**不正入力対策**（F-PLT-02 FR-7 の範囲。FR-12 で境界を明示）。
- 検証結果の保存形式（5 章の未決）。
