## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **T-DONE-4**: **原点・足元・向き・スケールを整え**、3D アンカーと 3D 当たり判定を付けられる。
- **T-DONE-9**: 元の 3D モデルを絶対に上書きしない。

逆算の理由: 2D の `F-2D-09`（原点 / アンカー）に対応する **3D 版の最初の一歩**であり、**`F-3D-06`（アンカー）と `F-3D-07`（判定）の土台**でもある。基準が決まっていなければ、その上に置く位置情報はすべて意味を失う。

そして 3D では、この問題が 2D より深刻になる。2D の座標は**左上原点・x+右・y+下**で一意に決められる（ADR-0001）。しかし 3D モデルは、**作られた環境ごとに up 軸も前方向も単位も違う**——しかも**ファイルにその情報が無いことがある**。だから本機能の核心は「正しい値を決めること」ではなく、**「判らないものを判らないまま扱えること」** である。

## 1. ユーザーストーリー

- 制作者として、**モデルが原寸で正しい大きさか**を知りたい。
- 制作者として、**足元を基準にしたい**（キャラクターは地面に立つ）。
- 制作者として、**モデルの前方向**を決めたい。
- 制作者として、**判らない情報を勝手に決められたくない**。
- 制作者として、**整えても元のモデルが変わらない**と確信したい。
- 制作者として、**対象エンジンごとの軸の違いを、自分で毎回直したくない**。

## 2. 用語

- **up 軸 / 前方向**: モデルにとっての「上」と「正面」がどの座標軸か。
- **原点モード**: モデルの基準点をどこに置くか（中心 / 足元 / 任意）。
- **単位**: 1 の長さが何を意味するか（メートル / センチ / 単位なし）。
- **bounds**: モデルが占める直方体の範囲。

## 3. 機能要件（FR）

### 3.1 判らないものを判らないまま扱う（継承の核心）

- **FR-1** **単位・up 軸・前方向は「不明」を取り得る**（系譜: 上流 §4 が `unit` / `upAxis` / `forwardAxis` すべてに `'unknown'` を持たせた前例）。**推測で埋めない**。
- **FR-2** **不明であることを表示**し、**不明のまま先へ進める**（作業を止めない）。ただし**不明が結果に影響する場面では警告する**（書き出し・スケール比較など）。
- **FR-3** ファイルに記載がある場合は**その値を初期値として示す**が、**「ファイルがそう言っている」ことと「制作者がそう決めた」ことを区別**する。
- **FR-4** 制作者が値を確定できる。**確定は取り消せる**（`F-CORE-04`）。

### 3.2 基準の整備

- **FR-5** **原点モード**（中心 / 足元 / 任意）を設定できる（系譜: 上流 §4 の `originMode`）。
- **FR-6** **足元基準**を設定できる（キャラクターが地面に立つための最重要基準。系譜: 上流 §5.1 の警告「原点が足元ではありません」）。
- **FR-7** **前方向**を設定できる（系譜: 上流 §4 の `forwardAxis`）。
- **FR-8** **スケール**を設定でき、**bounds が現実的な大きさか**を確認できる（系譜: 上流 §4 の `scale` / `bounds`）。
- **FR-9** 設定は **`F-3D-03` の面の上で、モデルに重ねて確認**しながら行える（**数値だけで決めさせない**）。

### 3.3 検査との接続

- **FR-10** **原点が足元でない**、**bounds の中心が大きくずれている**を**理由つきで警告**する（系譜: 上流 §5.1）。**警告は作業を止めない**（`F-CORE-06` / `F-3D-03` FR-8）。
- **FR-11** **単位が不明なまま、実寸に依存する判断をさせない**（例: 「大きすぎる / 小さすぎる」の判定は、単位が確定して初めて意味を持つ）。**不明なら、その旨を示す**。

### 3.4 非破壊（元を書き換えない — 継承）

- **FR-12** **整備は「解釈」として保持**し、**元モデルのジオメトリ・ノード変換を書き換えない**（`G5` / `F-CORE-03`。系譜: 上流 §12 / §14「元ファイルを保持する」「元の 3D モデルを絶対に上書きしない」）。
- **FR-13** 整備をやり直せる。**元の値へ戻せる**（FR-4/`F-CORE-04`）。
- **FR-14** 整備の結果は **書き出し時に適用**する。**保存された元データの意味を変えない**（`F-2D-12` FR-1 / `F-2D-16` FR-12 と同じ境界）。

### 3.5 対象ごとの差は書き出し側が担う（継承）

- **FR-15** **対象エンジンごとの up 軸・前方向・単位の違いを、この整備で吸収しない**。**書き出し側が担う**（系譜: ADR-0001 の「出力先の Y 軸・pivot 差はキャンバスで吸収せず書き出し側が担う」を 3D へ展開。`F-2D-16` FR-11 と同じ）。
- **FR-16** ここで決めるのは **アプリ内での一つの基準**であり、**対象ごとに別々の基準を持たない**（**基準が分裂すると、どれが正しいか判らなくなる**）。

### 3.6 変換の適用点を一つにする（継承 — 上流リスク台帳）

- **FR-17** **保存する値は常にモデル自身の空間**とする。**画面に見えている空間の値で保存しない**（系譜: 上流 `3d/3D_DECISION_LOG_AND_OPEN_ITEMS.md` `3D-RISK-09`「保存空間と表示空間の取り違え」。**向きを補正して表示している最中に置いた点を、見えたままの値で保存すると、補正を変えた瞬間に全部ずれる**）。
- **FR-18** **画面の操作から保存値への変換は 1 か所に集約**する（系譜: 同上。**表示側の都合が保存値へ漏れる経路を複数作らない**）。
- **FR-19** **表示の変換を変えても保存値が変わらない**ことを、**往復で確かめられる**ようにする（系譜: 同上の round-trip 検証。`F-3D-03` FR-13 の read-only と対）。
- **FR-20** 整備の変換は **派生を作るときに一度だけ適用**し、**適用したことを記録**する（系譜: 同上 `3D-RISK-01`「表示変換と焼き込み変換の二重適用」。**表示で 1 回・書き出しで 1 回掛かって、2 回回る / 2 回拡大される**事故を防ぐ）。表示は常に **「保存値 + 表示のための変換」** として描く。
- **FR-21** **整備の設定を、動きのデータや派生の断片へ混ぜ込まない**（系譜: 同上。混ぜると適用点が増え、二重適用の温床になる）。

### 3.7 後続工程の前提（継承 — 上流リスク台帳）

- **FR-22** **基準（足元・前方向・単位）が未確定のまま、それに依存する後続工程を始めさせない**（系譜: 同上 `3D-RISK-12`「動線順序の前提崩れ」。**未確定のまま進めると、自動配置・接地・動きの流用がすべて狂う**）。**止めるだけでなく、何をすれば進めるかを示す**。

## 4. 非機能要件（NFR）

- **NFR-1（正直さ）**: 判らないものを判らないまま扱い、推測で埋めない（FR-1/FR-2/FR-3）。
- **NFR-2（非破壊）**: 元モデルが不変（FR-12。`G5`）。
- **NFR-3（可視性）**: 基準が絵に重なって見える（FR-9）。
- **NFR-4（単一基準）**: アプリ内の基準は一つ（FR-16）。
- **NFR-5（境界の明確さ）**: 対象ごとの差は書き出し側（FR-15）。
- **NFR-6（可逆性）**: 整備を取り消せる（FR-4/FR-13）。

## 5. データ・保存への影響

- **整備の結果は解釈データとして保存**する（元モデルとは別。`F-CORE-03` の Source / 派生分離）。
- **元モデルはバイト不変**（FR-12。`F-3D-01` FR-10）。
- 保存は **additive / 名前空間分離**に従う（`D4` / `F-CORE-05`）。**2D の保存データの意味を変えない**（系譜: 上流 §2.1 / §14）。
- **不明（`unknown`）は正当な保存値**である（FR-1。「未設定」を「既定値」で塗り潰さない）。

## 6. 依存機能

- **F-3D-01**（安全読み込み）: 対象モデルと元の値の供給元。
- **F-3D-03**（ビューポート & 検品）: 重ね表示と警告の面（FR-9/FR-10）。
- **F-CORE-03 / 04**: 非破壊・履歴（FR-12/FR-13）。
- **F-CORE-06**（検品）: 警告と妥当性検証（FR-10/FR-11）。
- **F-3D-06 / F-3D-07**（アンカー / 判定）: 本機能の基準の上に載る。
- **F-3D-15**（3D 書き出し）: 対象ごとの軸・単位変換の担い手（FR-15）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 単位・up 軸・前方向が **「不明」を取り得**、**推測で埋められない**（FR-1/NFR-1）。
- **AC-2**: 不明のまま**作業を続けられ**、**影響する場面で警告**される（FR-2）。
- **AC-3**: **ファイル由来の値と、制作者が決めた値が区別**される（FR-3）。
- **AC-4**: 原点モード・足元基準・前方向・スケールを**設定でき、取り消せる**（FR-4〜FR-8/NFR-6）。
- **AC-5**: 設定が**モデルに重ねて確認**できる（FR-9/NFR-3）。
- **AC-6**: **原点が足元でない / bounds 中心が大きくずれている**が**理由つきで警告**される（FR-10）。
- **AC-7**: **単位が不明なまま、実寸に依存する判定が断定されない**（FR-11）。
- **AC-8**: 整備後も**元モデルがバイト不変**（FR-12/NFR-2）。
- **AC-9**: 整備が**書き出し時に適用**され、**保存された元データの意味を変えない**（FR-14）。
- **AC-10**: **対象ごとの軸・単位の差が、この整備で吸収されない**（FR-15/NFR-5）。
- **AC-11**: アプリ内の基準が**一つに保たれる**（FR-16/NFR-4）。

## 8. 非目標

- **モデルのジオメトリ編集**（本コンセプトの 3D は**整える**のであって**作る**のではない。`F-3D-03` 非目標と同じ）。
- 対象エンジンごとの軸・単位変換（**F-3D-15**）。
- アンカーの付与（**F-3D-06**）と当たり判定の付与（**F-3D-07**）。
- 骨格に基づく基準推定（**F-3D-08**。骨格の検査は別機能）。
- 単位の自動判定（FR-1 のとおり**推測しない**）。
- 軸の既定値の確定（実装時に判断。**不明を許す枠組みだけ**を固定）。
