## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **S-DONE-4**: 失敗・制限が**文章で分かり**、**手動で必ず回復できる**。

逆算の理由: ここまでの全機能が、**繰り返し同じことを要求してきた**——「理由つきで拒否する」「loss を開示する」「復旧手段を案内する」「未検査を明記する」。`F-CORE-06` は指摘 1 件が持つべき中身（対象・影響・直し方・**無視してよい条件**）まで定めた。

しかし **中身が揃っていても、伝わらなければ意味がない**。本機能は、**それらを人が読んで動ける文章にする**ための横断要件である。

そして本コンセプトにとって、これは飾りではない。Vision の非採用の法則が言うとおり、**「使い勝手が悪ければ使われない」**——**失敗したときに何が起きたか分からない道具は、その一度で見限られる**。

## 1. ユーザーストーリー

- 制作者として、**何が起きたのか**を、専門用語なしで知りたい。
- 制作者として、**自分がどうすればよいか**を知りたい。
- 制作者として、**自分のせいなのか、道具の制限なのか**を区別したい。
- 制作者として、**取り返しがつくのか**を先に知りたい。
- 制作者として、**同じ失敗を繰り返さない**ようにしたい。
- 制作者として、**警告が多すぎて読まなくなる**状態を避けたい。

## 2. 用語

- **失敗**: 進めなかったこと。
- **制限**: できないと決まっていること。
- **復旧手段**: 利用者が自分で取れる次の一手。

## 3. 機能要件（FR）

### 3.1 何を必ず伝えるか

- **FR-1** **何が起きたか**を、**専門用語に頼らず**示す（内部の名称をそのまま出さない）。
- **FR-2** **どこで起きたか**を示す（対象。`F-CORE-06` FR-7a）。
- **FR-3** **なぜそうなったか**を示す（`F-CORE-06` FR-7b/7c）。
- **FR-4** **どうすればよいか**を示す（`F-CORE-06` FR-7d。**「失敗しました」で終わらせない**）。
- **FR-5** **取り返しがつくかどうか**を示す（**何も変わっていない / 途中まで進んだ / 元に戻せる**）。**原子性を約束した機能では、「何も変わっていない」と明言できる**（`F-2D-11` FR-14 / `F-3D-01` FR-8 / `F-3D-15` FR-24 など）。
- **FR-6** **利用者の入力の問題か、道具の制限か、環境の問題かを区別**する（**責めない書き方をしつつ、原因の所在は曖昧にしない**）。

### 3.2 制限の伝え方

- **FR-7** **できないことは、できないと明示**する（`F-2D-02` FR-2 / `F-3D-02` FR-3 / `F-2D-16` FR-6 が各所で求めた「理由と代替手順つきの拒否」を、**文章の要件として一本化**する）。
- **FR-8** **代替手順を示す**（**その場で行き止まりにしない**）。
- **FR-9** **将来対応するのか、しないのか**を、分かる範囲で示す（**期待させっぱなしにしない**）。
- **FR-10** **未検査・未対応を「問題なし」と読ませない**（`F-CORE-06` FR-7 / `F-PLT-04` FR-6 / `F-3D-14` FR-15 と同じ）。

### 3.3 量の制御（警告疲れを防ぐ）

- **FR-11** **重大度を区別**する（止める / 警告 / 情報。`F-CORE-06` FR-6）。**軽微な指摘で作業を止めない**。
- **FR-12** **件数と一覧への導線**を示し、**全部を一度に押しつけない**（系譜: 上流 §7 の警告表示）。
- **FR-13** **無視してよい条件を併記**する（`F-CORE-06` FR-7e。**厳しすぎて無視される基準は、基準として機能しない**——無視を「規律ある判断」に変える）。
- **FR-14** **同じ指摘を繰り返し出さない**（まとめる・抑制する手段を持つ。**読まれない警告は無いのと同じ**）。

### 3.4 失敗時の作法（継承）

- **FR-15** 失敗は **理由と復旧手段をひと組**にして示す（系譜: 上流 §7・§9。**「書き出せません」だけにしない**）。
- **FR-16** **元のデータが見つからない等の深刻な失敗では、具体的な復旧経路を案内**する（系譜: 上流 §9。`F-3D-15` FR-25）。
- **FR-17** 失敗の提示は、**支援技術にも確実に届く**（`F-UX-02` FR-3。**見えている人にだけ届く警告にしない**）。
- **FR-18** **色だけで深刻度を表さない**（`F-UX-02` FR-6）。

### 3.5 一貫性

- **FR-19** **同じ意味の失敗は、どの画面でも同じ言い方**をする（`F-UX-01` FR-5）。
- **FR-20** **モジュールが出すメッセージも、同じ要件に従う**（`F-UX-01` FR-9 / `F-CORE-06` FR-9）。
- **FR-21** **記録に残る文言と、画面に出る文言が食い違わない**（`F-3D-14` FR-12 の「画面と記録の一致」を、文章の面でも守る）。

### 3.6 書けないことは書かない

- **FR-22** **推測で原因を断定しない**（**分からないときは「分からない」と示し、確かめる手段を出す**）。
- **FR-23** **秘密情報をメッセージに含めない**（`F-CORE-06` FR-11 と同じ関心。**失敗の詳細に、出してはいけないものが混ざらない**）。

## 4. 非機能要件（NFR）

- **NFR-1（行動につながる）**: 読めば次の一手が分かる（FR-4/FR-8）。
- **NFR-2（安心）**: 取り返しがつくかが分かる（FR-5）。
- **NFR-3（公正さ）**: 責めず、原因の所在は曖昧にしない（FR-6）。
- **NFR-4（読まれる量）**: 警告疲れを起こさない（FR-11〜FR-14）。
- **NFR-5（到達性）**: 支援技術にも届く（FR-17/FR-18）。
- **NFR-6（一貫性）**: どの画面でも同じ言い方（FR-19/FR-20）。
- **NFR-7（正直さ）**: 推測で断定せず、未検査を隠さない（FR-10/FR-22）。
- **NFR-8（安全）**: 秘密情報を漏らさない（FR-23）。

## 5. データ・保存への影響

- **保存データに影響しない**。
- **記録（`F-3D-14` / `F-CORE-06`）へ残す文言と、画面の文言を一致させる**（FR-21）。
- メッセージの内容に**秘密情報を含めない**（FR-23）。

## 6. 依存機能

- **F-CORE-06**（検品）: 指摘の中身の正本（FR-2〜FR-4/FR-13）。
- **F-CORE-07**（書き出し）: 失敗と loss の提示（FR-15）。
- **F-UX-01**（デザインシステム）: 状態表示の形（FR-11/FR-12/FR-19）。
- **F-UX-02**（アクセシビリティ）: 届き方（FR-17/FR-18）。
- **F-CORE-02**（復旧）: 復旧経路の実体（FR-16）。
- **F-3D-14**（記録）: 記録との一致（FR-21）。
- **F-CORE-09**（Extension Host）: モジュール由来のメッセージ（FR-20）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: **何が・どこで・なぜ・どうすれば**が揃う（FR-1〜FR-4/NFR-1）。
- **AC-2**: **取り返しがつくかどうか**が示される（FR-5/NFR-2）。原子性を約束した機能では**「何も変わっていない」と明言**される。
- **AC-3**: **入力の問題か、道具の制限か、環境の問題か**が区別される（FR-6/NFR-3）。
- **AC-4**: できないことが**理由と代替手順つきで明示**される（FR-7/FR-8）。
- **AC-5**: **将来の見込みが、分かる範囲で示される**（FR-9）。
- **AC-6**: **未検査・未対応が「問題なし」と読まれない**（FR-10/NFR-7）。
- **AC-7**: **重大度が区別**され、軽微な指摘で作業が止まらない（FR-11/NFR-4）。
- **AC-8**: **件数と導線**が示され、全部を一度に押しつけない（FR-12）。
- **AC-9**: **無視してよい条件が併記**される（FR-13）。
- **AC-10**: **同じ指摘が繰り返し出ない**（FR-14/NFR-4）。
- **AC-11**: 失敗が**理由と復旧手段をひと組**で示す（FR-15）。
- **AC-12**: 深刻な失敗で**具体的な復旧経路**が案内される（FR-16）。
- **AC-13**: 失敗の提示が**支援技術にも届く**（FR-17/NFR-5）。
- **AC-14**: **色だけで深刻度が表されない**（FR-18）。
- **AC-15**: **同じ意味の失敗が、どの画面でも同じ言い方**（FR-19/NFR-6）。
- **AC-16**: **モジュール由来のメッセージも同じ要件**に従う（FR-20）。
- **AC-17**: **記録の文言と画面の文言が一致**する（FR-21）。
- **AC-18**: **推測で原因が断定されない**（FR-22/NFR-7）。
- **AC-19**: **秘密情報がメッセージに含まれない**（FR-23/NFR-8）。

## 8. 非目標

- 個々の文言・語調の確定（実装時に判断。**要件の枠だけ**を固定）。
- 多言語対応の方針（必要なら別判断）。
- 自動での原因究明（FR-22。**分からないものを断定しない**）。
- 失敗そのものを無くすこと（**失敗は起きる前提で、伝え方を定める**）。
- 検品の中身（**F-CORE-06**）と状態表示の形（**F-UX-01**）。

## 10. Open questions

- 専門用語をどこまで避けるか（正確さと分かりやすさの釣り合い）。
- 「将来対応するか」をどこまで書けるか（約束にならない書き方）。
- 同じ指摘のまとめ方（件数表示 / 折りたたみ / 抑制の記憶）。
- 記録用と画面用で長さを変える場合の一致の保ち方（FR-21）。
- モジュール由来メッセージの検査方法（要件を満たしているかをどう確かめるか）。
