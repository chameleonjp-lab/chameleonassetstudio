## 0. 完成系での位置づけ（逆算リンク）

由来する完成系:

- **D-DONE-7**: 対象エンジンで**そのまま使える形**で書き出せる。
- **D-DONE-6**: 出す前に確かめられる（`F-2D-15` の記録を根拠として受け取る）。

逆算の理由: **2D パイプラインの出口**であり、`D-DONE-1`〜`D-DONE-6` の成果が外部で実を結ぶかどうかが決まる場所。ここが弱ければ、どれだけ作りやすくても「結局エンジンで動かない」で終わる。

そして本機能の中心は、形式の数ではない。上流が 1 章で最初に置いた原則がそのまま核になる——**「『対応』という言葉を曖昧にしない」**。

## 1. ユーザーストーリー

- 制作者として、**使う対象を選ぶだけ**で、必要なファイル一式が出てほしい。
- 制作者として、**その出力が本当に対象で動くのか**を知りたい（「たぶん動く」では困る）。
- 制作者として、**取り込み手順**が付いてきてほしい。
- 制作者として、**何が保証されていないか**を先に知りたい。
- 制作者として、**同じ設定なら同じものが出る**と確信したい。
- 制作者として、**preset が増えても、今まで出していたものが変わらない**でほしい。

## 2. 用語

- **preset**: 対象と用途ごとの、出力構成・変換・命名の設定一式。
- **import notes**: 人が対象へ持ち込むための手順書。
- **互換性ラベル**: その出力がどこまで確かめられているかの表示（`generic` / `candidate` / `verified` など）。
- **verification record**: `verified` を名乗る根拠となる記録。

## 3. 機能要件（FR）

### 3.1 「対応」を曖昧にしない（継承の核心）

- **FR-1** 各出力に **互換性ラベルを付ける**（系譜: 互換性マトリクス 2 章）。少なくとも **確認していない汎用出力（`generic`）／確認前の候補（`candidate`）／確認済み（`verified`）**を区別する。
- **FR-2** **`verified` は記録がある場合にだけ使う**（系譜: 同 3 章。**記録がない限り使わない**）。記録には**対象名・対象バージョン・検証日・環境・素材種別・入力と期待出力・取り込み手順・期待結果（原点 / pivot / animation / 判定 / trim / 倍率 / 命名）・自動確認と人手確認の範囲・既知の制限・再検証が必要になる条件**を含む。
- **FR-3** **`verified` は対象バージョンに紐づく**。**永続的な保証として表示しない**（系譜: 同 3 章。対象の大きな更新で挙動は変わり得る）。
- **FR-4** **汎用出力は対象名で語らない**。対象ツール名でない出力（汎用 Web など）は、**プロファイル名と確認環境を記録**して初めて確認済みとなり、それが無ければ `generic` のままとする（系譜: 同 3 章）。
- **FR-5** **自形式を外部標準形式と名乗らない**（系譜: 同章冒頭の重要注記。**独自の atlas 形式は、外部ツールの標準形式そのものではない**）。
- **FR-6** 未対応は **理由と代替手順を示して明示的に断る**（`F-2D-02` FR-2 / ADR-0016 と同じ規律）。**対応しているかのように見せない**。

### 3.2 出力構成と説明

- **FR-7** 対象ごとに、**必要なファイル・座標変換・制限・対象バージョンを明示**する（系譜: `2D_COMPLETE_PRODUCT_SPEC.md` §5.6）。
- **FR-8** **import notes（取り込み手順）を同梱**できる。**まずファイル一式と検証済みの手動手順を優先**し、**専用の plugin / addon が必要になるのは、手動では重要な情報を再現できない場合に限る**（系譜: 同 §5.6。**連携の重さを先に背負わない**）。
- **FR-9** **検査・検証の記録を成果物へ含められる**（`F-2D-15` の記録。系譜: 互換性マトリクス 5 章の verification record）。
- **FR-10** **対象プロジェクトの内部ファイルを無検証で生成しない**（系譜: 同 6.1 の「直接生成しないもの」。**確認していないものを、動くかのように出さない**）。

### 3.3 座標と変換の境界（継承）

- **FR-11** **出力先ごとの Y 軸の向き・pivot の基準の違いは、書き出し側が担う**（系譜: ADR-0001。**キャンバスや保存座標で吸収しない**。`F-2D-03` FR-6 と対）。
- **FR-12** **出力倍率・trim・atlas 化は出力層の操作**であり、**保存データを変更しない**（`F-2D-12` FR-1/FR-3 と同じ境界）。
- **FR-13** **等倍の保存データを正本**とし、倍率違いを別の正本にしない（系譜: EXPORT_QUALITY_DESIGN 7 章の「常に等倍の正本」）。

### 3.4 再現性と後方互換

- **FR-14** **同じ編集元・同じ設定から、意味の同じ出力を再生成できる**（系譜: `2D_COMPLETE_PRODUCT_SPEC.md` §5.6。**決定的**であること。`F-2D-12` FR-6 と同じ規律）。
- **FR-15** **preset の追加・変更が、既存の出力の意味を変えない**（系譜: EXPORT_QUALITY_DESIGN 7 章。**既定値での出力を現行と同一に保つ**、**新オプションは省略可能な追加とする**）。
- **FR-16** preset は **保存・共有・再利用できる**。**同じ意味の設定を二重に持たない**（`F-2D-12` FR-4 と同じ）。
- **FR-17** preset の形式を変える場合、**移行の規律（`F-CORE-05`）に従う**。**黙って解釈を変えない**。

### 3.5 出す前の条件

- **FR-18** 書き出しは **`F-CORE-07` の書き出しフレーム**に載る（独自経路を作らない）。**出力前 preflight を通る**（`F-CORE-06`）。
- **FR-19** **loss がある出力は、理由つきで拒否するか、確定前に開示して確認を求める**（`F-2D-07` FR / `F-CORE-07` と同じ規律。**黙って落とさない**）。
- **FR-20** **適合が確認できていない対象向けの出力を、確認済みとして表示しない**（`F-2D-15` FR-16/FR-17 と対）。
- **FR-21** 失敗時は **成果物を中途半端に残さない**（`F-CORE-07` の原子性）。

### 3.6 拡張

- **FR-22** **モジュールが対象別 preset を追加できる**（`A4`）。ただし **同じラベル規律・同じ記録要件に従う**（FR-1〜FR-3。**モジュール由来だからといって `verified` を名乗れない**）。

## 4. 非機能要件（NFR）

- **NFR-1（正直さ）**: 確かめていないものを確かめたと言わない（FR-1〜FR-6/FR-20）。
- **NFR-2（決定性）**: 同じ入力・同じ設定が同じ出力になる（FR-14）。
- **NFR-3（後方互換）**: preset が増えても既存出力の意味が変わらない（FR-15/FR-17）。
- **NFR-4（境界の明確さ）**: 出力層の操作が保存データを変えない（FR-12/FR-13）。
- **NFR-5（実用性）**: 手順まで含めて、人が実際に持ち込める（FR-7/FR-8）。
- **NFR-6（原子性）**: 失敗が中途半端な成果物を残さない（FR-21）。

## 5. データ・保存への影響

- **保存データを変更しない**（FR-12/FR-13）。出力は成果物であり、`F-CORE-05` の保存内容に影響しない。
- **preset は設定データ**として保存し、**編集データと分ける**（`F-CORE-01` 6 章 / `adr/0007` の層分離）。
- **verification record は成果物側**に置く（FR-9）。制作上の関係情報は出さない（`F-2D-14` FR-24）。
- preset 形式の変更は **移行の規律**に従う（FR-17。`F-CORE-05`）。

## 6. 依存機能

- **F-CORE-07**（書き出しフレーム）: 器（FR-18/FR-21）。
- **F-CORE-06**（検品フレーム）: 出力前 preflight（FR-18/FR-19）。
- **F-2D-15**（2D 検品）: `verified` の根拠となる適合記録（FR-2/FR-9/FR-20）。
- **F-2D-12**（atlas）: 出力層の境界と決定性（FR-12/FR-14）。
- **F-2D-03 / F-2D-09**（座標・原点）: Y 軸・pivot 差の吸収元（FR-11）。
- **F-CORE-05**（形式・移行）: preset 形式の移行（FR-17）。
- **F-MOD-01 / 02**（カタログ・導入）: 対象別 preset をモジュールとして足す（FR-22）。
- **F-2D-13**（パレット）: 出力時の減色と loss（`F-2D-13` FR-14/FR-15）。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: 各出力に**互換性ラベルが付く**（FR-1）。
- **AC-2**: **記録が無ければ `verified` にならない**（FR-2/NFR-1、`F-2D-15` AC-10 と対）。
- **AC-3**: **`verified` が対象バージョンに紐づいて表示**され、永続的な保証として示されない（FR-3）。
- **AC-4**: **対象ツール名でない出力が、対象名で「対応」と語られない**（FR-4）。
- **AC-5**: **自形式が外部標準形式として表示されない**（FR-5）。
- **AC-6**: 未対応が**理由と代替手順つきで断られる**（FR-6）。
- **AC-7**: 出力に**必要ファイル・座標変換・制限・対象バージョン**が伴う（FR-7/NFR-5）。
- **AC-8**: **取り込み手順が同梱**でき、**無検証の対象プロジェクト内部ファイルが生成されない**（FR-8/FR-10）。
- **AC-9**: **Y 軸・pivot の違いが書き出し側で吸収**され、**保存座標が変わらない**（FR-11、`F-2D-03` AC と対）。
- **AC-10**: **出力倍率・trim・atlas 化が保存データを変えない**（FR-12/NFR-4、`F-2D-12` AC-1 と同じ境界）。
- **AC-11**: **同じ編集元・同じ設定から、意味の同じ出力が再生成**できる（FR-14/NFR-2）。
- **AC-12**: **preset の追加・変更で、既存の出力の意味が変わらない**（FR-15/NFR-3）。
- **AC-13**: 同じ意味の設定が**二重に存在しない**（FR-16、`F-2D-12` AC-13 と同じ）。
- **AC-14**: **loss がある出力が、黙って出ない**（FR-19）。
- **AC-15**: **適合未確認の出力が、確認済みとして表示されない**（FR-20）。
- **AC-16**: 失敗時に**中途半端な成果物が残らない**（FR-21/NFR-6）。
- **AC-17**: **モジュール提供の preset も同じラベル規律・記録要件に従う**（FR-22）。

## 8. 非目標

- **対象ツール一覧・対応形式の確定**（実装時／モジュールで判断。**ラベル規律と記録要件だけを固定**する）。
- **対象プロジェクトの内部ファイルの無検証生成**（FR-10）。
- 対象アプリの**プロジェクト全体の自動生成**（系譜: 互換性マトリクス 6.1 の「直接生成しないもの」）。
- 専用形式（他社ランタイム形式）の**完全な読み書き・ランタイム互換**（系譜: 同上。名乗らない）。
- 書き出しフレームそのものの定義（**F-CORE-07**）。
- 検査項目・適合判定の定義（**F-2D-15**）。
- 直接連携（plugin / addon）の実装（FR-8 のとおり**手動手順を優先**。必要性が示されてから別判断）。
