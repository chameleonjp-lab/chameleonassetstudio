## 0. 完成系での位置づけ（逆算リンク）

由来する完成系（`features/README.md` 2 章）:

- **D-DONE-2**: **レイヤー・パーツ・フレームを整理し**、ラスタ／ベクタを非破壊で編集・修正できる。
- **D-DONE-4**: フレームアニメーションと**簡易リグ焼き込み**を扱える（＝リグが束ねる対象が要る）。

逆算の理由: 以降のほぼすべての 2D 編集が **「どの層・どのまとまりに対する操作か」** を必要とする——ラスタ編集（05）はどのレイヤーを塗るのか、図形（06）はどこに置くのか、リグ（08）は何を動かすのか、当たり判定（10）は何に付くのか。**F-2D-03 が「どこ」を担うなら、本機能は「何」を担う。**

さらに Part（意味のまとまり）は、**単なるグループではなく「腕」「脚」といった制作上の意味を持つ単位**であり、リグ・差し替え・バリアントの土台になる。

関係マップのノード: `A3 Edition Runtime`（2D の構造）、`F-2D-03`（操作面）、`G5 非破壊`、`D1`（保存契約）。

## 1. ユーザーストーリー

- 制作者として、**レイヤーを重ねて**描き分けたい。順番・表示・ロックを自由に扱いたい。
- 制作者として、**関連するレイヤーをまとまり（パーツ）として**扱いたい（腕・脚・武器など）。
- 制作者として、パーツの**中身を差し替えて**別バージョンを作りたい。
- 制作者として、差し替えたときに**他のパーツのものが勝手に移動・削除されない**でほしい。
- 制作者として、レイヤーを消したときに**それを使っていた場所が黙って壊れない**でほしい。

## 2. 用語

- **Layer**: 描画の層（ラスタ / ベクタ / 画像参照など）。
- **Part**: 複数 Layer を束ねる**意味の単位**（親子関係・pivot 等を持つ）。
- **所属**: どの Layer がどの Part に属するか。
- **差し替え（replace）**: ある Part の所属 Layer 集合を、別の Layer 集合へ置き換える操作。
- **bake（焼き込み）**: リグ等の結果をフレームへ確定すること（`F-2D-08`）。

## 3. 機能要件（FR）

### 3.1 レイヤー

- **FR-1** レイヤーの**追加・削除・複製・並べ替え**ができる。
- **FR-2** レイヤーごとに **可視性・ロック・不透明度**を扱える。
- **FR-3** レイヤーは**種別**（ラスタ / ベクタ / 画像参照 等）を持ち、種別に応じた編集機能（`F-2D-05` / `F-2D-06`）が働く。
- **FR-4** レイヤー操作は **Core の履歴経路に乗り**（F-CORE-04）、**非破壊**である（F-CORE-03）。

### 3.2 パーツ（意味のまとまり）

- **FR-5** **Part は複数 Layer を束ねる**。Part は**親子関係と pivot** 等の属性を持つ。
- **FR-6** **各 Layer は高々 1 つの Part に所属**する。**未所属の Layer を許可**する（系譜: ADR-0023）。
- **FR-7** **親子に循環を作らせない**（系譜: ADR-0014 の意味検証必須対象）。
- **FR-8** Part の**表示・操作単位**として扱える（まとめて選択・移動等）。

### 3.3 差し替えの境界（継承）

- **FR-9** Part の**所属 Layer 集合を差し替え**られる。差し替えは **Part の identity（id / 名前 / 種別 / 親 / pivot 等）を維持**する（系譜: ADR-0023）。
- **FR-10** 差し替えで **Layer / テクスチャ / フレーム / アニメーションを作成・削除・再採番しない**（系譜: ADR-0023）。
- **FR-11** **別の Part が所有する Layer を指定した場合は、理由を示して拒否**する。**そのPart から暗黙に移動・削除しない**（系譜: ADR-0023。「黙って奪わない」）。
- **FR-12** 差し替えは **1 回の確定＝1 履歴操作**として原子的に扱う（取消・Undo/Redo・保存/再読込を含む。系譜: ADR-0023、F-CORE-04 FR-4）。
- **FR-13** 差し替えの**書き込み範囲を限定**する（対象 Part の所属情報と更新時刻のみ）。**対象外の Part や他の領域を変更しない**（系譜: ADR-0023 の write-set 限定）。

### 3.4 焼き込み済みとの関係（継承）

- **FR-14** **すでに bake したフレームを、差し替えで変更しない**。**次回の bake から新しい構成を使う**（系譜: ADR-0023）。過去の成果を遡って書き換えない。

### 3.5 検証と安全

- **FR-15** 参照の**存在と一意性を検証**する（F-CORE-06 の意味検証・出力検証に乗せる）。
- **FR-16** レイヤー削除時、**それを参照している箇所（Part / フレーム / 当たり判定など）の扱いを明示**する。**黙って壊さない・黙って直さない**（F-CORE-06 FR-2 の「自動修復しない」と整合）。

### 3.6 操作面

- **FR-17** **canvas 上での選択・並べ替え**が、共通の選択・ハンドル基盤（F-2D-03 FR-10）に乗る。
- **FR-18** レイヤー数が多くても**一覧・操作が重くならない**（`PF1` / F-PLT-03）。

## 4. 非機能要件（NFR）

- **NFR-1（非破壊）**: 構造操作が Source を書き換えない（`G5` / F-CORE-03）。
- **NFR-2（原子性）**: 差し替え等の確定が中途半端な状態を残さない（FR-12）。
- **NFR-3（明快さ）**: 拒否・警告の理由が分かる（FR-11/FR-16）。
- **NFR-4（予測可能性）**: 操作の影響範囲が限定的で予測できる（FR-13/FR-14）。
- **NFR-5（応答性）**: 多数レイヤーでも操作が滑らか（FR-18）。

## 5. データ・保存への影響

- レイヤー・パーツの構造は **保存データの中核**であり、**F-CORE-05 の器**に従う。本機能は独自形式を作らない。
- **書き込み範囲の限定**（FR-13）は保存の予測可能性に直結する。ある操作が**どこまでを変えるか**を契約として持つ。
- **UI 一時状態（選択中のレイヤー等）は保存データに混ぜない**（F-CORE-01 6 章）。可視性・ロックは**保存する属性**として扱う（表示専用の一時状態と区別する）。
- レイヤー削除時の参照の扱い（FR-16）は、**意味検証（F-CORE-06）と同じ規律**に従う。

## 6. 依存機能

- **F-2D-03**（Canvas）: 選択・操作の面（FR-17）。
- **F-CORE-03**（非破壊）/ **F-CORE-04**（履歴）: 操作の土台（FR-4/FR-12）。
- **F-CORE-05**（保存形式）: 構造の永続化。
- **F-CORE-06**（検品）: 参照・循環の検証（FR-7/FR-15/FR-16）。
- **F-2D-05 / F-2D-06**: 種別ごとの編集（FR-3）。
- **F-2D-08**（リグ焼き込み）: Part を動かす側（FR-14 の bake 境界）。
- **F-2D-10**（当たり判定）: 付与先の単位。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: レイヤーの追加・削除・複製・並べ替え・可視性・ロック・不透明度が扱え、**すべて履歴に乗る**（FR-1/FR-2/FR-4）。
- **AC-2**: Part が複数 Layer を束ね、**親子関係**を持てる（FR-5）。
- **AC-3**: **1 つの Layer が複数 Part に同時所属しない**。未所属 Layer は許可される（FR-6）。
- **AC-4**: 親子に**循環を作れない**（FR-7）。
- **AC-5**: 差し替えで **Part の identity が維持**され、**Layer / テクスチャ / フレームが作成・削除・再採番されない**（FR-9/FR-10）。
- **AC-6**: **別 Part が所有する Layer の指定が、理由つきで拒否**され、**元の Part から奪われない**（FR-11）。
- **AC-7**: 差し替えが **1 回の Undo で戻り**、保存・再読込を跨いでも一貫（FR-12/NFR-2）。
- **AC-8**: 差し替えが**対象 Part 以外を変更しない**（FR-13/NFR-4）。
- **AC-9**: **既に bake したフレームが差し替えで変わらず**、次回 bake から新構成が反映される（FR-14）。
- **AC-10**: レイヤー削除時、**参照していた箇所の扱いが示され、黙って壊れない**（FR-16）。

## 8. 非目標

- ラスタ／ベクタの**編集操作そのもの**（`F-2D-05` / `F-2D-06`）。
- リグ・bake の仕組み（`F-2D-08`）。本機能は bake 済みを壊さない境界だけを定める。
- **時間依存の所属切替**（衣装・表情・状態切替・keyframe 別所属・state machine）。系譜でも別 ADR へ分離されており、本コンセプトでも**別途**とする。
- バリアント生成 UI（`F-2D-14`）。
- レイヤー効果・ブレンドモードの網羅（必要なら `F-2D-13` 等のモジュール）。
