## 0. 完成系での位置づけ（逆算リンク）

由来する完成系（`features/README.md` 2 章）:

- **D-DONE-2**: レイヤー・パーツ・フレームを整理し、**非破壊で編集・修正**できる。
- **D-DONE-3**: **原点・アンカー・当たり判定**を付けられる（＝画面上で位置を指す手段が要る）。
- **S-DONE-3**: 2D と 3D が、別最適化されながら**同じ操作感**で行き来できる。

逆算の理由: F-2D-01 で作ったものを **最初に映す面**であり、**以降の 2D 編集機能（04 レイヤー / 05 ラスタ / 06 図形 / 09 原点・アンカー / 10 当たり判定 / 11 tileset）が、すべてこの上に載る**。

そして本機能には**もう一つの責務**がある——**座標の正本を守ること**。原点・アンカー・当たり判定は「画面のどこを指したか」が意味を持つ機能であり、**画面座標とデータ座標の対応が信頼できなければ、それらの機能はすべて信用できなくなる**。

関係マップのノード: `A3 Edition Runtime`（2D 側の編集面）、`PF4 描画ライブラリ`（利用者）、`G5 非破壊`（表示の都合でデータを変えない）。

## 1. ユーザーストーリー

- 制作者として、**拡大・縮小・移動**して細部と全体を行き来したい。
- ドット絵の制作者として、**拡大しても滲まない**でほしい（ピクセルがぼやけたら仕事にならない）。
- 制作者として、**グリッドに合わせて**きれいに配置したい。
- 制作者として、**透明部分がどこか**を見て分かりたい。
- 制作者として、**大きな絵でも操作がもたつかない**でほしい。
- 制作者として、**表示のために勝手にデータが変わる**のは絶対に困る。

## 2. 用語

- **共通アセット座標**: 保存データが使う座標（系譜: ADR-0001。**左上原点・x+ 右・y+ 下・px・回転は度**）。
- **画面座標**: 実際に表示されているピクセル位置（ズーム・パンの影響を受ける）。
- **ビューポート**: 現在表示している範囲（ズーム倍率・表示位置）。
- **overlay**: キャンバス上に重ねる補助表示（グリッド、選択枠、アンカー表示など）。

## 3. 機能要件（FR）

### 3.1 表示

- **FR-1** プロジェクトの内容（レイヤー合成結果）を**表示**する。
- **FR-2** **ズーム・パン・全体表示（フィット）・等倍表示**ができる。
- **FR-3** **ピクセルを滲ませない表示**を選べる（ドット絵制作で拡大しても補間でぼやけない）。
- **FR-4** **グリッド・ガイド等の補助表示**を持ち、**表示/非表示を切り替えられる**。
- **FR-5** **透明部分が判別できる**表現（チェッカーボード等）と、確認用の背景色切替を持つ。

### 3.2 座標の規律（継承）

- **FR-6** **共通アセット座標を正本**とする（左上原点・x+ 右・y+ 下・px・回転は度）。原点・アンカー・当たり判定・フレーム内位置は、すべてこの座標で表す（系譜: ADR-0001）。
- **FR-7** **grid / snap は UI 操作の補助**であり、**保存座標の単位・意味を変えない**。**既存データを開いただけで座標を丸めない**（系譜: ADR-0001。`G5`）。
- **FR-8** **画面座標 ↔ アセット座標の変換を一箇所の規範に集約**する。各編集機能が**独自の変換を持たない**（ずれの温床を作らない）。
- **FR-9** **出力先（Unity / Godot 等）の Y 軸方向・pivot 表現の差を、キャンバスで吸収しない**。変換は**書き出し側**が担い、変換式を記録する（系譜: ADR-0001。F-CORE-07 / `F-2D-16`）。

### 3.3 編集の土台

- **FR-10** **選択・ハンドル操作の共通基盤**を提供する（各編集機能が独自に作らない。操作感の一貫性）。
- **FR-11** **ズーム・パン・選択などの表示状態は UI 一時状態**であり、**保存データに混ぜない**（F-CORE-01 6 章。復元するならセッション状態として別レイヤー）。
- **FR-12** **モジュールが overlay を描ける**（`A9` の拡張点）。ただし**overlay が Document を勝手に変更しない**（表示は表示に留まる）。

### 3.4 性能

- **FR-13** **大きなキャンバス・多数レイヤー**でも、ズーム・パン・描画操作が滑らかに動く。
- **FR-14** 重い再描画を**必要範囲に限る／UI から逃がす**（`PF3` / F-PLT-03）。
- **FR-15** 描画は **F-PLT-05 のロード規則に乗る**（2D レンダラのみを載せる。`P4`）。

## 4. 非機能要件（NFR）

- **NFR-1（応答性）**: 操作が 1 フレーム内の手応えで返る（`PF1` の応答性予算）。
- **NFR-2（座標の正確さ）**: 画面で指した位置とデータ上の位置が一致する（FR-6/FR-8）。ずれを許さない。
- **NFR-3（非破壊）**: **表示・補助機能がデータを変更しない**（FR-7/FR-12。`G5`）。
- **NFR-4（ゼロコスト整合）**: 2D レンダラ以外を載せない（FR-15。`P4` / `P5`）。
- **NFR-5（一貫性）**: 3D ビューポート（`F-3D-03`）と**操作の作法を揃える**（`S-DONE-3`）。

## 5. データ・保存への影響

- **ビューポート状態（ズーム・パン・選択）は保存データに含めない**（FR-11）。復元する場合はセッション状態として **Document と分離**（F-CORE-01 6 章）。
- **grid / snap 設定は UI 設定**であり、**保存座標の意味に影響しない**（FR-7）。
- 座標の正本は **共通アセット座標**であり、本機能は**その表示と入力変換だけ**を担う（座標系そのものを再定義しない）。

## 6. 依存機能

- **F-2D-01**（新規作成）: 表示対象の生成元。
- **F-PLT-05**（レンダラのロード）: 2D レンダラの載せ方（FR-15）。
- **F-PLT-03**（offload）: 重い再描画の逃がし先（FR-14）。
- **F-CORE-03**（非破壊）/ **F-CORE-04**（履歴）: 編集操作の土台（本機能は入力面を提供）。
- **F-CORE-09**（Host）: モジュール overlay の登録経路（FR-12）。
- **F-2D-04/05/06/09/10/11**: 本機能の上に載る編集機能。

## 7. 受け入れ条件（Acceptance）

- **AC-1**: ズーム・パン・フィット・等倍が使え、**大きなキャンバスでも滑らか**（FR-2/FR-13）。
- **AC-2**: **拡大してもピクセルが滲まない表示**を選べる（FR-3）。
- **AC-3**: **画面で指した点とデータ上の座標が一致**する（拡大率・パン位置に関わらず）（FR-6/FR-8/NFR-2）。
- **AC-4**: **snap を有効にしても、既存データを開いただけで座標が変わらない**（FR-7、`G5`）。
- **AC-5**: グリッド・透明表現の**表示切替**ができ、**データに影響しない**（FR-4/FR-5/NFR-3）。
- **AC-6**: **ズーム・パン・選択が保存データに混ざらない**（FR-11、F-CORE-01 AC-6 と対）。
- **AC-7**: **モジュールの overlay** が描け、**Document を変更しない**（FR-12）。
- **AC-8**: 2D プロジェクト表示時に **3D レンダラが載っていない**（FR-15、F-PLT-05 AC-2 と対）。
- **AC-9**: 3D ビューポートと**操作の作法が揃っている**（NFR-5）。

## 8. 非目標

- **描画方式・レンダラの採用決定**（`APP-O-03` / F-PLT-05）。
- 個々の編集ツール（ラスタ `F-2D-05` / 図形 `F-2D-06` / レイヤー `F-2D-04`）。
- 原点・アンカー・当たり判定の**付与機能そのもの**（`F-2D-09` / `F-2D-10`。本機能は指すための土台）。
- 出力先ごとの座標変換（**F-CORE-07 / F-2D-16**。FR-9 で境界を明示）。
- 3D ビューポート（`F-3D-03`）。
- 画面デザイン（`F-UX-01`）。
