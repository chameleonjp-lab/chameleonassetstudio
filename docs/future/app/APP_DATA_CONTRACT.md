## 1. なぜデータ契約が要るのか

本コンセプトの中心は **install-on-demand**——利用者ごとにモジュール構成が違う。これは**データにとって危険な前提**である。

- ある人が rig モジュールで付けた情報を、持っていない人が開いたらどうなるか。
- 外して配布し、別環境で開き直したら、何が残っているか。
- モジュールが増えるたびに、保存形式は壊れていかないか。

**構成の自由は、データの安全と引き換えにしてはならない。** `APP_MODULAR_ARCHITECTURE.md` 5 章が「**モジュール構成は自由でも、プロジェクトは壊れてはならない**」と置いたのは、この緊張への回答である。本書はそれを**機能単位の約束から積み上げて**確定する。

## 2. 三つの層（Source / 派生 / 一時状態）

正本: `features/F-CORE-03-non-destructive-edit-model.md`

すべてのデータは、次の三つのいずれかに属する。**どれに属するかが曖昧なデータを作らない。**

| 層 | 何か | 規律 |
|---|---|---|
| **Source（元データ）** | 取り込んだ原本 | **verbatim 保持**。**バイト不変**。**書き換える経路を作らない** |
| **派生（derivation）** | 編集・整備・軽量化の結果 | Source を参照して作る。**やり直せる**。**元を消費しない** |
| **一時状態** | 視点・選択・表示切替・作業中の候補 | **保存しない** |

### 2.1 この分離が支えているもの

| 分離が無ければ壊れるもの | 正本 |
|---|---|
| 取り込んだ画像が編集で汚れない | `F-2D-02` FR-6 / `F-2D-05` FR-7 |
| 元の 3D モデルを絶対に上書きしない | `F-3D-01` FR-10 / `T-DONE-9` |
| ラスタ化・焼き込みで図形定義を失わない | `F-2D-06` FR-6 / `F-2D-08` |
| 軽量化が置き換えではなく別モデルになる | `F-3D-10` FR-1 |
| 整備が「解釈」として保持され、ジオメトリを書き換えない | `F-3D-05` FR-12 |
| ディザが元の階調を消費しない | `F-2D-13` FR-12 |

**`G5`（非破壊・元データ保持）は、これらすべての共通の根**である。

### 2.2 一時状態を保存しない境界

`F-UX-01` FR-12 が横断の取り決めとして固定した。個別には `F-2D-03`（視点）・`F-2D-05`（選択・筆の設定）・`F-2D-13`（作業中のパレット）・`F-3D-04`（表示切替・展開状態）が同じことを定めている。

**判断基準**: **その値が失われて、制作物が変わるか**。変わらないなら一時状態である。

## 3. 保存形式（`D1`）

正本: `features/F-CORE-05-save-format-versioning-migration.md`

### 3.1 契約

- **形式には版がある**。版のないデータを作らない。
- **物理形式は本書で決めない**（`APP-O-01`）。**現行の器を継承するか、新形式を起こすかは人間判断**。
- 決めないままでも、**意味論（何をどこへ書くか・何を書かないか）は確定できる**——本書はその立場を取る。

### 3.2 何を保存し、何を保存しないか

| 保存する | 保存しない |
|---|---|
| Source（原本） | 一時状態（2.2） |
| 派生と、それを作るための設定（レシピ） | 描画結果そのもの（再生成できるもの） |
| 制作上の付与情報（原点・アンカー・判定・パレット・関係） | 制作上の関係情報の**出力への持ち出し**（`F-2D-14` FR-24） |
| 検査記録（最新 1 件は必須。履歴は任意。`F-3D-14` FR-7） | 秘密情報（`F-CORE-06` FR-11） |
| 利用条件・出所（`F-3D-13`） | 利用者の見た目設定（**編集データと分ける**。`adr/0007`） |

## 4. 移行（`D2`）

正本: `features/F-CORE-05`

### 4.1 契約

- 移行は **段階的・決定的・非破壊**である。
- **黙って解釈を変えない**。
- **移行前に退避する**（系譜: ADR-0006 の「ローカル作業コピー」と「可搬正本」の区別。`F-CORE-02` が復旧点として具体化）。

### 4.2 版を上げる規律（重要）

> **optional を積み増すだけで済ませない。**

系譜: 上流 `3D-RISK-10`「additive の積み上げによる契約の劣化」——**optional field が版を据え置いたまま増え続けると、版管理が一度も試されないまま破綻する**。

したがって `F-3D-13` FR-13 は「**項目を足すたびに版の扱いを判断する**」を要件に置いた。本書はこれを**データ層全体の規律**として引き上げる。

**判断のきっかけ**: 追加のたび。**「まだ additive だから大丈夫」を繰り返さない。**

## 5. 構成非依存の不変条件（`D3`）

正本: `features/F-CORE-05` / `F-MOD-02`

### 5.1 契約（`APP_MODULAR_ARCHITECTURE.md` 5 章の継承）

- **どのモジュール構成でも、同じプロジェクトを開ける**（`S-DONE-5`）。
- **未導入の機能が付けたデータは、保持され、破壊されず、非活性になるだけ**（`F-MOD-02` FR-5）。
- **未対応環境で開いて保存しても、失われない**（往復）。
- **撤去してもプロジェクトデータを失わない**。**再導入すれば、以前の情報が再び使える**（`F-2D-13` FR-17〜19）。

### 5.2 「知らないものを捨てない」の系譜

この不変条件は、**取り込みの側にも同じ形で現れている**:

- **未知の塊を捨てず、保持したうえで警告する**（`F-3D-02` FR-20。系譜: 上流の未知 chunk の扱い）。
- **拡張データをバイト列のまま保持すれば、素通しが成立する**（`F-3D-09` FR-2）。

**同じ規律が、保存の側と取り込みの側の両方から要求された**——これは `D3` が偶然ではなく、**データを扱う以上どこでも必要になる原則**であることを示している。

### 5.3 確かめ方

- 未導入環境で開いて保存し、**往復で失われないこと**を確認する。
- 導入 → 撤去で**指標が導入前へ戻ること**を確認する（`F-PLT-04` FR-11。残渣ゼロ）。

## 6. 名前空間拡張（`D4`）

正本: `features/F-CORE-05`

### 6.1 契約

- モジュールは **Core のデータ契約を拡張できる**。
- ただし **既存の意味を変えられない**。**名前空間つきの拡張領域にのみ書ける**。
- 拡張は **additive**（`D3` と対）。

### 6.2 書き込み範囲を限定する（継承）

系譜: ADR-0023（part / layer 差し替え）が定めた **write-set を対象へ限定する**規律が、データ層の一般則として効く。

- **`F-2D-04` FR**: 構造操作の書き込み範囲を対象へ限定する。
- **`F-2D-14` FR-7**: レシピは**書き換える範囲を明示**し、**範囲外は常に保持**する。
- **`F-2D-14` FR-8**: **範囲内に手動変更が 1 件でもあれば、その範囲全体を保護**する（**項目単位の自動マージを機械に決めさせない**）。

**「どこまで書き換えるか」を宣言し、宣言外を触らない**——これが `D4` の実務上の姿である。

### 6.3 派生の連なり（継承）

系譜: 上流 `3D-RISK-07`「derived 連鎖の親子関係の崩れ」。`F-3D-10` FR-14b〜14d が具体化した:

- 各派生は **直接の親が何か**を保持する（**元だけを指していると、連なった途中の再現も古さ判定も壊れる**）。
- **親が変わったかで「古い派生」を判定**できる。
- **子を持つ派生の削除をそのまま通さない**（孤児を残さない）。

### 6.4 内部要素を指す参照（継承）

系譜: 上流 `3D-RISK-02`。`F-3D-06` FR-12b〜12d が具体化した:

- 内部要素への結び付けは **宣言点を 1 か所に限る**。
- **どのバイト列を基準にした番号か**を保持し、**照合できなければ「未解決」と表示**する。**黙って別の要素へ結び付けない**。
- 派生側での張り直しは **専用の検証を要する操作**とする。

## 7. 参照と識別（横断）

系譜: ADR-0002（ID と名前と参照の規則）

- **識別子と表示名を混同しない**。**表示名を変えても参照が壊れない**（`F-3D-06` FR-7）。
- **外部から参照される名前は一意**である（`F-2D-09` / `F-2D-11` FR-3 / `F-3D-06` FR-5 / `F-3D-07` FR-7）。
- **再生成・複製で識別子を再採番しない**（`F-2D-14` FR-9 / `F-2D-08`）。追加は一度だけ生成し、削除は事前提示。
- **未解決参照・循環を黙って落とさず、理由つきで拒否**する（`F-2D-08` / `F-3D-01` FR-6）。

## 8. 出力との境界（横断）

**保存データと出力成果物は別物である。** これを混ぜると、出力の都合が保存内容へ侵食する。

| 境界 | 正本 |
|---|---|
| atlas 化・trim・出力倍率は**出力層の操作**で、保存座標を変えない | `F-2D-12` FR-1〜3（系譜: ADR-0004） |
| 出力先の Y 軸・pivot・軸・単位の差は**書き出し側が担う** | `F-2D-16` FR-11 / `F-3D-05` FR-15（系譜: ADR-0001） |
| **等倍の保存データが正本**。倍率違いを別の正本にしない | `F-2D-16` FR-13 |
| **制作上の関係情報を出力へ持ち出さない** | `F-2D-14` FR-24 |
| 整備の変換は**派生生成時に一度だけ適用**し、記録する | `F-3D-05` FR-20（系譜: `3D-RISK-01` の二重適用防止） |
