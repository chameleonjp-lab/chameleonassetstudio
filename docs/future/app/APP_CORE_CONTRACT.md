## 1. Core とは何か（範囲の定義）

`APP_MODULAR_ARCHITECTURE.md` 2 章の層構成において、Core は **Shell の上、Edition Runtime の下**に位置する。

**Core に属するもの**（`features/F-CORE-01`〜`10`）:

| 要素 | 正本 | 一言でいうと |
|---|---|---|
| Project / Document ライフサイクル | `F-CORE-01` | 作る・開く・保存する・再開する |
| 自動保存とクラッシュ復旧 | `F-CORE-02` | 落ちても失わせない |
| 非破壊編集モデル | `F-CORE-03` | 元を残し、派生を分ける |
| Undo / Redo と履歴 | `F-CORE-04` | 取り消せる |
| 保存形式・版・移行 | `F-CORE-05` | 器と、その育て方 |
| 検品 / Inspection フレーム | `F-CORE-06` | 出す前に確かめる枠 |
| 書き出しフレーム | `F-CORE-07` | 外へ渡す器 |
| Home / Project Dashboard | `F-CORE-08` | 入口 |
| Extension Host | `F-CORE-09` | モジュールを載せる仕組み |
| capability / 権限の強制 | `F-CORE-10` | 宣言外をさせない |

**Core に属さないもの**:

- **エディション固有の編集能力**（2D の描画・3D の表示は `Edition Runtime`）。
- **個別の制作機能**（`Feature Modules`）。
- **OS との接続**（`Shell` / `F-PLT-01`・`F-PLT-02`）。

### 1.1 Core の設計原則

> **Core に機能を足さない。**（`APP_MODULAR_ARCHITECTURE.md` 2 章）

Core は**すべての利用者が常に負担する層**である。ここに 1 つ機能を足すことは、**その機能を使わない全員に重さを課す**ことと同じであり、`P4`（未使用ゼロコスト）の直接の違反になる。

したがって Core が持つのは **「機能」ではなく「契約」** である——**上に載るものが従うべき規律**と、**それを守らせる仕組み**。

## 2. Core が約束すること（不変条件）

上に載るすべて（Edition Runtime / Feature Modules / 各機能）は、次を**前提にしてよい**。

### C-1: 元データは失われない

- 取り込んだ元データは **Source として verbatim 保持**される（`F-CORE-03`）。
- 編集は**派生に対して**行われ、**Source を書き換えない**（`G5`）。
- 保持しないものがある場合、**確定前に開示され、確認を求められる**。

**実例**: `F-2D-02`（画像取り込み）・`F-3D-01`（モデル取り込み）は、この約束の上に「原本がバイト不変であること」を受け入れ条件に置いている。`F-3D-10`（軽量化）が**元を置き換えず別モデルを作る**のも、同じ約束に由来する。

### C-2: 操作は取り消せる

- 編集操作は **共通の履歴経路**に乗る（`F-CORE-04`）。**画面ごとに別の取り消し方を作らない**（`F-UX-01` FR-11）。
- **1 つの確定操作は 1 つの履歴単位**として扱われる（`F-2D-05` の 1 ストローク、`F-2D-14` の 1 一括、`F-2D-04` の 1 確定）。
- モジュールが提供する操作も**同じ経路に登録される**（`F-CORE-09`）。

### C-3: 失敗は何も壊さない

- 検証・生成・保存のいずれかが失敗したら、**何も変更されない**。
- **開始後の部分成功を許可しない**（`F-2D-14` FR-18 / `F-3D-01` FR-8 / `F-3D-15` FR-24）。
- 中断で**中途半端な生成物を残さない**。

**この約束が、`F-UX-03` FR-5（取り返しがつくかを示す）を成立させる**——**「何も変わっていません」と言い切れるのは、Core がそれを保証しているから**である。

### C-4: 構成が違っても、データは壊れない

- **どのモジュール構成でも、同じプロジェクトを開ける**（`S-DONE-5` / `D3`）。
- **未導入の機能が付けたデータは保持され、非活性になるだけ**（`F-MOD-02` FR-5）。
- **未対応環境で開いて保存しても、失われない**（往復）。
- 拡張されたデータは **additive / 名前空間分離**に従う（`D4` / `F-CORE-05`）。

### C-5: 保存の器は、黙って意味を変えない

- 形式には**版があり**、移行は**段階的・決定的・非破壊**である（`F-CORE-05` / `D2`）。
- **optional を積み増すだけで済ませない**（`F-3D-13` FR-13。系譜: 上流 `3D-RISK-10`。**積み増しだけでは版管理が一度も試されないまま破綻する**）。
- **一時状態を保存しない**（視点・選択・開いている場所。`F-UX-01` FR-12 が横断で固定）。

### C-6: 検品には共通の枠がある

- 検証は **三段（構造 / 意味 / 出力 preflight）** に分かれ、**段ごとに失敗時の既定動作が違う**（`F-CORE-06` / ADR-0014）。
- **検証は read-only**——検証それ自体がデータを書き換えない。
- **指摘 1 件は決まった中身を持つ**（`F-CORE-06` FR-7a〜7f）: 対象 / 実測値と推奨値と前提 / 理由 / **その先で何が起きるか** / **直し方とこのアプリで直せるか** / **無視してよい条件** / 検査規則の版。
- **未検証・未対応を「問題なし」と見せない**。

### C-7: 書き出しには共通の器がある

- 成果物・説明・取り込み手順・検査記録を**同じ器**で扱う（`F-CORE-07`）。
- **loss がある出力は、理由つきで拒否するか、確定前に開示して確認を求める**。
- **記録の無いものを「確認済み」と表示しない**（`F-2D-16` / `F-3D-15` が各エディションで具体化）。

### C-8: 宣言外のことは起きない

- モジュールは**必要な能力を宣言**し、**宣言外のことをしない**（`F-CORE-10` / `A8`）。
- 権限は **Host が強制**する（`F-CORE-09` / `A9`）。**善意に頼らない**。
- 未検証のモジュールは**導入導線に乗らない**（`G1` / `F-MOD-04`）。

### C-9: 使わないものの重さを負わない

- Core と Shell は**痩せたまま保たれる**（`P4`）。
- **未導入のモジュールは、起動時間・常駐メモリ・配布サイズに乗らない**。
- **撤去でコストが戻る**（残渣ゼロ。`F-MOD-02`）。
- この約束は**主張ではなく実測で確かめられる**（`F-PLT-04` の 3 状態測定）。

## 3. Core が要求すること（上に載る側の義務）

Core の約束は、**上に載る側が規律に従うことで成立する**。

### R-1: 独自の保存経路を作らない

保存・書き出し・履歴は、**Core の経路に乗る**。`F-2D-16` FR-28 / `F-3D-15` FR-28 が「独自経路を作らない」と明記しているのはこのためである。

### R-2: 独自の検証系統を作らない

検品は `F-CORE-06` の三段に対応づける。`F-3D-03` FR-12 / `F-3D-04` / `F-2D-15` FR-6 が「別系統の検証を作らない」と定めている。

### R-3: 一時状態を保存データに混ぜない

視点・選択・表示切替・作業中の候補は保存しない（`F-2D-03` / `F-2D-05` / `F-3D-04` FR-7 / `F-2D-13` FR-23）。

### R-4: 同じ意味の設定を二重に持たない

`F-2D-12` FR-4 が最初に定め、`F-2D-16` FR-16・`F-3D-03` FR-11a・`F-3D-15` FR-20 が引き継いだ規律。**しきい値・制約値・出力設定は、確定値の所在を一つにする**。

### R-5: モジュールも同じ作法に従う

モジュールが提供する操作・ツール・検証・UI・preset・メッセージは、**すべて Core と同じ規律**に従う（`F-2D-13` FR-20 / `F-2D-15` / `F-3D-15` FR-29 / `F-UX-01` FR-9 / `F-UX-03` FR-20）。**足せるのは機能であって、例外ではない。**

### R-6: 推測で作らない・黙って直さない

- **自動生成しない**（`F-2D-10` の判定、`F-3D-06` のアンカー、`F-3D-07` の判定）。
- **修正案を自動確定しない**（`F-2D-15` FR-9 / `F-3D-10` FR-7）。
- **判らないものを判らないまま扱う**（`F-3D-05` FR-1 の `unknown`）。
- **推測で原因を断定しない**（`F-UX-03` FR-22）。

## 4. Extension Host（`A9`）

正本: `features/F-CORE-09-extension-host-lifecycle.md`

### 4.1 役割

モジュールを **登録・有効化・無効化・撤去**する仕組み。**Core の一部として提供される**（`A2`）が、**モジュールの実体は Core に含まれない**。

### 4.2 契約の要点

- モジュールは **マニフェストで自身を宣言**する（`A6` / `APP_MODULE_MANIFEST_SPEC.md` *(予定)*）。
- Host は **有効化 / 無効化のライフサイクル**を持つ（`F-MOD-02` FR）。
- モジュールの操作は **Core の履歴に登録される**（C-2）。
- 導入・撤去は **原子的**であり、**準備中の置き場・退避した旧版・未完了の印を分けて持つ**（`F-MOD-02` FR-7a。系譜: 上流の実例）。
- **識別子に経路の区切り・絶対位置・上位を辿る表記を許さない**（`F-MOD-02` FR-7b。**識別子が置き場所の指定になってはいけない**）。

## 5. capability / 権限（`A8`）

正本: `features/F-CORE-10-capability-permission-enforcement.md`

### 5.1 役割

**モジュールができることの範囲**を宣言させ、**それを超えさせない**。

### 5.2 契約の要点

- 能力は **マニフェストで宣言**される（`A6`）。
- **宣言していないことはできない**（`F-CORE-10`）。
- ファイルの読み書きは **`F-PLT-02` の権限境界**に従う（`F-3D-01` FR-18 / `F-3D-02`）。
- **ネットワーク接続は既定で行わない**（本コンセプトは**オフライン前提**。`F-3D-01` FR-9 系の外部参照拒否、`F-MOD-06` FR-13 の「作業内容を外部へ送らない」と同じ立場）。
- 権限は **`APP-RISK-07`（ネイティブ化を理由に安全境界を緩める）を塞ぐ機構**である。

## 6. 層をまたぐ判断の置き場

| 判断 | 置き場 | 理由 |
|---|---|---|
| 保存形式の物理形式 | `APP-O-01`（未決） | 現行継承か新形式かは人間判断 |
| モジュール実体の配布方式 | `APP-O-02`（未決） | 同梱／取得／ローカルの選択 |
| 描画ライブラリの採用 | `APP-O-03`（実測後） | `F-PLT-04` の計測が先 |
| 3D の付与（骨格・追従・動き） | `APP-O-04`（未決） | 非目標との線引きを引き直す必要がある |
| 外殻の採用 | `APP-R-01`（実測後・人間承認） | 選定基準は `F-PLT-01` で確定済み |
| 第三者拡張の開放 | `G4`（Stage 4 判断） | まず公式モジュールから |

**本書はこれらを決めない。** Core 契約は、**どの選択肢を採っても成立する形**で書かれている。

## 7. この契約が守られているかの確かめ方

| 約束 | 確かめ方 | 正本 |
|---|---|---|
| C-1 元データが失われない | 取り込み後の原本がバイト不変 | 各取り込み機能の AC |
| C-3 失敗が何も壊さない | 失敗・中断後にプロジェクトが無変更 | 各機能の原子性 AC |
| C-4 構成が違っても壊れない | 未導入環境で開いて保存し、往復で失われない | `F-MOD-02` / `F-CORE-05` |
| C-9 使わないものの重さを負わない | **未導入 / 導入済み・未ロード / 有効の 3 状態で測る** | `F-PLT-04` FR-10 |
| C-9 撤去でコストが戻る | 導入 → 撤去で指標が導入前へ戻る | `F-PLT-04` FR-11 |
| C-8 宣言外のことが起きない | 宣言外の読み取り・接続が発生しない | `F-CORE-10` |

**`P4` は主張ではなく実測で確かめる**——これが本コンセプトの中心命題（多機能と軽量の両立）を、言葉だけに終わらせないための仕掛けである。
