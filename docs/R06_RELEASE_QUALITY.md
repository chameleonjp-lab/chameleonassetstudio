# R06: 正式公開の品質確認準備

状態: 部分実装。正式公開の終了条件は未達。

編集画面のJS/CSSを必要時に読み込む。読み込み中の表示と、失敗時のホーム復帰・再読込を設けた。
ホーム画像取込の確認画面は共通CSSを直接読み込み、編集画面を開く前でも320px幅で操作できる。
アプリに開発版・commitの表示と問い合わせ先を設け、build-info.jsonで配信されたrevisionを照合できる。

source commitと配信URLを照合するまでは出荷済みと扱わない。

## 小画面と画素一致の追加修正

ズーム・グリッドの操作を描画領域から分離し、小画面では操作列だけを横スクロールできるようにした。
全体表示は画面回転に追従し、手動倍率では倍率と表示中心を保つ。非表示のタブから戻るときも追従する。
ツールの使い方と検査コード・保存データの差分は詳細を開いて読める。通常の説明と操作名は平易な日本語にした。
公開版の情報はホームとプロパティへ置き、編集画面の高さへ加算しない。

独立確認で320×568・375×667・667×375の通常編集と独立コマ編集、44px以上の下部ナビ、回転、200%倍率、保存・Undo・PNG・再開を確認した。
独立コマ時も描画領域は高さ110px以上で、初期位置から下部ナビへ到達できた。
R04の独立コマ・複数画像・64コマ取込とホーム取込を保持している。
タイムラインのカードを縦方向へ縮めず、縦スクロールは外側のパネルで扱う。320px幅のCIではコマの描画ボタンが親要素に隠れた。縦方向の修正だけでは解消せず、代替字体の使用でコマ一覧が約28pxへ縮む横方向の切れを再現した。小画面ではコマ一覧へ一段分の幅を割り当て、文字拡大と代替字体の両方でクリック対象へ到達できることを検査する。
実機iPhoneの結果とは扱わない。

WebKitで半透明の見本を再合成するとRGBの丸め差が出たため、合成不要の静止PNGは検証済み編集画像のbytesを保持する。
全参照画像の存在・種類・デコード検査を行った後、単一可視画像、位置0、倍率1、回転0、不透明度1、実画像・定義・キャンバス同サイズの場合だけ適用する。
APNG・変形・重なり・WebPなどは従来の合成を使う。保存や出力形式のversionは変更しない。
見本4種は出力画素の完全一致と保存後の再開をChromium・WebKitで検査する。
複数画像の読込途中で失敗した場合も、読込済みの画像を解放する。2枚目のBlob欠落・デコード失敗・参照種別の拒否を検査し、理由を維持して拒否する。

## WebKit前後表示の修正

DPR2・8倍表示では、色付け用キャンバスの再利用により前コマの赤が後コマの青に置き換わる不具合を修正した。
OffscreenCanvasから描画ごとのImageBitmapを確定し、描画後に解放する。非対応環境では独立したキャンバスを使う。
製品rendererを直接使う画素検査と既存の前後表示操作をWebKitで確認した。許容差は従来の2を維持する。

## 計測の入口

`e2e/release-quality.spec.ts`は製品ビルドを初回ロードし、320px幅でホームから512px画像を取り込み、PNGを保存する。
編集画面を先読みしていないこと、確認操作44px、横overflowなしを検査する。
計測区間は画像入力から確認画面表示まで、および書出しナビゲーション開始からPNGダウンロード開始まで。
クラウドでの1回の参考測定は[evidence/r06-cloud-baseline.json](evidence/r06-cloud-baseline.json)に記録する。
初期JSは約498kB、編集画面の遅延JSは約464kB。総転送量の削減とは扱わない。
描画・変形95%100ms、メモリ、Safari実機性能はこの値から判定しない。
最終版では入力から描画更新までを同じ端末・素材・区間で繰り返し測り、p95とサンプル数を残す。

`npm run e2e:quality`はChromium・WebKitを製品ビルドで順番に実行する。CIでも実行し、記録は`test-results-quality`へ保存する。
`release-performance.spec.ts`は自作512×512・1レイヤー素材をホームから取り込み、実際のブラシとドラッグ移動を30回ずつ操作する。
入力イベントのcaptureから、期待する画素が描画バッファへ現れるまでをブラウザ内の時計で測る。
ブラシの指押下から途中表示、指を離してから保存・画像更新後の確定表示、ドラッグ移動を別区間で記録する。
確定表示には画像処理・原子的な保存・デコードが含まれる。測定外の保存待機やPlaywrightドライバの待機を混ぜない。
各区間の全サンプル、p95、素材hash、browser版、viewport、source commitとローカル変更の有無をJSONへ添付する。
requestAnimationFrameで観測したCanvas更新は物理画面の表示時刻ではなく、クラウドの値を実機保証へ転用しない。
1レイヤーに加え、512×512・2レイヤー・8コマでも30回ずつ描画・移動を測る。再生は8fpsで実キャンバスの青い画素位置の変化を24回観測し、最初の表示時間と更新間隔を記録する。ホーム初回表示、取込、8回のコマ保存、PNG/.casproj出力の時間と実出力のhashも残す。これら画面操作の時間はドライバ待機を含む参考値として区別する。

各段階のJS heapはChromiumで取得できる範囲だけを記録し、WebKitで取得できなければnullとする。DOMに接続されたCanvasのRGBAサイズは寸法からの参考推定であり、OffscreenCanvas・画像decode・GPU・プロセス全体・peakを含まない。LinuxではPlaywright worker配下のブラウザ子プロセスをたどり、各段階のRSSも記録する。Node worker自身は除外する。共有ページの重複計上・終了した子プロセスの欠落があり、プロセスRSS合計は物理メモリの厳密な合計やpeakではない。実機メモリと最終候補版のiPhone計測は残る。

commit `1eabe0ec`の製品ビルドで行ったクラウド参考測定は、[全サンプルと条件](evidence/r06-input-performance-2026-10-02.json)へ保存した。
各区間30回のp95は、Chromiumで途中表示8.8ms・確定表示85.7ms・移動17.3ms、WebKitで18ms・372ms・25msだった。
WebKitの確定表示には保存・画像処理の待ち時間があり、描画中の反応と混ぜない。512px取込・PNG保存の1回測定はChromium75/112ms、WebKit256/693ms。
標準素材全体や実機の性能合格とは扱わない。

## 最終版で一度に行うiPhone確認の準備

R05新版出力を含む最終候補版と確認素材が揃ってから、人間へ1回の確認を依頼する。
出力比較用の3倍率バックアップ・参考ZIPと期待値は[R05確認素材](R05_FIELD_CHECK.md)へ用意した。
必須端末はiPhone 17 Pro、Safari。OS/browser、縦横、commit、URL、日時を記録する。

1. ホームから見本付き64×64素材を作る。自作の画像を2枚のレイヤーにし、8コマを作る。
2. 1コマを複製して1pxだけ描き直す。前後表示・再生・停止を行い、他コマと原本が変わらないことを確認する。
3. 100/200/300msを設定し、イベント・原点・取り付け位置・判定を加える。連番とシートを取り込む。GIF/APNG非対応なら警告と代替手段を確認する。
4. 関連反転を作り、元を変更して更新する。2素材の一括変更、Undo/Redo、名前変更直後の編集を確認する。
5. Safariを閉じて再開する。.casprojを「ファイル」へ保存し、別コピーとして再取込する。ごみ箱復元も行う。
6. 製品画面から出した通常Web・PixiJS・Phaser向けZIPを受取側で開く。余白除去、複数ページ、1/2/3倍の絵・時間・原点・判定を比較する。
7. 横向き、キーボード、文字拡大、VoiceOver、保存失敗後の再試行を確認する。描画点のずれ・横overflow・44px未満の主要操作を記録する。

各項目は成功・失敗・未確認で記録する。失敗した経路だけを再確認し、未確認を成功へ変更しない。
