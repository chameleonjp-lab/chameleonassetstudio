# R04: 独立コマの描画と画像取込

既存のFrame.layerStatesと編集TextureRefを使い、保存schema・バージョンは変更しない。
タイムラインで「このコマを描く」を選ぶと、他コマや通常表示と共有している画像だけを複製し、対象コマの表示へ結び直す。
ブラシ・消しゴム・塗りつぶし・範囲操作は編集用画像へ適用し、source画像は変更しない。
再生・巻戻し・停止・別コマの選択は描画モードを解除する。
独立した画像でもコマ固有の位置・拡大率を保持する。切抜き・padding・サイズ変更は対象コマの表示位置から補正する。

GIF/APNGを全コマデコードできるブラウザでは、個別durationMsを保持する。
ImageDecoder非対応時は先頭画像だけの確認と欠落説明を表示し、承認なしに保存しない。
追加デコーダやdependencyは導入していない。

連番・シート・アニメ画像の上限は64コマ。通常の独立素材一括取込は16件のまま。
コマ画像の合計RGBA推定は64MiB、取込画像・生成PNG等の保存量は128MiBを上限とする。
512×512の64コマはRGBA推定上限に収まる。これはiPhoneの実測メモリ保証ではない。
順次デコード・生成して進捗を表示し、取消時はpreview・素材・隔離画像を保存しない。
確認画面での確定まで正本を変更しない。

linked左右反転は複数編集画像・複数コマを扱う。一括変更の復旧点は変更前の全編集画像を1件へまとめ、画像ごとの部分状態を作らない。
関連コピーの作成後にTextureRefを追加・削除した場合、構造の再同期は引き続き安全に拒否し、コピーの再作成を案内する。
リグ・未知の構造・不足画像の拒否理由は維持する。linked色替えは従来どおり選択画像1枚が対象。

## 検証と残る境界

- 部品検査: 独立化・再複製・元画像保護・個別時間・容量境界・取消・全画像復旧。
- 画面検査: 2レイヤー8コマの1px描画とUndo/Redo・再読込・バックアップ再取込、1/16/64コマ512px連番、取消の無保存、変形した独立コマの描画と巻戻し。
- 複数画像の関連反転: 作成・画素更新・Undo/Redo・再読込・バックアップ再取込を検査する。
- Chromium全体と変更境界のWebKitを最終版で検査する。検査件数・tree SHAはPRへ記録する。
- iPhone Safari実機、性能実測、課題Fのゲーム側受取は未確認。個別時間等を保持する配布形式はD3判断を伴うR05へ残る。R04だけを正式公開の完了としない。
