# R05: 配布出力の実装とD3判断資料

状態: D3の旧形式維持・新版追加案に沿って実装中。R05終了条件は未達。

新版distribution/package 0.2.0の出力・受取処理、複数素材、設定保存は作業ブランチで実装した。
実装・検査境界は[D3統合記録](D3_CONSUMER_INTEGRATION_NOTES.md)を参照。
ブラウザ実行・最終CI・実機・出荷まで成功した意味ではない。

## 独立して実装した画面

既存のexportDistributionZipを製品画面へ接続した。
固定格子・透明余白除去、1/2/3倍、画像間余白、事前拒否・警告を選べる。
ダウンロードしたZIPのmanifest・画像ページ・補助ファイルの一致を6通りで検査する。
通常ZIPと配布ZIPは、個別時間・イベント・コマ別当たり判定の情報を失う場合の拒否を維持する。
配置の設定は画面内のみ。保存・複数素材・新版の受取処理を完成扱いしない。

## 採用を求める具体案

計画書§8 D3の推奨案に従い、旧ZIP・Atlas 0.1.0・distribution 0.1.0を保持する。
追加する形式はdistribution 0.2.0とpackageの新版。既存のasset.jsonを正本とする。

新版manifestへ各コマの表示位置、元キャンバスサイズ、切抜き矩形、ページ参照を明記する。
アニメーションには同じframeIdを繰り返した場合も区別できるoccurrencesを持たせる。
各occurrenceはframeId・page/frame参照・durationMs・開始時間を持ち、durationMsの既定値は1000/fps。
イベントは既存のframeId/frameIndexの規則を解決し、反復・ループの発火順を定義する。
コマ別判定は非表示指定を含めて解決した値を持ち、原点・アンカー・判定の座標は倍率変換後で揃える。
原本のID・payload・未知の拡張情報はasset.jsonで保持する。解釈不能な参照は出力前に拒否する。
例: 100/200/300msの3コマは開始時刻0/100/300ms、ループ時間600ms。固定fpsへ丸めない。

通常Web・PixiJS 8.12.0・Phaser 4.2.0向け補助処理は同じタイムライン計算を共有する。
上記エンジン版は現在のブラウザ検査用取得版。正式対応の採用は新版受取を実行確認してから記録する。
SpriteSheetのtrim・複数ページ・1/2/3倍で原点・判定がずれないことを、製品画面から出したZIPで確認する。
Unity/Godotの専用実行環境は確認済みと表示しない。

複数素材はIDで分離したディレクトリへ配置し、重複する表示名・ファイル名でも上書きしない。
外側manifestには素材一覧と各manifest参照・hashを持たせる。
全素材の事前検査後に出力し、取消・容量超過ではダウンロードを開始しない。
設定保存はR02のexport-presetsを後方互換な任意項目で拡張し、profile・padding・対象・倍率を保存する。
既存設定を読む際は既定値を補い、バックアップ再取込も同じ値を保持する。
