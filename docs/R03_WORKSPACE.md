# R03: 制作を始める画面と目的別の編集

対象基準: main `f8d9bc8`（R01 / R02マージ済み）。

ホームに新規作成・画像取込・最近のプロジェクトを優先して配置する。画像取込は既存の安全検査と確認ダイアログを使用し、確定時だけプロジェクト・素材・画像を単一トランザクションで保存する。取消と保存失敗では部分データを残さず、失敗理由をダイアログ内で示して再試行できる。

最近のプロジェクトには最初の素材のサムネイルを表示する。画像欠落や読込失敗はプロジェクトを開く操作を妨げず、作成したBlob URLはアンマウント時に解放する。サムネイルは保存済みの見本であり、全レイヤーの最新合成画像ではない。

正常時の保存容量は開閉できる詳細へ移す。容量注意・警告・重大警告はホーム上部にも表示する。復旧結果と保存領域の保護操作結果は詳細の外に表示し、閉じた状態でも結果を読める。

編集画面の既存項目を素材・レイヤー・画像修正・ゲーム情報・パーツに分類し、目的別メニューで表示を切り替える。「すべて表示」は従来の全項目を利用できる。書き出しとコマには既存専用画面から到達する。主要切替操作は44px以上。

キャラクター・アイテム・タイル・エフェクトの開始用の絵を明示チェックで生成できる。外部画像・フォントを使わず、オリジナルの図形だけをCanvasへ描く。既存テンプレートと空白作成の既定動作は維持する。生成した画像は通常の元画像・編集画像・サムネイルとして保存する。利用・改変・作品への配布に追加条件はない。

## 互換性と確認

asset.json / .casproj / export ZIP / JSON Schemaは変更しない。画像取込と保存に既存処理を使用する。

画面検査はホーム取込 → PNG出力 → ホーム → 再読込、320pxの横幅、正常時の容量折り畳み、目的別項目、取消、保存失敗の無変更と再試行、4種類の見本と空白の画素を対象とする。従来の素材作成検査では、DB書込成功と構造履歴記録の間に操作しないよう、UIの操作可能状態まで待機する。

独立レビューで指摘されたモーダル内エラー・作成結果の説明・操作領域を修正した。初心者実ユーザー、iPhone Safari実機、6課題の全工程と性能はR06の最終確認として残る。R03の自動検査だけで初心者・実機の合格とは扱わない。
