## 範囲と採用根拠

要件PR #294、計画PR #295、関係図PR #296、保存基盤PR #297のmerge後、main `f38e428d0aff8cbb5329b0eef9a1786b3bca131e` から実装。
B02と、画面接続に必要なB01の保存/救出部分を同じ変更へまとめる。

- `/` は軽量トップ。既存rootリンクの利用者へ2D保存済みprojectの所在を説明する
- `/2d/` は既存2D App。保存DB、`.casproj`、旧ZIP、Web/PixiJS/Phaser、Asset0.2.0は変更しない
- `/3d/` は独立した保存・救出shell。造形、viewport、rig、animation、GLBは準備中と明記する
- 3Dは実リンクを利用者が操作して新しいcontextへ開く。`noopener noreferrer`。別windowになるかはbrowser設定による
- popupの成否を`window.open`の戻り値から推測しない。リンク再操作/長押しと選択可能なURLを案内。旧画面への無断redirectなし
- double activationは短時間の重複を抑止する。別タブ化が合計memoryを減らす保証はない

新規依存・renderer・decoderは採用しない。G03は未通過。G00の許可範囲は独立native保存と入口であり、以前停止したGLB資源上限レビュー/不明操作は再実行していない。

## 実装境界

`index.html` + `src/entries/hub.tsx` はReact、editor、保存DB、workerをimportしない。
`2d/index.html` + `src/entries/2d.tsx` は現行Appへ接続。
`3d/index.html` + `src/entries/3d.tsx` はshellへ接続。shellのstatic依存として完全backup encoderを取得してから編集を受け付ける。
共有はReact/ReactDOM、Viteの小さな補助、entry error boundaryに限定し、editorのbarrel共有を作らない。

Vite multi-page buildは各入口のHTMLとscope別build-infoを出力する。
`tools/build/domainBoundary.ts` は実Rollup graphのstatic/dynamic imports、referenced files、CSS/assetsを追い、domain混入ならbuildを失敗させる。
`domain-bundles.json` は対象buildの依存一覧を残す。将来のworker追加も実通信検査で照合する。

Pages assembleはtop/2d/3d/guide/h3を保持する。base配下のdirect access/reloadをPages検査へ追加。
本工程自身は公開・mergeを行わない。既存main公開workflowはユーザーのmerge後に従来どおり動作する。

### 既存mainのWebKit失敗

main `f38e428` の[CI run 37117033391](https://github.com/chameleonjp-lab/chameleonassetstudio/actions/runs/37117033391/job/111185730420)で、rich-distributionのPhaser WebGL 2xがevent editor待ちでtimeout。他のWebKit97件は成功。
取得した失敗DOMではfixtureのframes/eventsがあり、animation optionが未選択だった。IDB transaction完了後reload済みであり、保存失敗と判断しない。
`EditorScreen`のselectedAssetId effectによるselection resetを、同じ小さなUI状態resetのまま描画前へ移す。IOや保存処理は追加せず、timeout/retry/期待値を緩めない。
[ReactのuseLayoutEffect契約](https://react.dev/reference/react/useLayoutEffect)の描画前処理に基づく。初回選択とasset切替に同期renderが一回加わるため、既存browser/性能検査を維持する。
